# Port metadata coherence to retained macFUSE

This plan is a living execution record for SFS-681. It follows `.agent/PLANS.md`.

## Purpose / Big Picture

The retained legacy macFUSE mount must consume the same semantic metadata
invalidations and mount-local coherence health already proven by the Windows
adapter. A macOS read-only open may retain Unified Buffer Cache pages only
after the local view has an explicit healthy boundary and complete invalidation
coverage. When metadata changes arrive, the macFUSE bridge must retain the
semantic scopes and translate them to its native inode, attribute, and entry
invalidation queue. Windows behavior and the experimental FSKit backend are
outside this change.

The result is observable through focused unit tests: unsafe startup/degraded
health refuses repeated `keep_cache`, precise semantic batches are accepted,
reset or incomplete coverage is reported conservatively, and queue failures
remain visible to the VFS health tracker.

## Surprises & Discoveries

- The shared `KernelInvalidator::invalidate_batch` fallback deliberately returns `Unsupported` after best-effort legacy calls. The macFUSE implementation therefore has no semantic coverage today even though its native queue already supports inode, attribute, and entry targets.
- `StudioVfs::coherence_allows_os_cache()` is already the shared health gate used by WinFSP but is not consulted by macFUSE's read-only open decision.
- macFUSE native invalidation is asynchronous and its current queue API does not expose admission success or delivery failure to semantic callers; the port must make queue admission explicit without claiming native delivery.

## Context and Orientation

`crates/studiofs-vfs/src/coherence.rs` owns the health state machine. VFS
metadata synchronization commits local state, retires its own attribute/dentry
and OS-generation caches, then calls `KernelInvalidator::invalidate_batch` with
volume-scoped `InvalidationIntent` values from `studiofs-meta`.

`crates/studiofs-macfuse/src/adapter.rs` decides per-open `direct_io` and
`keep_cache`, tracks kernel-observed inode liveness, and protects invalidation
from active asynchronous reads. `crates/studiofs-macfuse/src/low_level.rs`
owns the bounded native invalidation queue and its worker, which eventually
calls macFUSE's inode and entry notification functions.

The Windows reference is
`crates/studiofs-winfsp/src/context/invalidation.rs`: it retains semantic
targets, preserves historical names for rename/unlink, reports queue
acceptance separately from native delivery, and defers native purges for dirty
writers.

## Plan of Work

First add tests in the existing macFUSE test modules. One test will establish a
generation, force the VFS to remain outside the healthy state, and prove a
repeated read-only open still drops cached pages. Another will submit
attributes/content/entry/directory intents to `MacFuseKernelInvalidator` and
prove they are retained in the queue with `Queued` acceptance; reset and an
incomplete generation must not receive that result. Add a bounded queue test
for closed/full admission if the current queue shape requires it.

Then add a queue admission method that returns `Queued` only when every
requested native target was retained, while preserving the existing legacy
`inval_*` methods for compatibility. Implement macFUSE's semantic batch
translation at the adapter boundary: attributes and content become inode
targets, directory becomes attribute invalidation, entry keeps its parent/name,
and reset is unsupported. Reuse existing active-writer/read-drain protection.

Finally gate macFUSE read-only `keep_cache` on
`vfs.coherence_allows_os_cache()`. Unsafe health must also clear the retained
generation through the existing disabled-participation path so an earlier
healthy generation cannot be reused after degradation.

## Concrete Steps

Run from `/Volumes/Storage/dev/studiofs`.

1. Add the focused failing tests and run them individually with
   `cargo test -p studiofs-macfuse <exact-test> -- --nocapture`. The tests must
   fail because current macFUSE returns `Unsupported` for semantic batches and
   allows repeated cache reuse without a health gate.
2. Implement only the queue admission, semantic translation, and health gate.
3. Rerun the new tests and the existing macFUSE cache/invalidation tests.
4. Run `cargo fmt --all -- --check`, `cargo check -p studiofs-macfuse`,
   `cargo clippy -p studiofs-macfuse --all-targets -- -D warnings`, and
   `git diff --check`.

## Validation and Acceptance

Acceptance requires nonzero focused tests proving: startup/degraded health
does not retain macFUSE kernel pages; healthy repeated generations can retain
them; attributes/content/directory/entry semantic intents are queued; reset,
queue closure/capacity, or incomplete writer-protected coverage is not claimed
as complete; and Windows files are unchanged. Native macFUSE mounted behavior
must be reported separately because this host may not provide a reliable
macFUSE mount/unmount contour.

## Idempotence and Recovery

All queue changes are bounded and coalescing. Re-running tests uses their
existing target temp directories. If a native mounted test is unavailable, keep
the focused evidence and report the missing host prerequisite; do not convert
it into a passing result.
