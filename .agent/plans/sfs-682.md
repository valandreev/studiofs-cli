# Enable adaptive metadata caching on retained macFUSE

This plan is a living execution record for SFS-682 and follows `.agent/PLANS.md`.

## Purpose / Big Picture

The retained legacy macFUSE backend currently gives every metadata reply a
one-second kernel lifetime. That leaves repeated `stat`, lookup, and directory
metadata operations paying the callback cost even after SFS-681 has established
the shared coherence health and invalidation path. This change will let stable
metadata participate in the macOS kernel cache for a longer bounded interval
when coherence is healthy, while returning zero cache lifetime when the health
state is uncertain. Native invalidation remains the correctness mechanism for
remote and local mutations.

The result is observable in focused macFUSE tests and mount logs: healthy
coherence selects the adaptive metadata policy, degraded or unconfirmed
coherence selects the conservative policy, and missing lookups use the same
policy for negative dentry caching. Windows, Linux, the shared coherence
contract, and the experimental FSKit backend remain unchanged.

## Surprises & Discoveries

- SFS-681 already invalidates the root/inode kernel state when coherence becomes
  unsafe, so the metadata TTL change does not need a second fallback timer.
  Evidence: `StudioVfs::apply_coherence_transition` calls
  `retire_untrusted_coherence_cache` on a safe-to-unsafe transition.
- The retained macFUSE bridge has no negative-entry reply today: `lookup`
  returns `ENOENT`. FUSE low-level entry replies can represent a negative dentry
  with inode zero, so the adaptive policy can cover negative lookups without a
  shared API change.

## Decision Log

- Decision: Keep the policy in the macFUSE adapter and derive it from
  `StudioVfs::coherence_allows_os_cache()` at each metadata reply.
  Rationale: the health state can change while a mount is alive; a cached policy
  stored only at mount creation would keep using aggressive TTLs after a failure.
  Date/Author: 2026-09-09 / Codex
- Decision: Use a bounded 60-second adaptive timeout and zero-second
  conservative timeout for attribute, positive-entry, directory, and negative
  lookup metadata.
  Rationale: 60 seconds matches the proven Windows metadata timeout, while zero
  disables stale metadata reuse during uncertainty; native invalidation remains
  the primary correctness mechanism.
  Date/Author: 2026-09-09 / Codex
- Decision: Do not add an environment switch or change shared VFS metrics.
  Rationale: SFS-682 requires automatic health fallback and the existing macFUSE
  open-cache and invalidation diagnostics already expose the relevant state;
  adding a second configuration surface would duplicate the Windows-only policy
  and expand scope before SFS-684's benchmark decision.
  Date/Author: 2026-09-09 / Codex

## Outcomes & Retrospective

The retained macFUSE adapter now selects a 60-second bounded metadata lifetime
only while `StudioVfs::coherence_allows_os_cache()` is true. It uses zero-second
timeouts after unsafe or unconfirmed coherence, replies to missing lookups with
negative entries under the same policy, and keeps the runtime-stats inode
uncached. The existing native invalidation path remains the freshness mechanism.

The full macFUSE library suite passed with 194 tests, plus package check and
Clippy with warnings denied. Native mounted proof was not run; it remains a
separate host-gated validation and is not implied by package tests.

Final verification also passed `cargo fmt --all -- --check` and
`git diff --check`. Linear was updated with the implementation and validation
evidence; no commit or pull request was created.

## Context and Orientation

`crates/studiofs-macfuse/src/adapter.rs` owns the retained macFUSE callback
adapter and currently defines `TTL_SECONDS = 1.0`. Low-level `lookup` replies
carry both `entry_timeout` and `attr_timeout`; `getattr` replies carry
`attr_timeout`. The same entry reply shape is used by create, mkdir, mknod, and
symlink callbacks, while setattr replies carry attributes only.

`crates/studiofs-macfuse/src/low_level.rs` owns the native invalidation queue.
SFS-681 maps semantic attribute/content/directory/entry invalidations into this
queue and exposes delivery diagnostics. `crates/studiofs-vfs/src/coherence.rs`
and `crates/studiofs-vfs/src/vfs/workers.rs` own the health state machine; the
macFUSE adapter must only consume its public health decision.

## Plan of Work

First add unit tests in the existing macFUSE test module for the policy's
adaptive and conservative timeout values, for health-driven selection before
and after the fixture reaches a healthy boundary, and for the negative lookup
timeout being zero in the conservative mode and bounded in adaptive mode. Run
each new test against the unchanged implementation and confirm the expected
failure.

Then replace the fixed adapter TTL with a small macFUSE policy value selected
from the current VFS coherence health. Use the adaptive timeout for positive
entry and attribute replies and use the conservative timeout when health is
unsafe. In the lookup callback, translate only `ENOENT` into a low-level entry
reply with inode zero and the selected negative-entry timeout; preserve all
other errno replies. Keep the existing invalidation queue and health-retirement
behavior intact.

Finally run the focused macFUSE tests, package compilation and Clippy, format
and diff checks. Native mounted macFUSE validation remains separate and must be
reported as unavailable if the host does not provide a reliable mount contour.

## Validation and Acceptance

Acceptance requires nonzero tests proving that healthy coherence selects a
longer bounded metadata lifetime, unsafe or unconfirmed coherence selects zero
cache lifetime, positive metadata replies use the selected values, and an
`ENOENT` lookup is represented as a negative entry with the selected negative
timeout. Existing invalidation tests must remain green. No Windows or shared
VFS source file may change.

## Idempotence and Recovery

The changes are confined to the macFUSE adapter and its execution plan. Tests
use the existing workspace target tempdir harness. If a native mounted test is
unavailable, retain focused package evidence and report the missing host
prerequisite rather than weakening the test or increasing a timeout.
