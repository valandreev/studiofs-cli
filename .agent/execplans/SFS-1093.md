# Expose client compression accounting

This living ExecPlan follows `.agent/PLANS.md`. Keep Progress, Surprises & Discoveries, Decision Log, and Outcomes & Retrospective current.

## Purpose / Big Picture

A user can inspect compression effectiveness through existing upload statistics, diagnostics, and the hidden runtime stats file. Logical quota remains based on file size. Stored upload bytes measure the encoded STFS body, including a v3 seek table but excluding its fixed header and all encryption framing. The ratio is stored divided by logical, so smaller values mean better savings.

## Surprises & Discoveries

Production bootstrap previously constructed independent read/write DataStore objects; changing only clone constructors would hide normal read decode time from upload stats. Bootstrap now constructs the dedicated read pool through clone_for_reads, which shares accounting and throttle state while keeping a separate connection pool. Full reads decode in FetchScheduler after remote decryption, and snapshot payload reads have a separate decode caller. Range reads decode inside DataStore itself.

## Decision Log

Successful fragment PUTs count logical/body bytes and outcomes; failed attempts and preparation do not. Repeated successful PUTs count again, consistently describing client transfer work. Generic artifacts are excluded through an absent fragment outcome. The raw policy-off case contributes bytes but neither rejection counter. The ratio is absent before nonempty uploads. Effective policy lookup failure yields None and a policy-known gauge of zero. Decode time includes blocking admission and full checksum work, excludes download/decryption, and includes failed v3 decodes. This keeps accounting outside foreground durability and quota decisions. These decisions implement ADR 0015 without per-file tracking.

## Context and Orientation

`crates/studiofs-data/src/store.rs` prepares STFS v2 (raw) or v3 (compressed) fragment bodies, encrypts them into SFEC envelopes, and performs PUTs and range reads. It now owns shared CompressionStats and the outcome accompanying PreparedPayload. `crates/studiofs-vfs/src/fetch.rs` and `snapshot_worker.rs` use its metered full decoder. `vfs/bootstrap.rs` creates the dedicated read connection pool sharing client stats. `vfs.rs` projects counters into the serde-defaulted VfsUploadStats in `vfs/metrics.rs`. `vfs/runtime_stats_surface.rs` projects the values into existing object_io metrics through VfsUploadStats::insert_compression_metrics, also used by `crates/studiofs/src/cli/perf.rs` for diagnostics parity. `crates/studiofs/src/cli/status.rs` displays the human-readable policy, ratio and counters. ADR 0015 documents the exact size and time definitions.

## Plan of Work

Test compressible, random, disabled, and final-threshold input, no accounting before success, diagnostic defaults and typed policy, decode paths, and quota remaining logical after a successful compressed PUT. The quota fixture also fetches a cold range and full fragment through FetchScheduler, proving both decode timings appear in the VFS counters.

## Interfaces and Dependencies

CompressionStats is a local data-store snapshot. Its Arc<Mutex<_>> is shared by read/write clones and is never persisted. PreparedPayload carries Option<FragmentUploadOutcome>, where no outcome denotes generic artifacts and V3/Raw reason identify fragment encoding. VfsUploadStats adds typed optional CompressionPolicy, optional f64 ratio, and u64 counters with serde defaults. Existing encryption counters, quota code and compression algorithms retain their contracts.
