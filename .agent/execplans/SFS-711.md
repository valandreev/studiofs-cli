# SFS-711: Detect replay gaps below the retained event-log floor

This ExecPlan is a living record of the SFS-711 implementation and follows
`.agent/PLANS.md`. Keep `Progress`, `Surprises & Discoveries`, `Decision Log`,
and `Outcomes & Retrospective` current while working.

## Purpose / Big Picture

An existing client that was offline longer than PostgreSQL retains event-log
history must stop trying an impossible catch-up. After this change, the client
receives a typed `RebootstrapRequired` result containing the local cursor, the
authoritative retained-history floor, and the checkpoint version to use for a
later recovery. PostgreSQL outage, a normal caught-up page, and a missing range
not explained by the retained floor remain distinct outcomes.

The user-visible proof is a focused `studiofs-meta` test: a cursor below the
persisted `metadata_state.event_log_prune_floor` returns the typed outcome,
while a cursor at the floor continues through the existing paged replay path.
The later automatic local rebase is SFS-712 and is deliberately out of scope.

## Surprises & Discoveries

- SFS-709 already persists `metadata_state.event_log_prune_floor` and rejects
  non-contiguous pages as `MetaError::ReplayGap`; the missing behavior is the
  authoritative floor check and a distinct rebootstrap outcome.
- `metadata_sync.rs` is newer than the current Codebase Memory generation, so
  its exact source is verified directly after graph discovery.
- The replay transaction now takes a shared per-volume advisory lock before
  reading `metadata_state`; SFS-709's prune transaction already takes the
  matching exclusive advisory lock before deleting rows and advancing the
  floor. This avoids contending with ordinary metadata version updates.

## Decision Log

- Decision: Add `MetaError::RebootstrapRequired` instead of reusing
  `MetaError::ReplayGap`. Rationale: callers and SFS-712 must distinguish an
  expected finite-history recovery boundary from a structural/malformed gap.
  Date/Author: 2026-09-15, Codex.
- Decision: Carry scalar recovery coordinates, not checkpoint bytes, in the
  error: local cursor, retained floor, checkpoint version, and frozen target.
  Rationale: the existing validated `BootstrapCheckpointDescriptor` API is the
  safe source of checkpoint bytes; putting payloads in an error would duplicate
  a remote read and enlarge diagnostics. Date/Author: 2026-09-15, Codex.
- Decision: Coordinate replay and pruning with shared/exclusive transaction
  advisory locks keyed by volume, while reading the floor and checkpoint in
  the same transaction as the event-page query.
  Rationale: pruning then either commits before the sync snapshot or waits for
  the snapshot to finish, without blocking ordinary metadata version updates.
  Date/Author: 2026-09-15, Codex.

## Outcomes & Retrospective

Implementation is complete and ready for delivery. The
retained-floor decision is centralized in `validate_replay_cursor_against_floor`;
the replay transaction takes a shared advisory lock and reads format,
checkpoint, and floor before selecting the page. Structural gaps remain
`ReplayGap`, while a cursor below the persisted floor is surfaced as
`RebootstrapRequired` and records the existing degraded/read-only recovery
state. No checkpoint bytes or automatic rebase behavior were added; SFS-712
remains the consumer of the signal.

## Context and Orientation

`crates/studiofs-meta/src/pg_engine/event_log_pruning.rs` prunes complete
`batch_version` groups and persists the highest safely removed version in
`metadata_state.event_log_prune_floor`. The same row stores the published
bootstrap `checkpoint_version` and current remote `version`.

`crates/studiofs-meta/src/pg_engine/metadata_sync.rs` owns the existing-client
catch-up path. It starts a PostgreSQL transaction, takes the shared per-volume
replay advisory lock, and selects a bounded page through
`metadata_io::query_foreign_event_page`, and only then applies the page to the
local redb view. `crates/studiofs-meta/src/pg_engine/sql.rs` contains the SQL
constants. `crates/studiofs-meta/src/engine.rs` defines typed errors and the
redacted `PgSyncFailure` diagnostics mapped to CLI/VFS status.

`BootstrapCheckpointDescriptor` in `engine.rs` is the validated checkpoint
record produced by SFS-702. SFS-711 reports its `checkpoint_version`; SFS-712
will later fetch/import the complete descriptor while preserving local pending
state. No foreground metadata read is moved to PostgreSQL.

## Validation and Acceptance

Acceptance requires all of the following:

- A local cursor strictly below the persisted floor returns
  `MetaError::RebootstrapRequired` with the floor and checkpoint version from
  the same PostgreSQL state snapshot.
- A cursor exactly at the floor proceeds to normal bounded page selection;
  this remains distinct from a PostgreSQL outage/timeout.
- A missing first batch while the persisted floor does not explain it remains
  `MetaError::ReplayGap`, and a page with no rows below a target is not treated
  as successful convergence.
- The replay-gap/rebootstrap result clears the frozen startup target and keeps
  the lifecycle degraded/read-only through the existing recording seam.
- Focused tests pass with nonzero counts, package checks and Clippy pass with
  warnings denied, and formatting/diff checks pass. Live PostgreSQL execution
  remains environment-gated.
