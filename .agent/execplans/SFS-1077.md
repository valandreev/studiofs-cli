# Serve scratch entries through StudioVfs namespace operations

This living ExecPlan follows `.agent/PLANS.md` and builds on the rule engine
in `.agent/execplans/SFS-1074.md`, rule loading in `.agent/execplans/SFS-1075.md`,
and local scratch storage in `.agent/execplans/SFS-1076.md`.

## Purpose / Big Picture

After this change, files, directories, and symlinks matched by `.studiofsignore`
(including the built-in `._*` AppleDouble rule) are served as real local-only
scratch entries through `StudioVfs`. Creating, reading, writing, truncating,
setting attributes, setting extended attributes, listing directories, unlinking,
removing directories, and renaming within the scratch class all work on the
creating client without emitting any `event_log` rows or submitting S3 uploads.
AppleDouble `._*` files move out of the metadata-only `IgnoredEntryRegistry`
discard class into the scratch layer while `.Spotlight-V100`, `.fseventsd`, and
trash components remain in discard. Cross-class renames and hardlinks return
`EXDEV` (`VfsError::CrossDevice` / `STATUS_NOT_SAME_DEVICE`) until promote
(SFS-1078) and demote (SFS-1079) land.

## Surprises & Discoveries

- Observation: `crates/studiofs-winfsp/src/context.rs:1376` (`heal_directory_orphans_for_delete`) checks only `is_synthesized_ignored_ino(dir_ino)` before calling `meta.readdir(dir_ino)`. Scratch directories use normal allocated inodes (`< FIRST_IGNORED_INO`) and do not exist in tracked `dentries`, so `heal_directory_orphans_for_delete` must also skip scratch directories.
  Evidence: Direct inspection of `crates/studiofs-winfsp/src/context.rs:1376-1399`.
- Observation: `acl.rs` `effective_access_level_meta` (used by `enforce_access_async`) calls `meta.get_attr(current)` directly without checking `get_scratch_attr`, and `sync_ops.rs:1667` skipped `enforce_access` for scratch inodes during `fsync`.
  Evidence: Direct inspection of `crates/studiofs-vfs/src/vfs/acl.rs:163-184` and `crates/studiofs-vfs/src/vfs/sync_ops.rs:1667`.
- Observation: ADR 0016 specifies that the `user.studiofs.` prefix (including `user.studiofs.scratch`) is hidden from `listxattr` so `cp -a` and `rsync -X` do not fail trying to copy virtual read-only xattrs, while `getxattr` returns the marker and `setxattr`/`removexattr` reject writes.
  Evidence: `docs/adr/0016-per-path-sync-status-and-barrier.md:163-168`.

## Decision Log

- Decision: Add a dedicated local-only `SCRATCH_SYMLINKS` redb table (`TableDefinition<u64, &[u8]>`) alongside the existing four `SCRATCH_*` tables.
  Rationale: Keeps scratch symlink targets isolated from tracked `SYMLINKS_TABLE` (which is replicated and exported in snapshots) and avoids overloading `SCRATCH_XATTRS` with magic keys. Created on open after the format check with no format version bump.
  Date/Author: 2026-11-20 / Antigravity.
- Decision: Maintain two in-memory hint structures in `RedbMetaEngine` (`scratch_index` behind a leaf `RwLock`, serialized with scratch mutations via `scratch_mutation_lock`): the set of live scratch inodes and per-parent scratch child counts.
  Rationale: Tracked hot-path operations (`lookup`, `readdir`, `getattr`, `read`, `write`, `rmdir`, `xattrs`) pay zero extra redb read transactions when a file is tracked or a directory has no scratch children. Linearizability is preserved by inserting into the hint before `txn.commit()` and removing after `txn.commit()` under `scratch_mutation_lock`.
  Date/Author: 2026-11-20 / Antigravity.
- Decision: Cache per-directory compiled rule scopes in `IgnoreRules` keyed by `(parent_ino, dir_rename_epoch, rule_generation)` in a bounded LRU behind a leaf mutex outside `LockTier`.
  Rationale: Satisfies the hot-path requirement without rescanning ancestor paths or looking up rule-set hash maps on every `create`/`mkdir`/`symlink`. `dir_rename_epoch` bumps only on directory renames, removals, and foreign invalidation resets, not on ordinary file creation.
  Date/Author: 2026-11-20 / Antigravity.
- Decision: Sort merged `readdir` entries deterministically by `entry.name` byte order when merging tracked, deferred, and scratch children.
  Rationale: Tracked and scratch redb tables each yield entries in lexicographic `name` order; merging and sorting by `name` keeps directory offsets stable and repeatable across repeated enumerations.
  Date/Author: 2026-11-20 / Antigravity.
- Decision: Expose virtual read-only xattr `user.studiofs.scratch` with value `b"1"` via `get_xattr`/`get_xattr_size`, hidden from `list_xattrs`, and rejected on `set_xattr`/`remove_xattr` with `MetaError::AccessDenied`.
  Rationale: Matches ADR 0014, ADR 0016, and the existing reserved xattr convention (`RETAINED_RECEIPT_XATTR`).
  Date/Author: 2026-11-20 / Antigravity.

## Context and Orientation

StudioFS separates foreground metadata in `studiofs-meta` (`RedbMetaEngine`,
wrapped by `PgMetaEngine` and `ReadOnlyMetaEngine`), local payload caching in
`studiofs-cache`, platform-neutral filesystem core in `studiofs-vfs`
(`StudioVfs`), POSIX errno mapping in `studiofs-bridge`, and OS adapters in
`studiofs-linux-fuse`, `studiofs-macfuse`, and `studiofs-winfsp`.

SFS-1074 added the pure `.studiofsignore` classifier in
`crates/studiofs-vfs/src/scratch_rules.rs`. SFS-1075 added background rule
loading, persistence, and pinning in `crates/studiofs-vfs/src/vfs/ignore_rules.rs`.
SFS-1076 added the local redb tables (`scratch_inodes`, `scratch_dentries`,
`scratch_overlay`, `scratch_xattrs`) in `crates/studiofs-meta/src/redb_engine/scratch.rs`
and routed scratch writes through the mounted writer stack with
`ScratchOverlayCommitter` and `ScratchUploadSubmitter`.

## Validation and Acceptance

Focused tests must pass (nonzero test counts) verifying:
- Rule-based classification on `create`, `mkdir`, and `symlink`, sticky class
  (adding a rule does not flip existing tracked entries; lookup never
  re-evaluates rules), whole subtree of a scratch directory stays scratch, and
  `.studiofsignore` in a tracked directory is always tracked.
- `._*` files route to scratch (preserving data across reads/reopen) while
  `.Spotlight-V100`, `.fseventsd`, and trash components stay discard.
- Lookup, merged `readdir`/`readdir_with_attrs` with stable sorted offsets,
  `getattr`, `setattr` (attr-only and truncate shrinking/growing), `read`/`read_into`/`read_into_fh`
  seeing unflushed writer pages, `write`/`write_fh`/`write_fh_with_deferred_materialize`,
  `flush`/`fsync`/`release`, and `xattrs` including read-only `user.studiofs.scratch`.
- Access checks enforced on scratch reads, writes, `setattr`, `fsync`, and xattrs.
- Unlink emits zero events and frees payload objects immediately when closed or
  after last handle closes when open-unlinked.
- `rmdir` fails with `DirNotEmpty` (`ENOTEMPTY`) on a tracked directory whose
  only children are scratch, and removes empty scratch directories with zero events.
- Same-class scratch rename stays scratch (including overwrite and open-unlinked
  target), tracked rename to a matching name in a tracked parent stays tracked,
  cross-class renames return `CrossDevice` (`EXDEV`), and hardlink rules return
  `CrossDevice` (`EXDEV`) for scratch->any and tracked->scratch-dir while keeping
  tracked->matching-name-in-tracked-parent tracked.
- Zero `event_log` rows and zero upload submissions across all scratch operations.

## Idempotence and Recovery

All new scratch tables are created on open after the format version check without
changing the persisted format version. Local redb transactions use `Immediate`
durability for scratch mutations; a failed transaction leaves prior metadata
intact, and startup cache cleanup reclaims any unreferenced local payload objects.
