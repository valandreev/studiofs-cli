# SFS-696 Introduce an Incompatible PG Sync Format Version Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish an incompatible PostgreSQL sync-format boundary, reject legacy local/remote state with a recreate/discover-required error, and add the atomic bootstrap-checkpoint fields needed by the follow-up sync issues.

**Architecture:** Keep the existing `CURRENT_FORMAT_VERSION` as the single compatibility number for local redb and the PostgreSQL `metadata_state` row. PostgreSQL stores that number beside the live checkpoint descriptor; fresh initialization and checkpoint publication write all descriptor fields together. Schema setup may add missing columns with unmistakable legacy sentinel values, but it must never rewrite legacy rows into the new format. Reachable PostgreSQL state is validated during `PgMetaEngine` startup and discovery; connection-unavailable local-first fallback remains unchanged.

**Tech Stack:** Rust 2024, `redb`, `tokio-postgres`, PostgreSQL DDL, `sha2`, focused unit tests, and the existing `studiofs-meta`/CLI fixtures.

---

## Context and decisions

- `CURRENT_FORMAT_VERSION` is `4` on the starting commit and will become `5`.
- `STUDIOFS_PG_SCHEMA_VERSION` is a currently unused DDL-generation marker at `6` and will become `7`.
- `metadata_state.metadata_format_version` is the persisted PG sync boundary and must equal the current local format version. A missing/legacy value is invalid; it is never treated as current.
- The live checkpoint descriptor adds `checkpoint_sha256`, `checkpoint_publication_state`, and `checkpoint_generation` to `metadata_state`. The existing `checkpoint_version`, `snapshot`, and `format_info` remain the replay floor, bytes, and format bootstrap payload.
- The durable applied replay cursor already exists in local redb (`pgLastAppliedBatchVersion` and its namespace companion). SFS-701's startup target is session state, so this issue will not add a stale target column to PostgreSQL.
- No data migration, compatibility read, dual-write path, or old-disk conversion is part of this change. Existing rows reached through schema repair receive sentinel values and fail the version check.

## Surprises and discoveries

- `STUDIOFS_PG_SCHEMA_VERSION` was only declared; no runtime code compared it, so the persisted row version is required for an actual compatibility boundary.
- `PgMetaEngine::validate_postgres_schema` checked table names but not required columns or the selected volume's format, so old PG state could pass startup validation.
- `metadata_state` already contains the checkpoint bytes, replay floor, and serialized `FormatInfo`; adding the checksum/publication/generation fields there keeps the future descriptor atomic without inventing another table.
- The local replay cursor is already durable in redb, while a startup target must remain ephemeral according to SFS-701; adding a PG target field would create stale state.

## Decision log

1. **Use `metadata_state.metadata_format_version` rather than a volume-level duplicate.** The compatibility contract belongs to the bootstrap/checkpoint state and is returned with the descriptor that SFS-702 will expose.
2. **Use `0` as the schema-repair sentinel for the new format column.** Fresh rows write `CURRENT_FORMAT_VERSION`; old rows cannot silently become compatible after `ensure_studiofs_pg_schema` runs.
3. **Use a 32-byte zero checksum only as the legacy schema-repair sentinel.** Fresh initialization and checkpoint writes always store the SHA-256 digest of the checkpoint bytes; the existing descriptor validation can reject a sentinel when it is consumed.
4. **Reuse `MetaError::UnsupportedFormatVersion`.** It already represents an incompatible persisted format and keeps local and PG failures typed consistently; its display will include the required recreate/discover guidance.

## Validation and acceptance

The change is accepted when:

1. A local redb record with format `4` returns a typed unsupported-format error expected at `5` and actionable recreate/discover guidance.
2. A reachable PostgreSQL volume with a missing/sentinel/legacy `metadata_format_version` cannot open through `PgMetaEngine` or discovery.
3. A fresh schema contains all descriptor fields and a fresh init/checkpoint write populates them atomically, including a real checksum.
4. Dump/load preserves the new state shape and rejects the old manifest version.
5. Focused tests execute at least one test each; `running 0 tests` is not considered evidence.

## Idempotence and recovery

- Re-running schema setup is safe: `IF NOT EXISTS` preserves current rows and never upgrades a legacy sentinel.
- Re-running init/checkpoint publication is safe under the existing `ON CONFLICT` rules; generation advances only for accepted checkpoint writes.
- If validation fails, the operator must recreate the incompatible PostgreSQL/local state or use `studiofs discover`; no compatibility repair is attempted.
