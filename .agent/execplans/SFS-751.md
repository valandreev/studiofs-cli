# Allow concurrent legacy macFUSE callbacks

This living ExecPlan follows `.agent/PLANS.md`. Keep Progress, Surprises & Discoveries, Decision Log, and Outcomes & Retrospective current.

## Purpose / Big Picture

One slow synchronous filesystem callback currently stops all unrelated requests on a legacy macFUSE mount. SFS-751 changes the session to macFUSE's supported multithreaded loop. A native test must hold a callback, complete an unrelated request within a deadline, and release the callback before the session and its callback state are destroyed. FSKit is outside this issue.

## Surprises & Discoveries

The Codebase Memory generation is older than current `low_level.rs` and `adapter.rs`; symbol line ranges are stale. Literal current source is required. `Session::run` has one production caller, `mount_with_request`, which keeps boxed callback state alive, clears the invalidator, drains asynchronous reply tasks, and drops the native session last. Existing request ownership consumes each reply and supplies a fallback error on unreplied drop.

The installed library reports libfuse API version 2.9.9 and exports both pthread and dispatch loops. macFUSE's pthread loop disables cancellation while processing callbacks. Unlike libfuse3, its function accepts no worker configuration argument.

The first regression used lookups in the same parent directory. Those requests remained serialized even with the multithreaded loop, so they did not isolate native callback dispatch. The regression now opens two distinct files before holding one write callback; the other write passes with the multithreaded loop and fails with the old loop.

The registered mounted scenario reported `Passed`, convergence across three clients, no namespace violations, and successful cleanup. Its operation log also records one client-c read-loop admission rejection (`active workers 1/1`). The runner's global mounted-I/O pool admits one operation; it rejected this peer read before spawning the native filesystem call. The diagnostic's 30-second text describes a configured timeout budget, not an observed timeout. That run is supporting convergence and cleanup evidence; the dedicated held-write regression supplies the decisive concurrent callback and shutdown proof.

The native test only needs a static C operations table: its setup is serialized and the installed library copies that table on session creation. Release can use channel disconnection instead of a condition variable; dropping the final sender releases all matching callbacks, whereas sending one token would release only one. The callback entry channel already proves execution, so the callback count was redundant for acceptance.

The current stable toolchain is Rust 1.99.0. Its strict CLI check and full Clippy pass stop on pre-existing `Atomic::fetch_update` deprecation in `studiofs-meta/src/pg_engine/replication_flush.rs:291`. Rust 1.95.0 is installed and matches the declared workspace MSRV (minimum supported Rust version); its strict CLI check passes. Full MSRV Clippy instead stops on existing `collapsible_if` and `nonminimal_bool` findings in `studiofs-cache`. Strict Clippy restricted to the changed package with `--no-deps` passes on Rust 1.99.0. These findings are outside this test-harness review and were not suppressed or changed.

On the single-threaded red path, request exit only after the queued peer write receives its reply. An earlier test teardown attempted exit with that write still queued and stalled native unmount. Its owned test mount and processes were removed. The regression now releases the blocker and collects both replies before red-path exit, keeps callback userdata owned by the session worker, and terminates the explicitly selected test process without destructors on a fatal native timeout. Native unmount can also leave a temporarily busy vnode; mount-point removal polls that observable condition with a three-second bound.

## Decision Log

- Decision: Use the native pthread session loop, preserving the existing asynchronous reply tracker.
  Rationale: macFUSE already owns decoding, request buffers, native worker dispatch, and worker teardown. Reimplementing a blocking callback pool would duplicate these owners and require new request copies and shutdown coordination.
  Date/Author: 2026-10-02 / Codex.
- Decision: Use a native test with synchronized callback blocking and an explicit ignored marker.
  Rationale: A unit check cannot establish the native library's concurrency behavior; an absent driver must never silently pass the acceptance check.
  Date/Author: 2026-10-02 / Codex.
- Decision: Remove the test operations allocation/wrapper, use a constant-initialized gate mutex and channel-disconnection release, and merge destruction confirmation into the session-result channel. Retain explicit destruction authorization and bounded confirmation before joining.
  Rationale: The allocation and extra synchronization state were unnecessary. A bare join would lose the bounded teardown check; immediate worker destruction after loop return could free callback state while the test is checking for premature return. The second result-channel message confirms async reply draining and destruction without a separate completion channel.
  Date/Author: 2026-10-02 / Codex.

## Context and Orientation

`crates/studiofs-macfuse/src/low_level.rs` owns the libfuse2 FFI and `Session`. Before SFS-751, `Session::run` called `fuse_session_loop`, which runs callbacks serially; it now calls `fuse_session_loop_mt`. `crates/studiofs-macfuse/src/lib.rs::mount_with_request` owns the boxed adapter state through session teardown. `crates/studiofs-macfuse/src/adapter.rs` uses shared immutable callback references, synchronized handle maps, and an asynchronous reply tracker. `crates/studiofs-macfuse/csrc/low_level_ops.c` creates callback tables using the installed headers, avoiding a hand-maintained C struct layout in Rust.
