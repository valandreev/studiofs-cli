# Scratch Layer: Share One Promote Path Between Automatic and Explicit Promotion (SFS-1125)

This ExecPlan is a living document. The sections `Progress`, `Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` must be kept up to date as work proceeds.

## Purpose / Big Picture

Automatic scratch promotion (triggered when `.studiofsignore` rules stop matching existing scratch entries) and explicit rename promotion (renaming a scratch file or directory to a tracked target) previously duplicated path resolution, subtree freezing, upload hand-off, and metadata migration logic across `studiofs-vfs` and `studiofs-meta`. After this refactor, both paths share one tracked-directory path resolver, one subtree walk/freeze helper, one upload hand-off helper, and one transactional metadata subtree mover, while keeping all existing intentional differences explicit and documented and preserving all existing event ordering, lock ordering, retained-identity, and recovery semantics.

## Surprises & Discoveries

- `StudioVfs::sync_meta()` returns `Arc<dyn VfsMeta>`, whereas `find_over_limit_scratch_directories` accepts `&dyn MetaEngine`; because `VfsMeta` and `MetaEngine` are separate trait bundles that do not upcast directly between trait objects, making the shared path/subtree/freeze helpers generic over `M: MetaInodes + MetaNamespace + ?Sized` and `M: MetaEngineCore + ?Sized` lets both callers share the exact same functions without extra adapter shims.

## Decision Log

- Decision: Make `resolve_tracked_directory_path_with`, `collect_scratch_promote_subtree`, and `freeze_scratch_promote_subtree` generic over `?Sized` metadata capability traits (`MetaInodes + MetaNamespace`, `MetaEngineCore`) rather than taking `&dyn MetaEngine`.
  Rationale: `StudioVfs` internally holds `dyn VfsMeta` (see `crates/studiofs-vfs/src/runtime.rs`), while offline status inspection receives `&dyn MetaEngine`.
  Date/Author: 2026-11-21 / StudioFS Agent

- Decision: Preserve intentional divergences explicitly in parameters and comments:
  - `promote_scratch` (explicit rename): can move out of an enclosing scratch parent directory, commits root binding and optional displacement via `rename_or_promote_in_txn` (`RenameEntry`), does not touch `TOTAL_INODES` (left for SFS-1126), and calls `namespace_mutations.record_rename` + `finish_rename_displacement`.
  - `promote_scratch_auto_inner` (automatic promotion): binds root in place via `AddEntry` (after updating parent `mtime`/`nlink`), resolves directory collisions via `merge_auto_promote_directory`, resolves non-directory collisions via `.scratch-conflict-<client>`, skips `kept_scratch` rule-matching descendants, updates `TOTAL_INODES`, and updates VFS dentry cache without inserting a negative marker on `original_name`.
  Date/Author: 2026-11-21 / StudioFS Agent
