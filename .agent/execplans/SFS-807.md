# Move macFUSE memory sampling out of open callbacks

This living ExecPlan follows `.agent/PLANS.md`.

## Purpose / Big Picture

Concurrent file opens must not queue behind an OS memory measurement. Read-only files use kernel caching only with a fresh estimate showing they fit; missing or stale telemetry selects direct I/O while local VFS payload caching still works.

## Surprises & Discoveries

The Linux adapter already has an owned memory worker with a one-second cadence and two-second expiry. Its sampler is crate-private; extracting a shared subsystem would broaden this fix. macFUSE currently treats missing telemetry as permission for UBC caching. Both legacy and FSKit call `CallbackState::wait_for_reply_tasks` during teardown.

## Decision Log

Use the existing Linux ownership/channel/join pattern locally in macFUSE without new dependencies. The initial implementation used versioned atomics to reject mixed snapshots. Review replaced that custom protocol with `RwLock<Option<(Instant, u64)>>`; callbacks use `try_read` and return `None` on contention or poison, while OS sampling runs outside the write lock. This preserves nonblocking reads with less custom code. Date: 2026-10-14.

Measure sample age from before the syscall and expire after two seconds; zero/missing/stale samples conservatively select direct I/O. Stop and join after callback drain, with Drop as the cleanup fallback. Date: 2026-10-14.

## Context and Orientation

`crates/studiofs-macfuse/src/adapter.rs` routes read-only open/create handles through `open_with_result` and `read_only_open_cache_policy`. Before SFS-807, the former called a process-global sysinfo snapshot guarded by a mutex. `CallbackState` owns the adapter and drains callbacks in both `lib.rs` and `fskit.rs`. `docs/platform-bridges.md` defines the macOS cache policy. The working branch is `feature/sfs-807-move-macfuse-available-memory-refresh-off-the-open-callback`; initial changes were only the tracked Codebase Memory snapshot and metadata, which must be preserved.

## Plan of Work

Add `adapter/memory_sampler.rs` with a dedicated thread, `RwLock` snapshot, and stop channel. Only the thread owns sysinfo. Store this sampler on `StudioVfsAdapter`, read it from `open_with_result`, and stop it after reply drain. Remove the global mutex/synchronous refresh and old tests that expect refresh from a reader. Document conservative fallback and age limits. Exercise the actual adapter open path while an injected sampling function is blocked on a channel.

## Attached review follow-up (2026-10-14)

Unknown attributes now always force direct I/O, tested with both absent and present memory estimates. The present-memory case failed before the correction. Sampling now waits only the remainder of the interval measured from the start of the current sample. A 300ms measurement leaves 700ms to wait; measurements taking at least one interval leave zero delay. This avoids accumulating a deadline and catch-up bursts. The old full-interval wait was temporarily restored and the pacing regression failed (1s versus 700ms), then passed with the correction. Actual measurements older than the TTL still correctly fail safe; pacing cannot guarantee freshness when OS sampling itself is too slow.
