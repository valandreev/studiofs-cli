# Decouple Linux callback workers from CPU count

This living ExecPlan follows `.agent/PLANS.md` and implements Linear SFS-789.

## Purpose / Big Picture

Linux synchronous callbacks may wait for disk or object reads. Operators need a worker limit independent of CPU count, bounded by the configured kernel background queue, with visible queue and worker values. Compare the proposed queue-derived default against explicit limits on real mounted workloads before promoting it.

## Surprises & Discoveries

The configured graph project E-dev-studiofs-cli is absent; home-val-dev-studiofs-cli is available. Direct source inspection confirms graph findings. Old libfuse headers expose only max_idle_threads, which controls thread retention, not active concurrency. A hard worker cap is possible through the existing opaque configuration API on libfuse 3.12+ only. Do not claim a hard cap on legacy builds.
