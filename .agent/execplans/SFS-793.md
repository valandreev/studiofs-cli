# Reduce Linux directory snapshot and reply allocation

This living ExecPlan follows `.agent/PLANS.md`. The task is Linear SFS-793.

## Purpose / Big Picture

Linux directory enumeration should avoid loading a directory when a caller only opens it, retain only the names/inode/type needed by ordinary readdir, and reuse reply storage. Offsets are positions in an immutable per-handle name snapshot: 0 starts at dot, 1 at dot-dot, and 2 at the first child. Once the first read with room for a minimum child dirent captures that snapshot, namespace mutations must not change it, including when a caller seeks backward. A newly opened handle observes the current namespace on its first read.

The issue explicitly permits a measured equivalent to bounded/paged metadata state. Use a compact lazy snapshot rather than adding metadata cursors across every backend. Measure the retained bytes for a large directory against the old `DirEntryWithAttr` representation. This still has O(N) names after first use; it is not a claim of constant-memory enumeration. Existing VFS readdir continues to hydrate its bounded attribute batch once on first use.

## Surprises & Discoveries

Ordinary libfuse readdir uses only `st_ino` and the file type from `st_mode`. It does not need the full `InodeAttr` stored in every current handle entry. VFS already exposes filtered `readdir` returning `DirEntry`; reuse it rather than adding a second filtering or ACL path. The configured graph project `E-dev-studiofs-cli` was absent; the available `home-val-dev-studiofs-cli` index covers the inspected files without recorded parse errors. System libfuse3 3.18.2 and `/dev/fuse` are present; native mounting capability still needs checking.

Review follow-up: a reply can leave 1–31 bytes unused without fitting a child. Query libfuse for the smallest nonempty-name entry before capture; a 24-byte header constant is insufficient. Pool growth from 96 KiB to 128 KiB uses geometric over-allocation with `reserve` and is then discarded; the original review explanation incorrectly counted reserve from capacity rather than cleared length. Both regressions failed before correction.

## Decision Log

## Context and Orientation

`crates/studiofs-linux-fuse/src/low_level.rs` owns Linux callbacks, `SessionState`, raw directory handle lifetime, and aligned `DirectoryEntryBuffer`. `open_dir` currently captures `Vec<DirEntryWithAttr>` using VFS `readdir_with_attrs`; every `SessionState::readdir` allocates reply and scratch storage. `crates/studiofs-linux-fuse/src/cache_policy.rs` contains the analogous bounded synchronous read-buffer pool. `crates/studiofs-vfs/src/vfs/namespace_ops.rs` exposes `readdir`, which applies the same access checks, deferred entries, root filtering, and cache-coherence rules as the attribute-bearing method. No VFS behavior or metadata backend changes are planned. `docs/platform-bridges.md` describes Linux callback contracts.

## Plan of Work

First add characterization/regression tests next to the existing directory-buffer tests in low_level.rs. Prove an unused directory handle does not enumerate, and measure the old retained entry representation against the intended compact limit. Run these tests before implementation to observe the current failures.

Then replace handle entries with a mutex-protected optional boxed slice of plain DirEntry. Initialize only when a read can consume children; a failed VFS read remains retryable. Serialize initialization per handle, keep snapshots immutable thereafter, and render minimal inode/type stats. Replace each fresh reply allocation with a SessionState-owned bounded pool. Keep requested logical capacity separate from allocated capacity; clear initialized length and scratch on reuse, grow aligned storage safely, and reject embedded NUL without libfuse calls. Recycle after success and error with no lock held through the reply.

Finally test multi-chunk reads, replayed offsets, concurrent rename/unlink/create, fresh handles, zero/tiny sizes, invalid offsets, pool reuse and oversized/count bounds. Update the Linux documentation with first-read snapshot semantics and limits. Inspect all callers of changed signatures and the final diff.

## Validation and Acceptance

A large synthetic directory must retain less than one third of the old entry-and-name footprint; an unused handle retains no entries. A first chunk followed by namespace changes must resume and seek within the same original sequence without duplicates or missing old entries. A fresh handle must see the new names. Repeated replies must reuse aligned and scratch allocations without exposing stale bytes. Pooled storage must be bounded by count and both reply/scratch capacities, while a large one-off request remains valid and is discarded afterwards. Negative offsets return EINVAL and zero-capacity replies do not enumerate.
