# Wake macFUSE shutdown and deferred symlink replies on events

This living ExecPlan follows `.agent/PLANS.md`.

## Purpose / Big Picture

An idle macFUSE mount must not wake ten times per second to check shutdown. A symlink whose parent directory is admitted locally but not yet committed must wait for that commit without holding a blocking-pool worker. Explicit unmount, process signals, request cancellation and shutdown must wake the relevant waiter, with the existing five-second parent retry deadline retained.

## Surprises & Discoveries

A callback drain precedes VFS shutdown, so a VFS shutdown token alone cannot release legacy pending symlinks during session teardown; the adapter cancels its namespace reply token before draining. A dormant current-thread runtime can hold an actual deferred parent commit without adding production test hooks. The VFS already owns deferred namespace completion notifications. Legacy and FSKit symlink callbacks currently dispatch through blocking reply workers. Removing only the sleep would leave the worker occupied. The checked-out repository and shell are macOS paths despite the supplied Windows instruction; platform acceptance will be reported from actual executable checks.

## Review refinements (2026-10-15)

The supplied review defines one active mount watcher as the supported scope. Remove the weak-reference broadcast list, dedicated watcher pipe and dual descriptor poll. A single process-owned nonblocking UnixStream pair handles signal, unmount and drop wakeups. The signal handler retains its raw async-signal-safe write, while ordinary wake/drain code uses Read and Write. Consume wake bytes before rechecking the condition so stale wakes cannot make an idle watcher spin.

Both legacy and FSKit symlink requests now obtain a child token from the adapter shutdown token. That makes the extra parent-token check and select branch redundant. Flatten the timeout result, retaining the absolute deadline and error mapping. The shared dormant/callback runtime helpers live in `crates/studiofs-macfuse/src/test_support.rs`, enabled only for tests.

Keep the VFS shutdown-aware wrapper separate. The base waiter also serves local dirty flush, fsync and release barriers; making its waits cancel on background shutdown would alter local durability behavior. This review suggestion is rejected on contract grounds.

## Deep review disposition (2026-10-15)

The local, git-ignored report `docs/code-reviews/sfs-812-macfuse-signal-symlink-wait-deep-review.md` was verified against the code before any change. Its probe under `target/code-review-sfs-812/` reproduced 3 lost wakeups in 2000 rounds when two watcher loops share one stream.

- [x] Give every watcher a private wake stream; keep the signal stream observe-only while shutdown is requested.
- [x] Wait for deferred progress of the parent inode instead of complete settlement.
- [x] Log wake-stream failures, detach unmount wakes, reset shutdown state before either mount, and tighten tests.
- [x] Run focused tests, mutation checks, Clippy, formatting and diff checks.

Decision: watchers no longer share a stream for stop or unmount. `MacFuseUnmountSignal` keeps a list of the private streams of its active watchers and each watcher detaches on drop. The signal handler still writes only the process-lifetime stream after setting `SHUTDOWN_REQUESTED`; watchers never drain it while the flag is set, so every watcher observes the byte. A byte seen without the flag is stale and is drained, with re-arming if a signal raced the drain. Only `reset_process_shutdown_state`, run before either backend mounts while StudioFS owns no handler, and handler installation consume signal bytes.
Rationale: the earlier single-watcher scope was not enforced, ignored FSKit mount tests share one binary, and a lost wakeup under an infinite poll is a permanent unmount hang.

Decision: the VFS records, for each pending inode, the global settle sequence at its latest admission or settle (`inode_progress`, maintained only by `admit_pending_inode` and `settle_pending_inode`). Symlink captures `DeferredNamespaceProgress` before each attempt and waits with `wait_for_deferred_namespace_progress_or_shutdown`, which returns `Settled`, `Progressed` or `ShutdownStarted`. The full wait now also returns the `DeferredNamespaceWait` enum instead of `bool`.
Rationale: `pending_inodes` counts later `SetAttr` operations on the same inode; waiting for zero made a symlink wait for unrelated attribute commits and could time out with ENOENT even though the parent create was committed. Retrying after each settle of the parent inode bounds retries by real state changes on that inode.

Decision: a wake-stream error ends the watcher with an `error!` log and fail-safe unmount. Without its streams the watcher can no longer observe signals or unmount requests.

Decision: symlink copies name and target once into `Arc<[u8]>`, logs a blocking-attempt `JoinError` before mapping it to EIO, rechecks the absolute deadline before waiting, and accepts an injected retry timeout through `symlink_with_retry_timeout` so the deadline regression runs in 100 ms. A test-only `Notify` reports entry into the deferred wait so tests synchronize on that observable condition.
