# Automate dependency licensing and release notices

This living ExecPlan follows `.agent/PLANS.md`.

## Purpose / Big Picture

Dependency upgrades must not silently change approved licensing. CI will run a pinned cargo-deny policy across platform dependencies, exercise a rejected-license fixture, and generate a reproducible review bundle containing authors, licenses, and upstream notice texts. Release staging must reject unresolved evidence instead of treating this bundle as distribution clearance.

## Surprises & Discoveries

The prior audit has 65 registry packages without reviewed primary notice evidence. These remain evidence gaps, not license incompatibilities. Discovery of a newly recognized file does not automatically clear a baseline gap. There is no binary release packager. RWX owns Linux quality and cargo-audit; existing GitHub native checks are manual. Workspace GPL metadata changed since the pinned inventory, so baseline matching applies only to external dependencies. Cargo-deny treats legacy GPL-3.0 separately from GPL-3.0-only; two exact WinFsp exceptions preserve the prior review.

## Decision Log

Use existing inventory helpers instead of adding another notice dependency. Preserve cargo-audit independently. Scan all targets and all features in cargo-deny. Compare registry identities and license expressions against the reviewed inventory so approved SPDX identifiers alone cannot admit unreviewed changes. Generate review artifacts in CI; require an explicit strict release command before packing binaries. These are implementation choices within SFS-853's authorized solution.

Independent review found that mutable Cargo checksum maps alone cannot bind extracted text to a lockfile archive hash. Require a matching .crate archive and reject unsupported non-workspace path packages. Add root LICENSE to both CI filters. Include named files under LICENSES directories as well as nested LICENSE/COPYING/NOTICE files, retaining reviewed baseline gaps until the audit is intentionally updated.

Repeat generation into another directory and compare hashes. Run the generator with `--release` and verify unresolved evidence produces a failure.

## Validation and Acceptance

The approved lockfile must pass cargo-deny. MIT fixtures must pass while AGPL/missing license fixtures fail specifically on licensing. Repeated bundle generation must be byte-identical. Registry changes absent from the approved inventory must fail. The bundle must include authors, original expressions, license/notice texts, StudioFS LICENSE and native supplement. An unresolved release must fail before packaging. Run `git diff --check`; do not run full Rust suites.

## Idempotence and Recovery
