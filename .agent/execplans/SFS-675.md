# Define metadata coherence and measure the Windows baseline

This ExecPlan follows `.agent/PLANS.md`. Keep Progress, Surprises & Discoveries,
Decision Log and Outcomes & Retrospective current.

## Purpose and context

SFS-675 supplies a platform-neutral metadata cache contract and measured current
Windows behavior before later issues change cache policy. The operator must be
able to reproduce stat, open/close, absent-name lookup and directory-enumeration
measurements on a native mount. This is not an implementation of adaptive caches.

The starting commit is `83822d8ee9954bd072a057aa2ca3b686e14095b9` on the issue
branch. WinFSP mount options are in `crates/studiofs-winfsp/src/lib.rs`;
callbacks are in `crates/studiofs-winfsp/src/context.rs`; native notification
delivery is in `context/invalidation.rs`. The existing integration fixture in
`crates/studiofs-winfsp/tests/mount_sanity.rs` creates an isolated local redb VFS,
starts a real WinFSP drive and shuts it down with a named event. Shared
`KernelInvalidator` is in `crates/studiofs-vfs/src/vfs/namespace.rs`.

## Surprises & Discoveries

FileInfoTimeout already defaults to all ones, directory timeout to 1000 ms,
and kernel-mode open is disabled. Existing logs only count successful opens
and directory-buffer population, so they cannot supply exact requested counts.
The current WinFSP invalidator inherits a no-op entry method. Queue completion
does not prove the full future contract, particularly for skipped native paths.

## Decision log

Use trace-based entry observation instead of broadening shared VFS metrics:
the task needs an auditable baseline, not a new production metrics subsystem.
Use the existing local native fixture to isolate OS metadata behavior from
remote services. This excludes replication acceptance and must be stated.
Document future health semantics without implementing SFS-676 through SFS-678.

## Idempotence and recovery

Use fresh fixture directories under `target`, never an existing user volume.
Refuse a drive already in use. Retain measurement output under `target/perf`
and the durable result summary in docs; fixture teardown removes its temporary
metadata/cache. On failure inspect mount cleanup before rerunning. Do not
delete mounted roots or conceal a failed promotion attempt with a reset.

## Interfaces and dependencies

No new domain interface is implemented here. The shared document specifies
future semantic intents and capability/coverage requirements. Existing tracing
and the native test fixture supply observation. Windows-only additions must
remain target gated. macOS and Linux policy stay unchanged.

## Outcomes & Retrospective

Shared contract, source baseline, precise callback instrumentation and repeatable
native measurements are complete. Review corrected the existing-open-handle
version exception and documented both non-ignored and ignored full suites.
The native test and focused clippy passed. Full-suite acceptance remains with
the operator; SFS-675 must not be marked fully accepted without that evidence.

The baseline guard reads the existing parsed `.env` fallback before checking the
opt-in, without mutating the process environment. This fixes runs where `.env`
contains the required quoted values but the process environment has not been
populated, while avoiding enabling sibling ignored tests concurrently. Missing
opt-in or mount point is a safe skip consistent with the other ignored WinFSP
tests. The final exact ignored command completed `14 passed; 0 failed; 11
filtered out`; a prior attempt that globally loaded `.env` enabled a sibling
callback smoke and exposed a drive-sharing failure, which the fixture isolation
removed.

The latest supplied CSV is `target/perf/sfs-675-metadata-1788617449200-47924.csv`.
Repeated stat and open each produced 1000 open callbacks per 1000 operations;
missing probes stopped in security-by-name, and enumeration produced 1000
directory callbacks. Deferred close crosses timing windows. Timing includes
correctness checks, so this is a workload baseline rather than callback latency.
The supplied rows did not include a new executable hash or host transcript, so
that identity remains tied to the earlier recorded run until matching metadata
is attached.
