# Return local disk-full errors to filesystem clients

This living ExecPlan follows `.agent/PLANS.md`.

## Purpose / Big Picture

Applications must receive a disk-full response when StudioFS exhausts local payload capacity or the operating system rejects local storage writes. The platform-neutral VFS category will be `StorageFull`, translated to POSIX `ENOSPC` and WinFSP `STATUS_DISK_FULL`. Other errors retain their existing categories and diagnostic sources.

## Surprises & Discoveries

The persistent local backend wraps `FilePayloadStoreError::Io` inside `LocalPayloadBackendError::Other`, retaining the original I/O error through `Error::source`. Matching only the direct `Io` variant would miss real local writes.

VFS writer materializers also turn `WriterStackError` into strings, and sticky writer rejection stores only a string. Strict flush/fsync retries pending materialization and receives a fresh typed error, but subsequent writes require the retained sticky cause. The writer regression failed exactly at the sticky source-chain assertion.

The first real-backend regression setup did not exhaust storage because explicit default VFS dirty-buffer overrides enlarged the derived backend budget. Setting the raw configuration's dirty-byte and eager-flush limits to one block established the intended failing boundary; the corrected test then failed on GenericFailure versus StorageFull.

The attached-review red run selected one legacy retry test and failed its wrapped generic I/O assertion. The disk-full filter selected eight tests and failed three: direct kind mapping, object/fetch semantic precedence, and the missing finish-operation label. The object-ID prefetch count can currently fail only for arithmetic overflow; preserving its typed writer error is still required for consistent diagnostics, without adding a fault hook for an impossible capacity path.

The later local review report compares both stale local `main` and `origin/main`; its `SliceRange` recommendations concern already-merged PR #732. Its proposed writer input-error mapping is not a regression fix: those errors previously became `GenericFailure`. Redb metadata causes are converted to `MetaError::Storage(String)` before the bridge, and quota errors currently retain their existing fallback classification.

## Decision Log

Use the existing shared bridge classifier and inspect retained sources for storage-full errors. This keeps the original error objects and avoids changing unrelated backend errors from their existing critical-runtime category. Date/author: 2026-10-01, Codex.

Preserve typed writer causes at the existing VFS I/O boundary and share sticky causes rather than changing durability, staging retries, or callback sequencing. This is required for real payload failures to reach the classifier. Date/author: 2026-10-01, Codex.

Apply review simplifications that preserve diagnostics: use standard successor iteration for source chains, keep the sticky message and source in one optional record, and use one writer-to-VFS conversion at all seven call sites. Adapter tests use public VFS I/O errors; the shared classifier tests retain local capacity and payload-store coverage, removing the two adapter cache dev-dependencies. Keep the explicit capacity arm for an exhaustive, semantically correct local-error match. Leave `SliceRange` unchanged: Serde `try_from` validates deserialization only, while its existing contract and tests also require rejection of invalid public-field values during serialization. Date/author: 2026-10-01, Codex.

Attached review identifies three omitted details in the earlier simplification: the existing transient backend must still inject its wrapped generic I/O failure, the object-ID prefetch path must retain its typed writer error, and operation labels must remain in diagnostics. Replace the context-free conversion with one context-preserving writer conversion beside `WriterStackError`, used at all eight operation boundaries. Restrict storage-full source inspection to local I/O, local payload, and upload-stage I/O variants so nested object/fetch causes do not override their established semantic categories. Date/author: 2026-10-01, Codex.

Accept the local report's documentation clarification for metadata and quota boundaries. Preserve existing writer errno policy; do not fold POSIX quota exhaustion into `ENOSPC`, expose internal writer types, truncate valid source chains at an arbitrary depth, or expand the already-merged `SliceRange` API without a consumer need. These proposals are separate policy work or cosmetic changes, not required disk-full corrections. Date/author: 2026-10-01, Codex.
