# Move tracked files and directories into the local scratch layer

## Purpose

A user can rename a tracked file or directory into a scratch directory and still read it through the same local inode. Peers see the old tracked name removed. If any required payload is missing locally, the rename returns EXDEV before changing the namespace, allowing the application to copy and delete.

## Surprises & Discoveries

The tracked rename path in `crates/studiofs-vfs/src/vfs/namespace_ops.rs` already distinguishes a scratch destination parent and returns CrossDevice. Promotion uses per-file Restore sessions before its redb transaction. A tracked unlink has special handling for unpublished files and published base slices, so plain removal events alone cannot establish the required peer behavior.

## Decision Log

Reuse the configured promotion entry limit for the demotion subtree. A destination name that matches a scratch rule under a tracked parent continues through tracked rename. Route by destination parent identity. Stage durable local-only copies under fresh payload IDs to keep scratch bytes independent from tracked pending-upload cancellation, eviction, and eventual remote object reclamation. Keep the inode and cancel each original pending upload by its current queue identity.
