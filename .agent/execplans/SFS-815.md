## Surprises & Discoveries

The adapter currently receives but ignores the flag. Redb already owns the required serialization: its write transaction reads the destination before removing either entry. VFS also has special handling for filtered macOS metadata and destructive trash renames; these paths need explicit consideration so no-replace cannot silently delete a source.

## Decision Log

Keep existing `rename` and `rename_atomic` APIs as replacement-enabled wrappers. Add explicitly required metadata `rename_atomic_with_replace` so an implementation cannot accidentally ignore no-replace. Return `EntryExists` from the destination lookup inside the same write transaction before any namespace change. This reuses the existing transaction and error mapping without new locks or dependencies. Date/author: 2026-10-07, Codex.

## Outcomes & Retrospective

The callback now honors the flag through the local transaction. Focused tests prove collision preservation, ordinary replacement, hardlink collision, and two concurrency boundaries. Independent review approved the final implementation. Live mount acceptance is separate from callback/unit tests and was not run; full suites are reserved for the operator. Filtered and trash no-replace requests explicitly fail safely rather than use destructive nontransactional behavior.

## Context and Orientation

`crates/studiofs-winfsp/src/context.rs` translates the Windows callback to the platform-neutral VFS. `crates/studiofs-vfs/src/vfs/namespace_ops.rs` owns rename authorization, local namespace invalidation and cleanup. `crates/studiofs-vfs/src/runtime.rs` forwards metadata methods. `crates/studiofs-meta/src/engine.rs` declares `MetaFsOps`; Redb implements local transactions in `redb_engine/fs_ops.rs`, Pg forwards local mutations in `pg_engine/local_traits.rs`, and `read_only.rs` rejects mutations. Redb is the local foreground authority; PostgreSQL replication remains asynchronous. A name collision is represented by `MetaError::EntryExists`, mapped by WinFSP to `STATUS_OBJECT_NAME_COLLISION`.

## Interfaces and Dependencies

Add `MetaFsOps::rename_atomic_with_replace(parent, name, new_parent, new_name, replace_if_exists) -> MetaResult<RenameAtomicResult>` and `StudioVfs::rename_with_replace` with matching namespace arguments returning `VfsResult<()>`. Existing wrappers pass true. Use the existing Redb transaction, typed collision error, and WinFSP error mapping; no new dependency.

Filtered metadata and trash paths are deliberately rejected in no-replace mode: existing destinations return collision, absent destinations return Unsupported. These paths delete rather than perform a metadata-backed rename, so claiming atomic no-replace success would risk source loss. WinFSP maps Unsupported to `STATUS_NOT_SUPPORTED`. Replacement-enabled behavior is unchanged. This explicit boundary avoids a new cross-registry locking protocol. Date/author: 2026-10-07, Codex.

The VFS race test pauses immediately before metadata mutation and waits with a bounded channel for another thread to create the destination. Redb competition tests associate each result with its source inode, avoiding receive-order assumptions.
