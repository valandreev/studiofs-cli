# SFS-928 generic/011 dirstress cleanup leaves nonempty directories

This living plan follows `.agent/PLANS.md`.

## Purpose / Big Picture

xfstests generic/011 runs `dirstress` (create, mkdir, symlink, rename, unlink,
rmdir under several processes) and then removes the whole tree. On the Linux
FUSE mount the final `rm -rf` reported `Directory not empty` for every
`stress.N` directory, and occasionally a dirstress phase failed with
`Cannot chdir out of working directory: No such file or directory`. After this
change the stress tree is removable, directory link counts stay correct, and
generic/011 matches its upstream output.

## Surprises & Discoveries

- The metadata DB is `<client>/meta/<volume>/<volume>.db`; `cache/.../cache.redb` is the payload cache index.
- `readdir`/`lookup` hide base entries whose regular-file inode is not remotely visible, while `has_entries_merged_in_write_txn` (the rmdir emptiness check) does not filter. A dentry pointing at a missing inode therefore blocks `rmdir` without appearing in listings or fsck's namespace scan.
- Empty regular files ("drafts": `InodeAttr::is_unpublished_empty_draft`) stay out of PostgreSQL: their `AddEntry`/`SetAttr` are projected away and their unlink only journals `RemoveRegularFileGraph` + `RemoveAttr`. Their `RenameEntry` was still projected, so PostgreSQL gained a binding that the later unlink never removed, and self replay brought it back into the local base and serving tables.
- generic/001 fails on this host with both main (`186b1060…`) and the fix (`f4baf12f…`), four of four runs each on fresh volumes. It is not caused by this change.
- A separate orphan pattern remains in the dumps: an empty draft created at a name that an older published rename vacated can lose its dentry when that older self batch replays (completed local-only windows are excluded from the SFS-927 rebase suffix). It does not affect generic/011 cleanup and is left for a follow-up.

## Decision Log

- Decision: Fix the parent `nlink` in `rename_atomic` and carry the parent attribute in `RenameEntry.new_parent_attr`.
  Rationale: The displaced directory's ".." link goes with it; peers already apply `new_parent_attr` verbatim.
  Date/Author: 2026-10-31 / Claude Opus 5.5.
- Decision: Keep an empty draft's rename out of PostgreSQL instead of making its unlink publish `RemoveEntry`.
  Rationale: It matches the existing contract that drafts never reach PostgreSQL and needs no new remote work for canceled drafts. The projected batch must map one local event to at most one remote event (`matching_local_prefix`), so `rename_atomic` journals a replaced file's `RemoveEntry` and attribute change before a draft's `RenameEntry`, which then carries no displacement and can be hidden.
  Date/Author: 2026-10-31 / Claude Opus 5.5.
- Decision: Identify a draft rename by the `SetAttr` that `rename_atomic` appends right after it, plus the window's hidden status.
  Rationale: Hiding renames of every hidden inode also hid written-but-unuploaded files and changed generic/001 behavior; the draft test is the narrow condition the bug needs.
  Date/Author: 2026-10-31 / Claude Opus 5.5.
- Decision: Answer `GETATTR` for a removed directory the kernel still references by lookup from a snapshot taken at `rmdir`, until FORGET.
  Rationale: Local filesystems keep a removed working directory stat-able with `nlink = 0`; this extends the existing open-directory snapshot to lookup references only, so the open-handle behavior is unchanged.
  Date/Author: 2026-10-31 / Claude Opus 5.5.

## Outcomes & Retrospective

## Context and Orientation

`crates/studiofs-meta/src/redb_engine/fs_ops.rs` (`rename_atomic`, `append_unlink_events`) writes local metadata and journals replication events. `crates/studiofs-meta/src/pg_engine/remote_apply.rs` projects a local event window into the batch published to PostgreSQL; hidden regular files are those whose latest state in the window is an empty draft or an uncommitted, unready upload. `crates/studiofs-linux-fuse/src/open_directories.rs` keeps directory attributes the kernel can still ask for after removal; `low_level.rs` wires `rmdir` and FORGET to it.
