# Upgrade redb to 4.3.0 and preserve local storage contracts

This ExecPlan is a living document. Keep `Progress`, `Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` current, following `.agent/PLANS.md` from the repository root.

## Purpose / Big Picture

StudioFS keeps its serving metadata and persistent cache index in local redb files. After this change, builds use redb 4.3.0 and can reopen clean files written by the current redb 4.1.0 build while preserving StudioFS format version 5, local durability barriers, and existing compaction behavior. Focused tests over 4.1-created metadata and cache-index files make this observable.

## Surprises & Discoveries

- redb 4.2.0 reuses pages freed by a durable transaction on the next write when no reader or savepoint needs them. It also fixes cases where writes or `Database::compact()` grew the file or compaction stopped before shrinking it fully. Its `Database::compact()` distinguishes persistent and ephemeral savepoint errors from `TransactionInProgress`.
- redb 4.3.0 adds optional key separators. Byte-slice, string, and related variable-width keys store shorter separators; StudioFS uses `&[u8]` keys in metadata dentries and `&str` keys in the cache counters. Compatibility fixtures must contain real rows in those tables.
- StudioFS calls `Database::compact()` once from `RedbMetaEngine::compact_local_storage`; it already maps `TransactionInProgress` to `SkippedBusy` and propagates other errors. Keep this behavior and do not add a GC schedule or retry loop in SFS-731.
- `RedbMetaEngine::open()` uses `Database::create()` and initializes missing tables; the read-only format probe uses `ReadOnlyDatabase::open()`. Both paths need to remain covered without changing StudioFS format version 5.

## Context and Orientation

The workspace dependency is declared in `Cargo.toml` and resolved in `Cargo.lock`. `crates/studiofs-meta/src/redb_engine.rs` opens the foreground metadata database; its `layout.rs` defines the StudioFS tables, and its `format.rs` reads the persisted format record. `crates/studiofs-meta/src/redb_engine/gc.rs` delegates one local compaction call to redb. `crates/studiofs-cache/src/payload_index.rs` opens `cache.redb`, stores cache lifecycle rows, and tracks its own index format version. Both crates are used by the same workspace and must continue opening their existing files.

`Durability::None` is StudioFS's relaxed write mode. It remains bounded by periodic and explicit `Durability::Immediate` barriers, including the close-preparation path. redb's storage file version and StudioFS's metadata format version are separate: this upgrade must not bump StudioFS format version 5.

No redb-specific ADR exists in `docs/adr`; the applicable storage boundaries are documented in `docs/metadata.md`, `docs/cache.md`, `docs/architecture.md`, and the local-first contract.

## Idempotence and Recovery

The tests copy fixtures into isolated temporary directories and never open user metadata or cache files. Fixture generation occurs only before the dependency update, while the lockfile selects redb 4.1.0. The dependency update is reversible by restoring the two task-owned manifest/lockfile entries. No StudioFS database migration or destructive storage operation is part of this work.

## Artifacts and Notes

The compatibility fixtures are intentionally created by redb 4.1.0 and opened by tests compiled against the upgraded redb. The metadata fixture contains a StudioFS root, format record, and dentry row, so the test covers both string and byte-slice key encoding. The cache fixture contains a persisted payload row and index counters.

Upstream changes relied on here: redb 4.2.0 reuses newly freed pages earlier, fixes file growth and incomplete shrink during compaction, makes non-durable commits faster, and reports savepoint-blocked compaction with dedicated error variants. redb 4.3.0 optimizes separators for variable-width keys and fixes recovery, iterator, and transaction-poisoning correctness bugs. The API signatures StudioFS uses for `Database::create`, `ReadOnlyDatabase::open`, `Durability::{None, Immediate}`, transactions, and `Database::compact()` remain available; this upgrade must compile and exercise the existing call sites.
