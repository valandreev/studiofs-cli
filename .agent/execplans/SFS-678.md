# Adaptive Windows metadata caching with WinFSP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Enable a Windows-only adaptive WinFSP metadata-cache policy that keeps stable read-only metadata in the Windows cache longer after coherence becomes safe, while automatically falling back to conservative admission when SFS-677 reports an unsafe coherence state.

**Architecture:** Keep the shared `studiofs-vfs::coherence` health state and semantic invalidation contract unchanged. Add a small WinFSP adapter policy module that owns mount-time timeout defaults and the `adaptive`/`conservative` experiment switch; use the existing VFS health gate for per-open admission and existing purge/invalidation paths for revocation. Mount-time WinFSP settings are immutable, so the implementation must not claim to change `VolumeParams` live; runtime adaptation is implemented through health-gated `DisableCache` admission plus invalidation.

**Tech Stack:** Rust 2024, Cargo, `studiofs-vfs`, `studiofs-winfsp`, WinFSP 0.12 bindings, serde diagnostics, focused Windows unit tests.

## Surprises & Discoveries

- `FileInfoTimeout`, `DirInfoTimeout`, and related WinFSP timeouts are mount-time `VolumeParams`; WinFSP does not expose a proven live timeout switch through the current Rust adapter. Runtime fallback must therefore revoke future admission with `DisableCache` and purge already admitted state on the first unsafe transition.
- SFS-677 already performs the required conservative VFS retirement and exposes `coherence_allows_os_cache()`. Duplicating health tracking in WinFSP would create two authorities and could let the adapter disagree with the VFS.
- The baseline uses `FileInfoTimeout=u32::MAX`, `DirInfoTimeout=1000 ms`, and `VolumeInfoTimeout=1000 ms`. The adaptive candidate will preserve the cache-manager file-info fast path and make directory/name-related metadata explicitly longer-lived, while the conservative mode will use zero metadata timeouts and disable read-only cache admission.
- WinFSP-rs exposes `security_timeout`, `stream_info_timeout`, and `extended_attribute_timeout`; these must be set explicitly so the adaptive policy does not accidentally inherit an unrelated `FileInfoTimeout` value for name/security lookups.

## Decision Log

- Decision: Keep the shared health state in `studiofs-vfs` and add only a Windows adapter policy seam.
  Rationale: SFS-677 already owns mount-local safety and cache retirement; SFS-678 must not create a second health authority or alter macOS/Linux behavior.
  Date/Author: 2026-09-06 / Codex.
- Decision: Default the Windows mount policy to `adaptive`, with `STUDIOFS_WINFSP_METADATA_CACHE_POLICY=conservative` as an explicit rollback/benchmark control. Unknown values fail safe to `conservative` and emit a warning.
  Rationale: SFS-678 must exercise the new Windows policy, while SFS-680 needs a repeatable current-policy comparison and a safe NO-GO fallback.
  Date/Author: 2026-09-06 / Codex.
- Decision: Use `FileInfoTimeout=u32::MAX` and 60 seconds for directory, volume, security, stream, and extended-attribute metadata in adaptive mode; use zero for those metadata timeouts in conservative mode.
  Rationale: `u32::MAX` is the documented WinFSP cache-manager enablement value, 60 seconds is materially longer than the 1-second baseline while remaining bounded, and zero prevents new metadata retention when the explicit rollback is selected. Existing invalidation/purge remains the correctness mechanism.
  Date/Author: 2026-09-06 / Codex.
- Decision: Preserve all existing per-timeout environment overrides.
  Rationale: They are already used by the baseline and are needed for controlled benchmark comparisons; the policy default supplies the fallback only when no override is present.
  Date/Author: 2026-09-06 / Codex.
- Decision: Keep write-capable cache bypass unconditional and gate only read-only metadata admission.
  Rationale: SFS-676/SFS-677 and the existing WinFSP writeback regressions require write-capable handles to remain outside cache-manager writeback regardless of health.
  Date/Author: 2026-09-06 / Codex.

## Context and Orientation

`crates/studiofs-vfs/src/coherence.rs` defines `CoherenceHealthState` and the
`CoherenceHealthTracker`; `StudioVfs::coherence_allows_os_cache()` is true only
after an applied boundary and complete invalidation coverage make the mount
`Healthy`. `crates/studiofs-vfs/src/vfs/workers.rs` retires untrusted VFS and
known WinFSP cache state when health becomes unsafe, preserving dirty writer
state.

`crates/studiofs-winfsp/src/lib.rs` parses `STUDIOFS_WINFSP_*` mount options,
sets WinFSP `VolumeParams` before creating the host, and starts the WinFSP
timer. `crates/studiofs-winfsp/src/context.rs` decides the per-handle
`Create.Opened.DisableCache` bit. `context/invalidation.rs` translates the
platform-neutral invalidation journal into bounded WinFSP notifications and
reports queue/submission/failure diagnostics. `VfsWritePathObservabilitySnapshot`
and the canonical `coherence` diagnostics already expose cache admission and
invalidation health; this plan does not add a duplicate metrics authority.

The current baseline is recorded in `docs/perf/sfs-675-windows-metadata-baseline.md`.
Its historical values must remain unchanged. The shared semantic contract is
`docs/metadata-cache-coherence.md`, and operator-facing Windows environment
knobs are documented in `docs/configuration.md`.

## Plan of Work

First create `crates/studiofs-winfsp/src/cache_policy.rs` with the small
`WinfspMetadataCachePolicy` enum and `WinfspCacheTimeouts` value object. The
enum parses an optional environment value, defaults to `Adaptive`, maps unknown
values to `Conservative` with a warning, is logged through mount diagnostics,
returns policy-specific timeout defaults, and answers whether a read-only
handle may retain OS cache state by requiring both `Adaptive` and
`StudioVfs::coherence_allows_os_cache()`.

Then extend `WinfspMountOptions` and `parse_mount_options` in `lib.rs` with the
policy plus explicit security, stream, and extended-attribute timeout fields.
Apply all six timeout setters (`file_info_timeout`, `dir_info_timeout`,
`volume_info_timeout`, `security_timeout`, `stream_info_timeout`, and
`extended_attribute_timeout`) before constructing the WinFSP host. Add
`new_with_cache_policy` constructors while preserving existing constructors
for tests and callers; production mount creation passes the parsed policy.

Next update `StudioFsContext` so its read-only admission checks use the policy
object and the existing VFS health gate. Write-capable and runtime-stat rules
remain unchanged. Add focused tests proving adaptive healthy read-only opens
retain cache, conservative policy disables them, unhealthy health disables
them, and write-capable opens remain disabled in adaptive mode.

Finally document the policy, defaults, rollback switch, timeout overrides,
negative/name invalidation behavior, and the limitation that mount-time
timeouts are not changed live. Keep the SFS-675 baseline document historical;
add the SFS-678 candidate settings to the shared coherence/configuration docs.

## Interfaces and Dependencies

The new internal interface is:

    pub(crate) enum WinfspMetadataCachePolicy {
        Conservative,
        Adaptive,
    }

    impl WinfspMetadataCachePolicy {
        pub(crate) fn parse(value: Option<&str>) -> Self;
        pub(crate) fn allows_read_only_admission(self, vfs: &StudioVfs) -> bool;
        pub(crate) fn timeouts(&self) -> WinfspCacheTimeouts;
    }

`WinfspMountOptions` carries the policy-derived timeout values into
`apply_volume_params`. `StudioFsContext` carries the selected policy into the
existing `should_disable_os_cache_for_handle` seam. No new dependency and no
macOS/Linux adapter change are allowed.
