# SFS-946 preserve completed local-only namespace state

This living ExecPlan follows `.agent/PLANS.md`. The task is Linear SFS-946.

## Purpose / Big Picture

A locally created empty file must survive replay of an older published rename
that vacated its name, even if its local journal window was marked completed.
PostgreSQL never publishes that hidden draft, so completion cannot erase its
local namespace authority while an older publication pins the journal cursor.

## Surprises & Discoveries

The current flusher already retains windows whose projection requires local
serving replay. Explicit completion still reproduces the reported loss. Existing
completed create/delete tests require that canceled names stop blocking peers.
The exclusion list is shared by conflict detection and serving restoration;
changing it globally would broaden the behavior unnecessarily.
The first implementation passed 138 remote-apply tests but failed the existing
completed create/delete versus foreign-create test (78 backlog tests passed,
one failed). Replaying completed tombstones would erase the foreign binding.

## Decision Log

- Decision: Keep a separate in-memory set of locally completed ranges, and pass
  it only to namespace rebase alongside unreplayed publication prefixes.
  Rationale: Completion and publication are different facts. Existing conflict
  exclusions and publication scheduling should keep their current meaning.
  Date/Author: 2026-11-01 / Codex.
- Decision: Capture surviving bindings from completed local-only journal ranges
  before applying self batches, then restore those bindings during rebase.
  Rationale: Only live local bindings require preservation. Completed canceled
  creates and stale inode snapshots must not be replayed as new mutations.
  Date/Author: 2026-11-01 / Codex.

## Context and Orientation

`crates/studiofs-meta/src/pg_engine.rs` defines `LocalEventProgress`, the
in-memory ledger of half-open local journal ranges. `local_state.rs` completes
and trims those ranges while respecting rejected events and unapplied published
prefixes. `metadata_sync.rs` constructs the replay coordinator under the local
position and pending-state locks. `remote_apply.rs` applies remote batches and
reconstructs the final local namespace from the journal suffix. Its current
exclusions remove locally completed events along with published ones.

## Plan of Work

Extend the existing progress ledger with locally completed ranges excluding
already published intervals. Update the ledger only after successful durable
cursor persistence, and trim it on both completion and replay retirement. Pass
the ranges through the existing coordinator construction in metadata_sync.rs.
Capture their final namespace bindings before replay and retain only bindings
that still match the current serving namespace. Merge those live bindings into
the pending namespace reduction without replacing later pending bindings.
Keep the local cursor, publication scheduler and conflict exclusions unchanged.
