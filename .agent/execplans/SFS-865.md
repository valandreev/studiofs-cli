# SFS-865: Bound pending-upload scheduling

## Purpose / Big Picture

Keep uploader descriptor copies bounded as accepted upload backlogs grow. Accepted work remains owned by the cache pending index, and the worker refills a small scheduling window without another external wakeup. Preserve retries, deletion cancellation and local-first foreground behavior.

## Decision Log

Review follow-up: findings 1 and 4 identify real admission regressions. Select only due operations (or tombstoned inodes for immediate cancellation) from the authoritative queue, rotate admission across inodes, and retain bounded descriptor copies. The worker waits for the earliest authoritative deadline when capacity is available, so future work needs no new channel wakeup. Keep delayed descriptors within the existing hard window as a clock-change safeguard. Normal ready refills continue directly to dispatch; cancellation-only pages still yield. Finding 2's proposed condition is not used verbatim because it could enter a blocking select with newly ready work. Finding 3 has no demonstrated lost-work consequence; empty cursor cleanup belongs with the revised dirty index. Finding 5 is conservative accounting of owned JoinSet entries, not a proven correctness defect; reaping before refill is a harmless precision improvement, not an atomic running-task count. Update docs after behavior is verified. Historical memory measurements below remain pinned to 341a9025 and do not measure this follow-up. Date: 2026-10-17.

Use a maximum-items argument at the cache claim boundary. Retain unclaimed dirty identities in the authoritative index. Limit queued plus active descriptors to twice the effective upload worker count, using the existing worker configuration and no new option. Refill after dispatch and completion, yielding between pages to keep cancellation-only backlogs cooperative. Date: 2026-10-17.

Use a rotating claim cursor with a frozen upper object ID for each sweep rather than always selecting the smallest dirty object ID: repeatedly requeued low IDs must not monopolize the bounded window, and continuous newer arrivals must not prevent returning to older retries. Date: 2026-10-17.

## Context and Orientation

crates/studiofs-cache/src/upload_queue.rs owns accepted operations and their dirty identity set. crates/studiofs-cache/src/cached_store.rs exposes claim_pending_uploads and manages pins/accounting. crates/studiofs-vfs/src/vfs/upload_lifecycle/worker.rs copies claimed operations into ready or delayed queues and spawns upload tasks. A scheduling window is the combined number of those queued descriptors and active tasks. Wakeups are coalesced into a capacity-one channel, so remaining dirty work must not require one wakeup per page.

## Interfaces and Dependencies

UploadQueue::claim_pending(max_items, now_unix_ms, initial_delay_ms, canceled_inodes) returns at most max_items owned descriptors. CachedStore::claim_pending_uploads(max_items, initial_delay, canceled_inodes) supplies the current clock. Both layers expose next_pending_upload_deadline for the earliest unclaimed effective deadline; the worker consults it only with free scheduling capacity. The cancellation set is borrowed synchronously while claiming; queue code does not call back into VFS or await. Reuse standard collections, JoinSet and worker configuration. Add no dependency.
