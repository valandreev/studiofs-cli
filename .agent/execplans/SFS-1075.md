# Load and retain scratch classification rules

This living ExecPlan follows `.agent/PLANS.md` and builds on the rule engine in
`.agent/execplans/SFS-1074.md`.

## Purpose / Big Picture

A mount can read shared `.studiofsignore` files in a background worker and
classify a byte path against the last valid complete snapshot. A client that
already cached the rules can classify paths before contacting object storage.

## Surprises & Discoveries

The existing ignored-entry registry discards payloads. Sending a matching create
there would lose data. The repository at bd75a173 has the SFS-1074 classifier
and no scratch namespace storage. Cache upload ownership uses a set, while the
payload backend counts references independently and checks those references in
both ordinary and disk-pressure eviction.

Review found that local commits journal no invalidation batches; only
foreign apply, snapshots, and volume settings do. The first implementation
therefore missed local rename and unlink of a rule file, while it rescanned
the whole volume after every flush of any dirty file and every foreign batch.

## Decision Log

The VFS owns independent backend pins so upload completion cannot release
them. It consumes notifications from the shared local durability barrier and
the post-commit metadata invalidation worker. Notifications coalesce while the
worker refreshes. A directory walk handles subtree moves and exact path changes
without depending on the old dentry still being present.

Local writers pin before upload submission, when their bytes are still dirty.
Rename temporarily pins the source graph before metadata commit and releases
that reference after the namespace notification acquires the rule pin.
Committed foreign invalidations pin referenced IDs before rule prefetch. A
scan only removes obsolete pins when no newer pin request raced its inventory.
VFS construction resolves persisted rule paths in local metadata and restores
their pins without reading remote payloads. Paths absent from the persisted
snapshot are discovered by the worker.

Review decision (f1c90d3a): a scan retains only rule files within
`MAX_RULE_BYTES`; an oversized file is never loaded, so a large file named
`.studiofsignore` must not escape eviction. Upload-path pins of such a file
are released by the next quiet scan. The rename-time graph read is best
effort and logs instead of failing the rename. Backend pins are reference
counted, so the temporary rename pin and the rule pin compose. The new pin
sites take the ignore-rule pin mutex and then backend stripe gates, after
watched-set and redb reads are released, as `lock_order.rs` documents.
Pins taken before the flush's metadata commit can be dropped by a scan that
ran in between; the upload queue holds the payload until upload completion,
which normally follows the barrier refresh that re-pins it.

The cache stores validated sources. Compiled matchers are reconstructed locally
during VFS construction. The worker persists a replacement snapshot in an
immediate redb transaction before publishing it in memory. Readers clone an
Arc under a read lock and classify outside the lock. A broadcast message carries
volume-relative paths after publication.

Review decision: the worker records each discovered rule file and every
directory on its path in a watched set, before reading the file's
attributes. A local barrier refreshes only for a watched file. A local
namespace change, recorded by `NamespaceMutationOps`, or a foreign Entry
intent refreshes when its name folds to `.studiofsignore` (and starts
watching that inode) or when it moves a watched file or directory. Content
and attribute intents refresh only for watched files, since every dentry
change also touches its parent's attributes. A Reset refreshes. The worker
starts after startup compaction, whose `try_write` on the database lock a
concurrent scan would make skip. A directory removed mid-scan is skipped
instead of failing the whole pass. Durations are named constants.

PR review decision (a80d45d5): the watched set is no longer grow-only.
Rename passed the old `.studiofsignore` name as a binding, so a rule file
renamed away stayed watched and was re-pinned; its later flushes requested
rescans and gained rule pins. Namespace notes now say whether they bind or
unbind a name. Unbinding a rule file name still requests a refresh, which
recompiles the directory, but stops watching the inode; only a binding pins.
A completed, uncancelled scan keeps the rule files and directories it found
plus rule files bound since it began, so unlinked, foreign-removed, and
hard-link-elsewhere cases converge on the next scan. Foreign Entry intents
carry the pre-mutation inode, so they still watch conservatively until that
scan. The pin revision now changes only when a pin is added, because a
repeated pin cannot race a scan's inventory and previously deferred the
release of superseded payloads.

PR review decision (CI): `deferred_namespace_drain_commits_queued_operations_in_one_batch`
counted nine engine commits instead of eight on this branch and passed on
main (bd75a173). The extra commit is the worker's one-time first-mount
persistence of the rule inventory (`store_ignore_rules_cache` with no cached
row), which landed after `start()` returned and inside the test's window. The
deferred drain itself still commits in one batch and adds no rule
transaction for non-rule names. The mount waits for this bootstrap before
serving, so the started test helpers now do the same; the assertion is
unchanged. Persisting the empty inventory is kept so later mounts of a
volume without rule files skip the bootstrap wait.

## Context and Orientation

`crates/studiofs-vfs/src/vfs/ignore_rules.rs` discovers rule files using the
local metadata view, reads payloads with a shared three-second deadline, and
retries missing payloads. The mount command waits at most five seconds for
discovery, prefetch, and persistence on a first mount. The payload timeout
warning includes known missing directories. Discovery can exceed the mount
budget before missing directories are known.

`crates/studiofs-meta/src/redb_engine/layout.rs` declares the local-only
`ignore_rules_cache` table. Its writer opens only that table and commits
without emitting a metadata event. The PostgreSQL engine delegates to its local
redb and the snapshot export has no reference to this table.

## Plan of Work

Reuse the SFS-1074 parser. Preserve a directory's last valid rules when payload
loading or compilation fails. Remove cached rules when the directory no longer
has a rule file. Refresh on local barriers and committed invalidations. Keep
the background task with the VFS shutdown-owned cleanup tasks.

## Idempotence and Recovery

A retry rereads the local graph and compares each directory's inode, size,
content epoch, and object usage. The object comparison catches same-size
rewrites within one unpublished content epoch. A failed cache transaction leaves the previously published
snapshot active. A database without the optional cache table starts with the
built-in rules and runs first-mount prefetch.

## Artifacts and Notes

The immediate transaction uses the existing redb durability policy for writes
that must be visible after reopening. The local rule cache is reconstructible
from shared rule files.

## Interfaces and Dependencies

`StudioVfs::classify_scratch_path` takes canonical volume-relative bytes.
`StudioVfs::subscribe_ignore_rules_changes` returns a Tokio broadcast receiver
of affected paths. The empty byte path identifies the volume root. There are
no new dependencies.
