# SFS-787: Fetch authenticated SFEC frames for small cold reads

This living ExecPlan follows `.agent/PLANS.md`.

## Purpose / Big Picture

Small cold random reads should transfer only the encrypted header and required authenticated frames instead of a whole 4 MiB payload. SFEC is the encrypted envelope; its independent frames each carry an authentication tag. STFS is the plaintext object containing a 30-byte header and payload. Full reads and prefetch keep the existing checksum validation and complete cache population.

## Surprises & Discoveries

SFEC frames are 1 MiB. STFS uses a whole-payload XXH64 checksum, which cannot be recomputed from a partial read. Partial reads must authenticate every returned frame and the STFS header, validate declared sizes, and avoid complete-cache insertion. Complete reads retain XXH64 checks. ## Decision Log

Use the existing format, crypto CPU admission, request timeout, AIMD concurrency and retry loop. Limit the new foreground choice to small single-fragment reads; keep full paths for larger/sequential-window requests and prefetch. Partial bytes are never published into the whole-object cache or its singleflight broadcast. No new dependency or user setting is needed.

Final VFS review noted that a small random request spanning two logical blocks could bypass the old eager complete fetch. Preserve that path with `blocks_needed.len() == 1`; the public-read regression now checks both a middle range and a small crossing-block request.

Review follow-up retains `copy_partial_committed_payload_into` and its short-payload regression: a bare `copy_from_slice` would panic instead of returning the required corruption error. Shared decryption retains full-read worker admission and absolute frame indices for partial-read authentication. A parsed prefix holds validated fixed fields instead of constructing a dummy header.

The written review's proposed roughly 2 MiB reservation is not a safe universal bound: a partial span can cover two target frames plus frame zero, with additional decryption buffers. Reserve one existing cloud-fragment budget regardless of total key count; preserve the insufficient-budget error instead of clipping the reservation to the budget. Current production blocks have one fragment, so this does not lower their 4 MiB reservation. A 512-byte header probe was tested and rejected: OpenDAL 0.55 bounded ranges extending past EOF break short objects (Memory panics). An extra stat would retain the RTT overhead. Preserve the exact fixed-prefix/tail reads; variable-length fields also rule out assuming a strict 128-byte header.

Third review: `RandomInteractiveRead` is the default class of a fresh stream, so the first two reads of a cold sequential reader and repeated small reads of one hot block took the uncached partial path, adding transfer and RTTs over the main branch. Gate the partial path on `confirmed_seek`, set only when a read with stream history lands non-contiguously; every other read keeps complete fetch and cache population. The fixed SFEC prefix already determines all frame geometry, so the header tail and frame zero are read in one contiguous request, a target adjacent to frame zero is merged into it, and any other target is read concurrently: two sequential rounds instead of three or four, with exact ranges and no read past EOF. Bad caller ranges now return `DataError::InvalidRange` / `FetchError::InvalidRange`, are not retried, and the bridge classifies them as `InvalidInput`; envelope-derived bounds and remote-derived fragment problems stay corruption.
