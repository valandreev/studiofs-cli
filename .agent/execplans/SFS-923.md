# SFS-923 Linux FUSE inode ctime

This living ExecPlan follows `.agent/PLANS.md`.

## Purpose / Big Picture

Make Linux `stat` report a changed inode ctime after rename and link-count changes. The affected local operations are rename of a symlink, rename replacement of a multiply linked inode, and unlink of a multiply linked regular file.

## Surprises & Discoveries

- The baseline's three failures map to two shared metadata functions; ctime isn't advanced anywhere in rename and unlink link-count adjustments.

## Decision Log

- Decision: Update ctime on the affected inode in the existing atomic local metadata transaction and include the changed attrs in the event journal using the existing SetAttr event where needed.
  Rationale: This preserves local-first behavior and avoids a new wire-format field or another write transaction.
  Date/Author: 2026-10-30 / Codex.
