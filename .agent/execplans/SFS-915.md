## Surprises & Discoveries

Windows Git over the UNC checkout reports executable-bit changes in shell scripts; native WSL Git reports a clean tree. Use native WSL Git and Cargo for reliable repository state and Linux validation. WSL execution requires the sandbox escalation path in this desktop session.

The prior handoff distinguishes three defects. Commit `6e2ddd6f3` fixes stale-upload deletion by checking overlay object references without an epoch filter. Remaining evidence shows packed object fragments appearing after truncate deleted their payload, and stale bytes in a truncated tail after extension. The issue is accepted as real; no baseline reproduction is needed.

`trim_local_payload_staging` incorrectly skipped pending persisted slices whenever there was no mutable payload buffer to trim. A deterministic regression failed with two surviving slices, then passed after unconditional slice clipping, with persisted bytes reduced from nine to three.

Two state-ordering seams need regression proof. Upload reattachment performs separate attr/read-slice/write transactions without a file-session permit, permitting a rebased epoch to collide with a concurrent truncate epoch. Pressure-driven materialization also has callers that drop their write permit before materializing, or materialize other inodes without their session permits. The tracked background materializer and regular worker already hold the correct materialize permit. Overlay compaction itself reads and writes the current chunk within one redb transaction, ruling out a stale prepared compaction result on that path.

The first combined focused batch executed 77 selected tests: 75 passed, one ignored, and the existing global dirty-cap test failed. Nonblocking candidate acquisition can skip a background-busy inode, so inline opportunistic pressure must perform its remaining global drain after releasing its own write permit. This preserves backpressure without introducing nested inode waits. The standalone dirty-cap test had passed; the combined run exposed the missing contention behavior.

Independent review identified missing session-map cleanup after newly acquired permits. `FileSessionCleanup` owns the optional permit and the runtime state; it drops the permit before collecting the idle entry. Creating it before acquisition also covers a cancelled waiter, while moving it into upload reattachment's blocking closure covers a discarded or outliving job. New tests verify cleanup when a job never executes or an active operation is cancelled. The reviewer approved the corrected lifecycle.

The first mounted continuation gate stopped after run 02 despite both fsx summaries reporting success: retained-overlay relink and upload-stage linking reported missing local payloads. Truncate masked only the interval up to the old visible EOF, leaving stored packed fragments beyond it able to reappear after growth. The new regression reproduced the deleted-payload read before the correction. Truncate now masks the suffix in every actually stored base/overlay chunk before payload cleanup; enumeration avoids scanning distant sparse holes. Rollback restores the original hidden fragments, and existing shared-prefix coverage protects retained packed objects.

Gate `acceptance-20261028T175039Z` run 02 shows that a rare, timing-dependent loss remains under the kernel policy. Write 0x1045..0x116a was followed by MAPWRITE, TRUNCATE DOWN 0xe427->0x2227 (above the write) and COPY; a later read returned bytes from an older write. No relink, missing-payload or upload-stage warnings occurred, and the deterministic replay passes. None of the review fixes is on this path: fsx issued no same-size truncate, and opportunistic writes do not use the strict drain. Root cause is open.

## Context and Orientation

`crates/studiofs-vfs/src/vfs/upload_lifecycle/worker.rs` handles asynchronous payload uploads. `crates/studiofs-vfs/src/vfs/` contains size changes, local dirty metadata and the writer stack. Payload objects are immutable files; slices map file ranges to offsets within those objects. Packing lets several slices share one object, so deleting an object requires considering every live fragment. Truncate must also remove or clip pending slices, preventing a later metadata flush from restoring bytes beyond the new end.

Foreground operations use local redb metadata and cannot wait for remote publication. Follow `docs/juicefs-local-first-rust-contract.md`, `docs/architecture.md`, `docs/local-first-validation-matrix.md`, the VFS scoped contract, and relevant ADRs. Use the Codebase Memory graph for structural discovery and exact-path coverage checks, with direct reads for gaps.
