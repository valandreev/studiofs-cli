# Add local redb storage and compaction observability

This ExecPlan is a living record for SFS-732. Maintain `Progress`, `Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` according to `.agent/PLANS.md`.

## Purpose / Big Picture

After this change, an operator can read the existing `.studiofs-runtime-stats` file or run `studiofs perf` and see the physical size and redb page statistics for the local metadata database, the current retained local event sequence range, and whether metadata compaction has reduced the file. These values are labeled as metadata redb metrics so they cannot be mistaken for the separate cache index database. The same snapshot will show compaction attempts, outcomes, duration, and why the latest attempt skipped.

## Surprises & Discoveries

- Observation: `RedbMetaEngine::compact_local_storage` currently returns only `Compacted`, `SkippedBusy`, or `NoWork`; `PgMetaEngine` delegates that call to its local `RedbMetaEngine`.
  Evidence: `crates/studiofs-meta/src/redb_engine/gc.rs` and `crates/studiofs-meta/src/pg_engine/local_traits.rs`.
- Observation: the existing mounted runtime stats surface is a synthetic file and already feeds `studiofs perf`; its `metadata` section accepts bounded counters and gauges.
  Evidence: `crates/studiofs-vfs/src/vfs/runtime_stats_surface.rs`, `crates/studiofs-vfs/src/vfs/metrics.rs`, and `docs/perf/runtime-stats-schema.md`.
- Observation: redb 4.3 exposes allocated-page, stored-byte, metadata-byte, fragmentation, and page-size statistics through `WriteTransaction::stats()`, which walks table/page structures; it does not expose these values from a read transaction.
  Evidence: locked `redb-4.3.0/src/transactions.rs` and `src/tree_store/table_tree.rs`.
- Observation: the controlled 128-row delete changed `stored_bytes` and `fragmented_bytes`, but `fragmented_bytes` decreased in that workload.
  Evidence: focused test passed after asserting a change in the reported value instead of assuming its direction. Physical size was then compared before and after successful compaction.
- Observation: `RuntimeMetaHandle` did not forward `compact_local_storage`, so mounted startup compaction previously fell back to the trait's default `NoWork` result.
  Evidence: the new adapter regression failed with `compaction_attempts = 0` before the forwarding method was added, then passed with `compaction_attempts = 1`.
- Observation: `ReadOnlyMetaEngine` wraps metadata for immutable snapshot mounts and needs to forward the diagnostics method so the VFS still sees the local file and event sequence data.
  Evidence: `read_only_meta_forwards_local_storage_diagnostics` passed using an actual read-only redb handle.
- Observation: the independent review suspected an empty event log returned before assigning the sequence span. In Rust, `let Ok(first)` still matches `Ok(None)`; the implementation reports next sequence 1 and span 0.
  Evidence: `local_storage_diagnostics_report_empty_event_log_span` passed.

## Decision Log

- Decision: Keep runtime counters in memory and allow them to reset on mount. Rationale: SFS-732 says restart-safe counters are optional, and persistence would add writes to the storage being measured.
  Date/Author: 2026-09-26, Codex.
- Decision: Keep physical file-size lookup independent of the database lock. Collect redb page statistics only when `write_txn_lock.try_lock()` and the database `try_read()` both succeed, then use redb 4.3's `WriteTransaction::stats()` and abort the stats-only transaction. If either lock is busy, omit only those page metrics. Rationale: redb 4.3 has no stats method on a read transaction; the nonblocking gates avoid waiting for an existing metadata writer or the exclusive compaction lock. The built-in stats walks page/tree metadata, not user rows or values.
  Date/Author: 2026-09-26, Codex.
- Decision: Put metrics in the existing `metadata` section and prefix their names with `metadata_redb_`. Rationale: the section is already consumed by `.studiofs-runtime-stats` and `studiofs perf`, while the explicit prefix distinguishes this database from the cache redb index.
  Date/Author: 2026-09-26, Codex.
- Decision: Forward diagnostics through `ReadOnlyMetaEngine`, and forward compaction through `RuntimeMetaHandle`. Rationale: immutable snapshot mounts still need physical/event diagnostics, and the mounted startup compaction path otherwise silently used `MetaGc`'s default no-work implementation.
  Date/Author: 2026-09-26, Codex.
- Decision: Refresh redb page stats at most once per five seconds and hold the shared writer mutex for the `WriteTransaction::stats()` scan; return the prior sample when the writer/database gate is busy. Rationale: redb 4.3 exposes page stats only on a write transaction, so a single scan can serialize metadata commits; a bounded refresh interval limits repeated scan cost while preserving current writer synchronization. A concurrent diagnostics reader can omit page gauges while the cache mutex is held.
  Date/Author: 2026-09-26, Codex.

## Context and Orientation

`studiofs-meta` owns `RedbMetaEngine`, the foreground local serving database, `PgMetaEngine`, which wraps the local engine for PostgreSQL replication, and `ReadOnlyMetaEngine`, which wraps metadata for immutable snapshot mounts. `MetaGc::compact_local_storage` is the compaction boundary. The VFS stores a `RuntimeMetaHandle` in its synchronous metadata executor; this adapter must forward both compaction and diagnostics. The VFS serializes its point-in-time `RuntimeStatsSnapshot` to the synthetic `.studiofs-runtime-stats` file, which `studiofs perf` reads. The `metadata` section is numeric, so latest result and busy reasons use named 0/1 gauges. A gauge value of 1 means the named state matches the latest attempt; 0 means it does not. Missing redb page/event metrics mean a best-effort database read was unavailable. No user-row or payload scan is added.

## Plan of Work

First, extend the existing VFS stats-surface test so it expects a metadata redb physical-file gauge, page statistics, and compaction counters. Add a metadata-engine regression that creates temporary test-table data, checks stats and local event sequences, deletes the rows, takes diagnostics again, then runs explicit compaction and checks the recorded outcome, duration, and exact before/after physical sizes. A second test holds a read transaction through compaction to verify that a busy skip includes its typed reason.

Next, add a public `LocalStorageDiagnostics` value and a defaultable `MetaGc::local_storage_diagnostics` method in `crates/studiofs-meta/src/engine.rs`. `RedbMetaEngine` retains its database path, reads physical size with `std::fs::metadata`, and reads event sequences from one nonblocking read transaction. It calls `WriteTransaction::stats()` only when the existing metadata-writer mutex and database read lock can both be acquired without waiting, then aborts that stats-only transaction. The local event-log span is the end-exclusive next sequence minus the first retained sequence, or zero when the event table is empty. `PgMetaEngine`, snapshot `ReadOnlyMetaEngine`, and VFS `RuntimeMetaHandle` forward diagnostics to the local engine. `RuntimeMetaHandle` also forwards compaction so startup maintenance reaches the backend. Compaction records attempt/outcome counters, elapsed nanoseconds, a typed busy reason, and before/after physical bytes for successful compaction in a per-engine mutex; no diagnostic counter is persisted to redb.

Then, add the optional diagnostics to the existing `RuntimeStatsSnapshot.metadata` section in `crates/studiofs-vfs/src/vfs/runtime_stats_surface.rs`. The names will start with `metadata_redb_`; byte metrics use `bytes`, page/event counts use `count`, duration uses `ns`, and latest outcome/reason gauges are named boolean flags. Update `docs/perf/runtime-stats-schema.md` and the `RedbMetaEngine` section of `docs/metadata.md` with the new names, units, and meanings.

## Idempotence and Recovery

The regression uses the repository's temporary test directory and a test-only redb table; it never opens or edits a user's mounted metadata or cache database. Compaction is invoked only on that disposable test database. The metrics are read-only, in-memory counters and do not change the redb on-disk format or event-retention behavior.
