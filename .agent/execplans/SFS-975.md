# Classified retries, backoff and overload breaker for the CLI janitor

This living ExecPlan follows `.agent/PLANS.md`. It covers SFS-975 for `studiofs janitor <volume>` only; the mounted background janitor is unchanged.

## Purpose / Big Picture

Transient S3/PostgreSQL faults must not end a janitor run with lost work, and retries must not amplify load on a throttled provider. Operators get bounded, classified retries, an S3 request gate that slows down under throttling and recovers gradually, a cycle-level overload breaker, and a `--loop` breaker that backs off and eventually gives up instead of spinning.

## Surprises & Discoveries

- Observation: OpenDAL's `RetryLayer` calls `set_persistent()` on every error it returns, including permanent ones such as 403, so `is_permanent()` is always false afterwards.
  Evidence: `opendal-0.55.0/src/layers/retry.rs` maps every final error with `.map_err(|e| e.set_persistent())`; the red run of `s3_permission_denied_is_terminal_and_vanished_keys_are_not_failures` returned `PermissionDenied (persistent)` classified as transient.
- Observation: OpenDAL's S3 deleter treats a 404 DELETE as success, so a vanished object needs no special path on delete.
  Evidence: `src/services/s3/deleter.rs` maps `StatusCode::NOT_FOUND => Ok(())`.

## Decision Log

- Decision: Classify object errors by `ErrorKind` only; terminal = `PermissionDenied`, `ConfigInvalid`, `Unsupported`, directory kinds; `NotFound` = vanished; everything else transient.
  Rationale: The retry layer erases the temporary/permanent status (see Surprises). Unknown kinds are bounded by the overload breaker and the loop breaker, so treating them as transient cannot spin forever. Non-object errors without a typed cause (unordered listing, invalid checkpoint, mismatched queue key) stay terminal.
  Date/Author: 2026-11-09 / Claude.
- Decision: Adapt the request rate (AIMD-style: double spacing on 429/503/transport failure, shrink by 1/8 per other response) instead of resizing the in-flight limit.
  Rationale: The rate gate already serializes request starts; once spacing exceeds response latency the effective concurrency falls to one, so lowering the rate lowers both. It needs no new synchronization around OpenDAL's fixed concurrency semaphore.
  Date/Author: 2026-11-09 / Claude.
- Decision: Stop an object's remaining key deletes on the first failure.
  Rationale: The whole object is retried later under a new claim; issuing the remaining keys during a throttle only adds load.
  Date/Author: 2026-11-09 / Claude.
- Decision: PG policy — `BackendUnavailable` transient (cycle aborts, next cycle reconnects), `UnsafeToDelete` terminal, `StaleClaim` per object (row deferred, not counted toward the breaker).
  Rationale: Matches the existing fail-closed claim behavior; the advisory lock is session-scoped, so a lost connection cannot continue the cycle.
  Date/Author: 2026-11-09 / Claude.

## Outcomes & Retrospective

Implemented as planned. The overloaded or terminal stop paths reuse the existing checkpoint rollback, so unprocessed listed candidates replay and unacknowledged queue rows stay queued. Exit codes are not differentiated numerically; outcomes and error contexts (`terminal failure`, `transient failure`, `S3 overload circuit open`, `circuit open after N consecutive failed cycles`) are distinct. No live RustFS/PostgreSQL fault run was performed.

## Context and Orientation

`crates/studiofs-data/src/janitor.rs` builds the OpenDAL S3 operator with the SFS-974 rate gate and in-flight limit. `crates/studiofs/src/cli/janitor/pipeline.rs` runs one cycle: drain the PG GC queue, list objects, check eligibility, claim, delete canonical keys, finish the fenced claim, persist the checkpoint. `crates/studiofs/src/cli/janitor.rs` parses options and runs single or `--loop` cycles under the per-volume PG lock.

## Idempotence and Recovery

Only LIST, HEAD and DELETE are retried; all are idempotent. Retries stay inside the existing per-request deadlines (20 s DELETE), so every canonical key delete still fits the 60 s claim lease and no retry runs on an expired fence. A failed object is finished as `Retryable` and its queue row deferred before any stop.
