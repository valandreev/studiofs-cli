# SFS-782: reuse Linux reply attributes safely

Maintain this living ExecPlan according to `.agent/PLANS.md`.

## Purpose / Big Picture

Linux lookup and allocated open/create replies currently discard an available
attribute snapshot and call local getattr again. Reuse the snapshot when no
invalidation crossed its observation; otherwise retain the existing refresh.
Kernel replies must still receive a follow-up invalidation when a change crosses
their lookup reservation. Focused tests demonstrate fewer bridge getattr calls
and correct stale-size, rejection, and invalidation behavior.

## Surprises & Discoveries

Local setattr/unlink retire VFS attributes before native notifications are delivered.
An experimental Linux-only counter failed three stale-attribute regressions and
was removed. The existing VFS retirement map covers synchronous local changes
and bounded Reset invalidations; ordered stamps also avoid false refreshes from
parent-directory changes. Opening a newly created file synchronously retires its
initial incarnation snapshot, so ordinary allocated create keeps its protective
refresh. The stable create-response test isolates reply preparation using an
already persisted inode; a separate real-create test proves allocation retirement
forces refresh. An aged cache hit must retain its source deadline. The deadline
is retained only if the current cache entry equals the complete observed attrs;
missing/different entries conservatively force refresh. Codebase Memory is indexed
under `home-val-dev-studiofs-cli`, not the contract's older project key.

## Decision Log

Reuse the bounded VFS AttrReadCache retirement map. Stamp each retirement with
an increasing sequence, preserving existing equality comparisons. An opaque
AttributeObservation captures the reset epoch and sequence before the original
read. After reply liveness exists, validate the same reset epoch and that the
target inode's stamp is no newer. Reset the sequence with a new epoch on overflow.
Retain ReadOnly access/lifecycle/fence enforcement when approving reuse and
refresh synthetic high-range inodes and expired or uncached snapshots. Keep lookup reservations and follow-up
notifications unchanged. Truncating opens conservatively refresh their own
size change. An independent reviewer confirmed the token design and identified
the access, synthetic-inode, and source-expiry boundaries. No dependency or remote IO change.

## Validation and Acceptance

Stable replies must not call the bridge getattr helper again after the original
read. Required access/lifecycle checks remain in place and run before the final
observation check. A changed size before reservation must appear in the reply.
An invalidation crossing a pending reply must queue DATA after success, and
rejected replies must release lookup/handle resources. Local changes must invalidate observations before native notification delivery. Truncating
opens must prepare from the resulting size rather than the pre-open size.
