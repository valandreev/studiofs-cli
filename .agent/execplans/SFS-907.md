## Surprises & Discoveries

The sandbox hides `/dev/fuse` and denies sudo, but host execution exposes FUSE
and passwordless sudo. The host is devbench, Ubuntu Linux kernel 7.0.0-38-generic,
not WSL2. Never describe its measurements as WSL results.

The util-linux helper environment omits PATH; the daemon receives a fixed system
PATH and the readiness probe uses an absolute Python interpreter. StudioFS
appends the volume to mountpoint paths unless their basename already matches.
A narrow upstream patch normalizes `fuse.studiofs` to `fuse` for device-type
checks; the unpatched first smoke aborted before any test ran. Root-only smoke
can use target paths, but fsgqa cannot traverse mode-750 `/home/val`. User explicitly approved temporary `/srv/sfs907` mountpoints; home ACL
changes were rejected by automatic approval review and were not applied.

Pinned upstream `common/rc` already handles `_scratch_mkfs` for FUSE by mounting,
removing files and unmounting. It does not execute `mkfs.fuse.studiofs`. A real
reformat and geometry requests still cannot be supported by this adapter.

## Context and Orientation

`tools/posix-conformance/build-tools.sh` pins xfstests for its fsx utility, but
does not build the full suite. `docs/posix-conformance.md` contains SFS-906
and SFS-924 results. `crates/studiofs/src/cli/mount/mod.rs` exposes foreground,
read-only and allow-other options. The Linux adapter uses the volume as the
mount source and the `fuse.studiofs` filesystem type, so xfstests device strings
must be actual isolated volume names. PostgreSQL and S3 bootstrap mounts;
mounted metadata comes from local redb. No callback behavior changes here.

## Plan of Work

First build upstream with its standard make entry point and rebuild StudioFS.
Then add `tools/xfstests/mount.fuse.studiofs`, `local.config.example`, an exclusion
file with reasons, a per-test timeout runner, focused harness tests and README.
The helper only maps the two configured volume names and mountpoints, rejects
unsupported mount options, and records its process ID and non-secret options.
The runner retains one results directory per case, allowing restart after a
timeout. Finally extend `docs/posix-conformance.md` with exact environment,
counts, exclusions and classified failures. Product findings become linked
Linear issues, verified against existing findings before creating duplicates.

## Idempotence and Recovery

Never reuse the existing `test` volume. Do not destroy remote metadata or
payloads. After a timeout first try bounded umount/fusermount3, then lazily
detach only the configured task mount and terminate only its recorded daemon.
Keep logs and isolated client state for investigation. Each run gets a new
directory; resume only cases without recorded verdicts.
