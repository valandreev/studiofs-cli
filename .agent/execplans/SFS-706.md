# SFS-706: Mount fresh clients read-only until catch-up is live

## Purpose

Allow a valid local PostgreSQL metadata checkpoint to mount while remote
identity/catch-up work is unavailable, while preserving hard identity failures
and the existing dynamic VFS mutation gate.

## Surprises & Discoveries

- SFS-697 already provides the dynamic PostgreSQL lifecycle and mutation
  authority gate in VFS.
- The remaining SFS-706 mount blocker is the unconditional remote consistency
  check in the CLI mount admission path.
- General `check_consistency` callers include destroy and diagnostics, so a
  sticky startup shortcut there would weaken their remote probe contract.
- Startup schema validation already classifies transport and timeout failures;
  mount admission can reuse that known-unavailable state, while general
  consistency checks must still retry the remote identity probe.

## Decision Log

- Keep the change at the mount admission boundary; do not add a second VFS
  gate or an OS remount protocol.
- Read local format metadata first. For PostgreSQL, tolerate only
  `RemoteUnavailable` and `Timeout`; keep UUID mismatch and other errors fatal.
- Established and fresh-client lifecycle behavior remains owned by
  `PgMetaEngine` and observed dynamically by VFS.
- Track typed remote reachability failure in `PgMetaEngine`, skip duplicate
  mount-admission identity probes only after a known transport failure, and
  leave general validation responsible for retrying and clearing that state.
- Share the reachability classifier through `MetaError::is_reachability_error`.
  Successful remote probes clear the transport flag; reachability failures
  invalidate remote-format validation and set it.
- Keep `check_consistency` strict and expose the explicit
  `check_consistency_for_mount_admission` hook so only the CLI mount path gets
  the local-first shortcut.
- The review's proposed `lifecycle.allows_remote_sync()` gate was not applied:
  that API does not exist, and lifecycle state cannot distinguish transport
  failure from other degraded states.

## Outcomes & Retrospective

Implemented local-first PostgreSQL mount admission in
`crates/studiofs/src/cli/mount/session.rs`. A local format is now returned when
the PostgreSQL identity check has only a transport or timeout failure; UUID
mismatch and other consistency failures remain hard errors. Review follow-up
adds typed reachability state in `PgMetaEngine`, preserves the original error
as an `anyhow` cause, logs the warning cause, and covers non-Postgres rejection.
The second review also adds atomic flag transitions, the scoped admission hook,
a shared reachability classifier, and regression coverage for strict retry,
successful reconnect state, and the consistent metadata path.
