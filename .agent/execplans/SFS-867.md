# Restore periodic physical cache headroom protection

This living ExecPlan follows `.agent/PLANS.md`.

## Purpose / Big Picture

StudioFS must reclaim disposable downloaded payloads when other applications consume the filesystem hosting its cache, even below the configured cache budget. Aim for 10% available filesystem capacity without querying free space on foreground reads or writes. Never sacrifice dirty, pending, uploading, pinned or unpublished local data.

## Surprises & Discoveries

Existing candidate paging limits eligible results, not examined rows; a dirty-only index can require a full scan. Physical maintenance needs a separate bounded scan using the same index implementation. Existing background worker invokes `run_pressure_maintenance` from the upload statistics loop. The graph generation was 2026-10-18T10:04:24Z, with changed metadata; direct source reads verify the relevant paths.

Independent review found that GetDiskFreeSpaceExW's total can be quota-limited. Windows now resolves the canonical cache directory to its volume root and uses GetDiskSpaceInformationW: actual total capacity and the lesser of caller/actual available bytes. Unix statvfs does not guarantee user-quota reporting; that limitation is documented. Context7 confirmed libc fields; Microsoft primary documentation confirmed Windows layout and root-path requirements. A strengthened 40 MiB + 40 MiB regression failed when a pass removed 80 MiB, then passed after enforcing the cap before adding a second object. Index test cursors use authoritative access-order values rather than object IDs (sequences start at zero).

## Decision Log

Use the existing maintenance worker and eviction mutex, with a monotonic 30-second minimum interval between attempts, including failures. Enter pressure below 10%, recover toward 11% to reduce churn, and resample after successful removals. Bound each physical pass to 512 scanned rows, 128 deletions and approximately 64 MiB (a single larger object may exceed this byte bound); continue the scan cursor on subsequent intervals. Restrict physical eviction to downloaded, uploaded, unpinned entries: locally originated uploads can still await metadata publication. Preserve the independent configured-budget behavior. Report observed filesystem bytes separately from logical payload bytes removed. No new dependencies or configuration switches.

## Context and Orientation

`crates/studiofs-cache/src/runtime.rs` owns the local redb index, payload files, mutation gates and eviction mutex. `payload_index.rs` supplies authoritative lifecycle candidates in least-recently-used order. `payload_platform.rs` owns unsafe native operations. Add `disk_pressure.rs` as a runtime submodule to keep the policy cohesive. Existing redb locking prevents multiple live owners of one cache root; separate cache roots sharing a volume sample that volume independently. Removing index ownership does not guarantee immediate physical space release.

## Validation and Acceptance

Inject a sampler and monotonic time in tests. Below-budget cache must reclaim safe downloaded objects after external consumption; protected states survive. Repeated calls before the interval do not sample; foreground reads/writes do not sample. Verify failure cooldown, delayed release, external allocations, recovery hysteresis, separate roots on the same fake filesystem, and cursor progress past protected rows. Native Windows sampler tests use a disposable cache location. Mounted low-disk validation requires a disposable volume and rebuilt binary; do not fill a production volume. Linux/macOS native validation remains explicit if unavailable. Update the User Manual only after the required validation is established.

## Idempotence and Recovery

Only StudioFS-owned indexed payloads may be removed through the existing deletion-intent path. No cache wipe, raw volume filling, production volume mutation or external-storage probe is needed for deterministic policy tests. Sampling failure preserves payloads and waits for the next interval.
