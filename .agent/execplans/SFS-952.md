# SFS-952 Linux FUSE xattr ctime

This living ExecPlan follows `.agent/PLANS.md`.

## Purpose / Big Picture

Make Linux `stat` report a changed inode ctime after a successful `setxattr` or `removexattr` (xfstests generic/728).

## Surprises & Discoveries

- The setxattr step only appeared to pass: redb never advanced ctime for either mutation. The kernel updates its cached ctime locally after a successful xattr reply, and the next server getattr can overwrite it, so the observed pass/fail split was incidental.
- A `SetAttr` for a Ready regular file is classified as eager by `local_events_need_eager_flush`, so xattr writes on published files now flush to PostgreSQL immediately (as chmod already does). The PG xattr overlay-precedence test was moved to a directory inode to stay deterministic.

## Decision Log

- Decision: Touch ctime in the existing xattr write transaction and journal it with the existing `SetAttr` event, as in SFS-923.
  Rationale: Keeps local-first atomicity and replicates ctime without a new wire type.
  Date/Author: 2026-11-02 / Claude.
- Decision: Accept the eager PG flush for xattr writes on Ready files for now; SFS-956 (Release 0.3.0) makes the ctime-only event non-eager, without wire compatibility constraints.
  Date/Author: 2026-11-02 / user.

## Outcomes & Retrospective

Local regressions prove ctime advancement for both mutations and fresh VFS `getattr` visibility. The live mounted generic/728 run remains environment-gated and outstanding.
