# Correct Linux truncate modification time

This living plan follows `.agent/PLANS.md`. Linux applications must see a new modification time when pathname or handle truncation changes file size; explicit timestamps and unchanged sizes retain their existing semantics.

## Progress

- [x] Traced Linux setattr to the shared VFS size mutation and confirmed `/dev/fuse` on the host.
- [x] Ran the mounted regression before and after the correction; the initial run failed on pathname truncate and the final run passed all four cases.
- [x] Validated focused crate tests, checks, clippy, formatting, and final diff.

## Surprises & Discoveries

The sandbox hides `/dev/fuse`; it exists and is accessible on the host. An ext4 same-size truncate preserves mtime. The shared VFS size operation is also used by Windows, so an unconditional shared change could alter that platform.

## Decision Log

Use a Linux-requested VFS size-change timestamp policy, evaluated under the existing file session, with an explicit mtime taking precedence. Keep existing callers' semantics. The Linux adapter selects the policy for its setattr operations. This avoids a stale pre-operation size comparison.

## Outcomes & Retrospective

Linux FUSE now requests the VFS timestamp policy while other adapters retain their behavior. The mounted fixture passed all four operations; VFS tests covered explicit mtime and unchanged size. The registered xfstests generic/313 run was not repeated.

## Context and Orientation

`crates/studiofs-linux-fuse/src/low_level.rs` translates Linux FUSE setattr requests and sends them to `StudioVfs`. `crates/studiofs-vfs/src/vfs/namespace_ops.rs` serializes the size mutation and persists local attributes. It currently updates ctime but leaves mtime unchanged unless requested. The existing mounted test fixture creates a local VFS and FUSE session without remote services.

## Plan of Work

Add a mounted regression that sets a known old mtime and exercises pathname and handle truncation to zero and to 123. Run it against the unmodified implementation. Add a VFS entry point for POSIX size updates that requests an mtime update only when the size actually changes, preserving explicit timestamp assignments. Route Linux setattr to it; do not change Windows calls. Test same-size and explicit timestamp cases as well as the four requested operations.

## Concrete Steps

From the repository root run `cargo test -p studiofs-linux-fuse --lib mounted_truncate_updates_mtime -- --ignored --nocapture` outside the sandbox, where FUSE is available. Expect the old implementation to fail and the corrected implementation to pass. Run focused VFS and Linux FUSE tests and crate check and clippy, `cargo fmt --all -- --check`, and `git diff --check`.

## Validation and Acceptance

The mounted regression must observe all four size changes and their new mtime, and preserve mtime on a same-size request. Unit tests should additionally verify explicit mtime and other VFS callers. A native mount result is distinct from an xfstests run.

## Idempotence and Recovery

Tests use disposable local fixture state and a process-specific temporary mountpoint. The unmount guard cleans up if the worker fails. No remote state needs modification.
