# Bounded generation-aware directory snapshot cache for WinFSP

This is a living ExecPlan for SFS-693. Keep `Progress`, `Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` current while the issue remains in progress.

## Purpose

WinFSP currently rebuilds a directory enumeration for every newly opened directory handle. The rebuild performs local metadata enumeration, batched child-attribute reads, ACL filtering, UTF-16 conversion, and `DirInfo` construction before WinFSP can return the first page. After this change, clean repeated enumerations of the same directory reuse a bounded, generation-validated snapshot while each already-open handle keeps its own continuation buffer. Namespace, ACL, metadata-observation, dangling-entry, hidden-root-entry, and marker semantics remain unchanged.

The behavior is visible through focused WinFSP unit tests and cache counters. Native acceptance remains a separate release interleaved A/B benchmark using the registered `metadata_baseline::winfsp_metadata_baseline` workload; its artifacts must record cache hits, misses, invalidations, evictions, and the required stat/open/negative/enumeration timings.

## Surprises & Discoveries

- The per-handle `winfsp::filesystem::DirBuffer` already preserves marker continuation, but it cannot be cloned through the public API. The safe cache boundary is therefore an owned vector of reusable `DirInfo` values that is copied into each handle's existing native buffer under a mutex; this avoids repeated `DirInfo` construction without changing per-handle continuation state.
- The WinFSP `read_directory` callback receives a requested pattern, but the current implementation intentionally ignores it. The snapshot is therefore keyed only by directory and observation; pattern-aware filtering remains a separate future change.
- `directory_generation` covers namespace membership changes, while targeted attribute-cache retirement and ACL changes use separate observations. The public VFS token will include namespace epoch, directory generation, aggregate attribute revision, ACL epochs, and effective parent access level.

## Decision Log

- Decision: Keep the cache in `studiofs-winfsp` and expose only a small read-only VFS observation token.
  Rationale: WinFSP owns native `DirInfo` and per-handle buffers; moving those types into VFS would violate dependency direction. VFS remains the authority for freshness.
  Date/Author: 2026-09-07 / Codex.
- Decision: Use a bounded LRU with explicit entry and byte budgets and conservative admission.
  Rationale: A cache hit must not allow RSS growth without a declared limit; a snapshot larger than the byte budget is used for the current handle but is not retained.
  Date/Author: 2026-09-07 / Codex.
- Decision: Reject cache admission when the observation token changes during snapshot construction.
  Rationale: A result that crossed a namespace, metadata, or ACL invalidation must not become reusable cached state.
  Date/Author: 2026-09-07 / Codex.
- Decision: Keep the directory inode as cache identity and store the observation in the cache entry; do not key unfiltered snapshots by the ignored WinFSP pattern.
  Rationale: A freshness mismatch can replace one entry directly without scanning the cache, and different currently-unfiltered patterns must not duplicate the same snapshot. Pattern-aware filtering remains a separate change.
  Date/Author: 2026-09-07 / Codex.
- Decision: Treat namespace epochs as monotonic at cache admission.
  Rationale: Delayed work carrying an older observation must not clear newer entries or move the cache epoch backward; stale lookups miss without reset and stale insertions are rejected.
  Date/Author: 2026-09-07 / Codex.
- Decision: Stop accumulating `DirInfo` values when the snapshot cannot fit the cache byte budget and continue directly into the current handle's `DirBuffer`.
  Rationale: The VFS enumeration is already materialized, but the adapter must not add an unbounded second copy for an uncacheable directory; direct fallback preserves the current enumeration without cache admission.
  Date/Author: 2026-09-07 / Codex.
- Decision: Keep the bridge snapshot cache independent from the existing WinFSP file-cache admission bit.
  Rationale: The metadata snapshot is per-directory and generation validated; keeping the existing mount mode and write-capable OS file-cache bypass unchanged makes the native before/after benchmark comparable.
  Date/Author: 2026-09-07 / Codex.
- Decision: Route all production attribute-cache retirement seams through the aggregate-generation helper.
  Rationale: Direct removals during local-dirty, link/unlink, deferred-attribute, rollback, and cleanup paths otherwise leave a rendered directory snapshot with an unchanged observation token.
  Date/Author: 2026-09-07 / Codex.

## Context and Orientation

`crates/studiofs-winfsp/src/context.rs` implements the WinFSP adapter. `StudioFileHandle` owns one native `DirBuffer`, and `read_directory` populates it only when the marker is empty. `populate_directory_buffer` currently performs the complete expensive path.

`crates/studiofs-vfs/src/vfs/namespace_ops.rs` implements `readdir_with_attrs`, which merges local metadata, deferred local entries, batched child attributes, ACL filtering, dentry-cache updates, and prefetch hints. `crates/studiofs-vfs/src/vfs/namespace.rs` owns namespace epoch and per-directory generations. `crates/studiofs-vfs/src/vfs/acl.rs` owns ACL epochs. `crates/studiofs-vfs/src/vfs/workers.rs` retires attribute observations during committed local/remote invalidation.

The cache identity is the directory inode. Each entry stores the VFS directory-enumeration observation alongside its snapshot; a lookup compares the requested observation before reuse. A cache hit only fills the current handle's native buffer; it never shares continuation cursor state between handles.

## Validation and Acceptance

The focused cache test must prove a miss followed by a hit, that a changed observation does not reuse the old entry, that the entry and byte budgets evict or reject entries, and that counters remain bounded and observable. Adapter tests must prove that repeated enumeration preserves names and attributes, a dangling child is skipped, mutation creates a fresh snapshot, and marker continuation still comes from the per-handle `DirBuffer`.

The VFS tests must prove that namespace mutation, attribute retirement, ACL change, and reset all change the observation token. The native benchmark must show a nonzero candidate cache-hit count for repeated 64-entry enumeration, lower or non-regressing enumeration CPU/allocation attribution, no material stat/open/negative regression, and RSS within the declared cache byte budget. If the repeated interleaved evidence does not demonstrate a beneficial or acceptable tradeoff, record that decision and leave the issue open for owner review rather than claiming success from one run.

## Idempotence and Recovery

The cache is mount-local and in-memory. Restarting a mount discards it safely. A stale build is used only for the current already-started enumeration and is never admitted for reuse. Cache admission is conservative when observation acquisition fails. Cache eviction and reset are recoverable and do not affect metadata authority.
