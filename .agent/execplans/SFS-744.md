# Validate mounted writer lock ordering

This ExecPlan is a living document maintained under `.agent/PLANS.md`.

## Purpose / Big Picture

The VFS lock-order validator currently observes local dirty bookkeeping but misses mounted writer state and the shutdown phase. After this change, acquiring those real mutexes while holding a later namespace lock produces the existing diagnostic. Correct shutdown, writer, and namespace acquisition remains accepted. Filesystem durability and publication behavior stay unchanged.

## Surprises & Discoveries

The public enum already has `LocalDirty = 2`; its documentation describes only pending dirty bookkeeping, whereas the guide assigns all writer/cache dirty owners to tier 2. Writer shard and file guards nest in dirty snapshots and cleanup. Ordinary writes clone the file owner under the shard, release the shard, lock the file, and release the file before updating the shard. The graph has no recorded parse gaps in these files but reports changed metadata, so source inspection is required for conclusions.

The actual write path in `vfs/sync_ops.rs::record_writer_stack_state_payload` obtains dirty attributes as a temporary snapshot, releases the namespace mutex, calls the writer, then updates attributes separately. Shutdown claim and waiter paths release the phase mutex before async draining or notification waits. The separate async mutation gate and metadata-sync mutex remain uninstrumented.

The initial red run hit a test-only `Arc::clone` typo, which was corrected before counting evidence. The next build hit MSVC LNK1200 reading an existing PDB; removing only `target/debug/deps/studiofs_vfs-590ca735493fdb13.pdb` regenerated the artifact and allowed tests to execute. Rust 1.99 reports pre-existing `fetch_update` deprecation warnings across VFS and metadata; do not expand this issue into their migration.

The sandbox blocks payload staging with `PermissionDenied (os error 5)` and blocks rustfmt path resolution. Focused staging tests and formatting pass when run with the needed host access. The failed sandbox staging log is retained as `target/sfs-744-green-writer_stack-sandbox.log`; it is not passing evidence.

## Decision Log

Decision: Reuse `LockTier::LocalDirty` for mounted writer owners and broaden its documentation rather than changing numeric priorities or adding a separate writer priority. Rationale: the existing guide already puts these owners at the same tier, and preserving the public enum avoids an unnecessary compatibility change. Date/author: 2026-10-03, Codex.

Decision: Use the existing `OrderedMutex` for participating synchronous locks, leaving async admission/sync guards and independent cached-store internals outside thread-local tracking. Rationale: the wrapper already couples actual mutex ownership to validation, while async guards can cross threads across an await. Date/author: 2026-10-03, Codex.

## Context and Orientation

Work from `E:\dev\studiofs-cli` on `feature/sfs-744-cover-writer-stack-locks-in-vfs-lock-order-validation`. The initial working tree is clean. `crates/studiofs-vfs/src/lock_order.rs` assigns lock priorities and tracks each acquisition on its current thread. `crates/studiofs-vfs/src/ordered_mutex.rs` wraps a `parking_lot::Mutex`, registering a priority before locking and retaining that registration until the mutex guard is released. A tier is a numeric priority: lower numbers must be acquired first.

`crates/studiofs-vfs/src/vfs/writer_stack.rs` owns inode shards, handle shards, and per-file accepted writer state. `crates/studiofs-vfs/src/vfs.rs` owns the short synchronous shutdown-phase mutex and asynchronous shutdown coordination. `crates/studiofs-vfs/src/vfs/namespace.rs` owns real tier-3 namespace caches and dirty attributes. The writer tests can acquire these real state owners directly without adding a production hook. `docs/agents-coding-guide.md` documents the order.

## Plan of Work

Add tests that seed state through real writer methods, inspect the held tiers for actual writer and namespace mutexes, and deliberately invert namespace-to-writer and namespace-to-shutdown acquisitions.
