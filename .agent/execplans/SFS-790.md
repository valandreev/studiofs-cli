# Remove Linux open bookkeeping and memory sampling stalls

This living ExecPlan follows `.agent/PLANS.md` and implements Linear SFS-790.

## Purpose / Big Picture

Concurrent Linux FUSE opens must not wait for system memory refresh or a single
shared bookkeeping lock. Preserve inode liveness through rejected replies,
release replies, and deferred writes. Memory measurements expire after one
second; missing or expired measurements conservatively select direct I/O.

## Surprises & Discoveries

There are two global liveness locks: SessionState's handle map and
FuseInodeLiveness's inode state. Sharding only the handle map leaves every open
and close serialized on inode state. Codebase Memory MCP is unavailable here;
direct reads and `rg` covered all callers.

Independent review found that Session deliberately retains callback state after
shutdown timeouts. The sampler must be stopped independently of state Drop.
The existing rejected-open test also depended on a synchronous first sample;
under the direct environment policy its new background snapshot is absent.
Both review claims reproduced as one-test failures before correction.

## Decision Log

Use 32 mutex segments for each table. Select the handle segment by handle ID
and the inode segment by inode ID. All operations for one inode retain the same
lock, including lookup reservations and provisional FORGET accounting; no
operation needs multiple segments. Keep the existing per-inode reply serializer.

Replace the generic synchronous sampler and clock traits with an atomic memory
snapshot and one owned sampling thread per Adaptive session. The thread samples
immediately and waits one second between samples on a shutdown channel. Record
sample start time so slow sampling cannot publish already-expired data as fresh.
Joining the worker on drop prevents detached resource ownership. Thread startup
failure leaves the snapshot unavailable and is logged without failing the mount.
Session teardown explicitly calls idempotent sampler shutdown through a lock used
only to own the thread join; snapshot readers remain atomic and do not use it.
The rejection regression asserts generation disposition/reason, independently
of memory-policy flags. Update ADR 0011's former permissive fallback to reflect
the conservative fallback required here.

## Context and Orientation

`crates/studiofs-linux-fuse/src/low_level.rs` owns SessionState, installs guards
before replying, removes rejected handles, and transfers guards to deferred
release work. `src/invalidation.rs` owns reference counts and lookup reply
reservations; a guard decrements the open count on drop. `src/cache_policy.rs`
selects direct I/O or kernel caching and currently refreshes sysinfo synchronously.
These are internal Linux-only APIs. No VFS contracts or dependencies change.

## Validation and Acceptance

Focused tests must execute nonzero cases. Holding one inode/handle segment must
not block another segment. Multiple opens of the same inode remain live until
the last guard drops. Existing rejection and deferred-release regressions remain
green. Concurrent snapshot readers must finish while the memory source is held
on a channel. Exactly at the TTL, and on missing/failed samples, Adaptive uses
direct I/O even for a stable generation. Worker shutdown must join successfully.

## Idempotence and Recovery
