# Remove legacy startup-sync paths after the cutover

This ExecPlan records the narrow cleanup for SFS-719 after the bounded,
frozen-target startup catch-up cutover is already in place.

## Purpose / Big Picture

StudioFS must have one startup/convergence path: local metadata is served first,
then the bounded paged replication session catches up to one frozen PostgreSQL
target. The old `sync_metadata_to_current_head` helper still lets snapshot
reachability bootstrap run its own catch-up loop. Removing that duplicate loop
prevents maintenance work from reintroducing the old moving-head startup
assumption while preserving normal polling, NOTIFY replication, and explicit
metadata synchronization.

## Surprises & Discoveries

- SFS-701's `run_startup_catch_up_session` is the canonical bounded path and
  must remain in `lifecycle.rs`; its frozen-target and retry tests are semantic
  coverage, not obsolete startup-round tests.
- SFS-705 already completed the discovery-side cleanup. The current discovery
  code does not construct `PgMetaEngine` or replay the PostgreSQL event log, so
  no duplicate change is needed there.
- The reachability bootstrap transaction already detects a local/remote version
  race and returns a retry signal. After this cleanup, the caller will surface
  that bounded failure and the next regular replication poll will retry it.

## Decision Log

- Keep the general PostgreSQL command timeout and runtime sync configuration;
  they are still valid outside legacy startup catch-up.
- Delete `sync_metadata_to_current_head` instead of adapting it. Its only
  remaining production caller is the reachability bootstrap path, and retaining
  the helper would preserve a second catch-up entry point.
- Make one reachability bootstrap transaction attempt per invocation. Preserve
  the existing error text and let the already-existing bounded replication
  caller retry on its next poll.
- Do not remove `init`'s engine priming without evidence that it is startup
  catch-up; its history ties it to allocator/client-slot initialization rather
  than discovery priming.

## Outcomes & Retrospective

The legacy helper and its three-retry reachability wrapper were removed.
Reachability bootstrap now performs one bounded transaction and defers a
version-race retry to the next normal bounded replication poll. The canonical
frozen-target startup session and the already-pure discovery path were left
unchanged.

## Context and Orientation

Relevant code is under `crates/studiofs-meta/src/pg_engine/`:

- `metadata_sync.rs` contains the obsolete
  `sync_metadata_to_current_head` loop.
- `snapshot_reachability.rs` contains the one-transaction bootstrap and the
  obsolete retry/catch-up wrapper.
- `lifecycle.rs` contains the retained bounded paged startup session.
- `replication_api.rs` and `lifecycle.rs` call reachability bootstrap after a
  bounded sync operation and can retry it later.

The discovery implementation and its regression test are in
`crates/studiofs/src/cli/discovery.rs`; they already enforce the post-cutover
contract.
