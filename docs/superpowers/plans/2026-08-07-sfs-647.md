# ExecPlan: SFS-647 — error redaction, categories, and correctness contracts

## Purpose / Big Picture

Harden the shared StudioFS metadata and platform-bridge contracts without changing
the local-first product model. Persisted object-store credentials and PostgreSQL
DSNs must be safe in `Debug` output and diagnostics. Metadata failures must retain
repair, remote-unavailable, and timeout identity through VFS, POSIX/FUSE, and
WinFSP boundaries. Correctness-sensitive metadata operations must be required of
concrete engines so a dummy backend cannot silently return a safe-looking result.

The implementation is intentionally limited to the existing `studiofs-meta`,
`studiofs-vfs`, `studiofs-bridge`, and `studiofs-winfsp` contracts and their
focused tests. No new abstraction or error-enum mirror is planned.

## Surprises & Discoveries

- The issue and branch were already in the requested working state; no Linear or
  branch transition was needed.
- `FormatInfoDataStore` already has manual redacted `Debug`, but persisted
  `FormatInfo`, `RemoteStoreConfig`, `PostgresConfig`, and `StudioPgDsns` still
  derive `Debug` over secrets or full DSNs.
- `MetaError::PostgresUnavailable` already exists, but connection timeout and
  transport paths are split between that variant and `Storage`; the new shared
  `RemoteUnavailable` category should replace the backend-specific branch.
- `read_format_info_readonly` currently converts redb `RepairAborted` into a
  stringly `Storage` error, while redb exposes that error as a typed variant.
- Both Redb and PostgreSQL engines already implement the correctness-sensitive
  overlay, upload-match, atomic overlay-with-attributes, local flush/sync, and
  authority methods. Removing only their unsafe defaults should be compile-safe
  after test doubles are updated.
- POSIX adapters already share `studiofs-bridge::posix::vfs_err_to_errno`, so one
  shared mapping test covers Linux FUSE and macFUSE behavior; WinFSP has its own
  NTSTATUS translator and focused test.
- The existing Redb and PostgreSQL implementations satisfy the tightened trait
  contracts without new backend logic; Redb now states its intentional local-only
  no-op handle/poll hooks explicitly.
- WSL could not enumerate distributions (`E_ACCESSDENIED`), and the installed
  Linux target could not link because `x86_64-linux-gnu-gcc` is not installed;
  Windows-native checks therefore remain the available evidence for this run.
- Final diff review found parser-provided URL/keyword DSN error text as an
  avoidable leak surface; both paths now return fixed generic messages and the
  focused sentinel test covers both forms.

## Decision Log

- Keep `Storage(String)` for generic backend/storage context; add explicit
  `RepairRequired(String)`, `RemoteUnavailable(String)`, and `Timeout(String)`
  variants rather than mirroring every backend error.
- Remove `PostgresUnavailable` after migrating its callers to
  `RemoteUnavailable`; typed matching, not message substrings, decides fallback.
- Keep `MetaError::is_redb_repair_needed` as a compatibility helper, but make it
  match `RepairRequired` only.
- Preserve the name
  `flush_regular_file_overlay_slices_with_attr`; make it a required concrete
  implementation contract whose documentation requires one backend transaction
  for the slice and attribute mutation when both are present.
- Make overlay presence/object-match/upload-mark, local flush/sync, open-handle
  notes, and authority status required on `MetaReplication`/`MetaPayloadObjects`.
  Retain only wrappers whose semantics are backend-independent, such as the
  batch loop and invalidation diagnostics defaults.
- Use platform-native distinct mappings for the three explicit categories:
  POSIX `ENOTRECOVERABLE`, `EHOSTUNREACH`, and `ETIMEDOUT`; WinFSP
  `STATUS_DISK_CORRUPT_ERROR`, `STATUS_BAD_NETWORK_PATH`, and
  `STATUS_IO_TIMEOUT`. Verify constants with focused compilation/tests before
  finalizing.
- Redact complete DSN fields as `***`; endpoint, bucket, region, volume id, and
  other non-secret identity remain available where useful.

## Concrete Steps

### 1. RED: write and run focused tests

Add tests beside existing unit tests, using sentinel strings such as
`access-key-sentinel`, `secret-key-sentinel`, and a DSN password sentinel. Assert
that `Debug` output for each public credential/DSN-bearing type omits the
sentinels, and that typed category construction remains distinguishable.

Add bridge tests for `RepairRequired`, `RemoteUnavailable`, and `Timeout`.
Extend shared POSIX and WinFSP mapping tests with their exact distinct values.
Run the smallest package/test filters that compile these tests and confirm the
new assertions fail for the current implementation before changing production
code.

### 2. GREEN: metadata errors, redaction, and backend classification

In `engine.rs`, add the three explicit error variants and migrate repair and
PostgreSQL-unavailable matches. In `redb_engine/format.rs`, match the typed redb
repair variant before generic storage errors. In PG transport/runtime, preserve
safe context but return `RemoteUnavailable` for connect transport failures and
`Timeout` for command timeouts.

Replace derived `Debug` on `FormatInfo`, `RemoteStoreConfig`, `PostgresConfig`,
and `StudioPgDsns` with small manual implementations. Audit parsing/error paths
so invalid DSN errors do not interpolate the original DSN or a parser message
that contains it.

### 3. GREEN: shared and platform bridges

Add explicit bridge kinds and match arms in `studiofs-vfs`. Map them in the
shared POSIX helper and WinFSP helper. Keep generic storage/data corruption
behavior unchanged. Verify the new enum variants are handled exhaustively by
all platform translators and that no log branch formats a raw credential/DSN.

### 4. GREEN: required correctness contracts

Remove unsafe defaults for local overlay presence, overlay object lookup/match,
upload marking, local flush/sync, open-handle notes, authority status, and the
multi-operation overlay-with-attributes flush. Update all concrete engines and
test doubles with their existing semantics; do not add speculative behavior.
Keep backend-independent convenience wrappers. Update method documentation to
state the transaction boundary rather than promising an optional best effort.

### 5. Validation and handoff

Run focused commands only: package-level tests for metadata/bridge/VFS and the
WinFSP library tests available on Windows, plus `cargo check`/targeted Clippy,
`cargo fmt --check`, and `git diff --check`. If a Windows-only dependency or
external PostgreSQL prerequisite prevents a check, report it precisely instead
of calling it an integration pass. Inspect `git diff`, confirm no unrelated
files changed, update this plan, commit all changes, and optionally add an
English Linear progress/completion comment.

## Validation and Acceptance
