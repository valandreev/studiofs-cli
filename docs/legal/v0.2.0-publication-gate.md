## Platform packages and source delivery

The [release workflow](../../.github/workflows/release.yml) defines Windows
x86-64/ARM64, Linux x86-64/ARM64 and macOS ARM64 native builds with Rust 1.95.0
and `cargo build -p studiofs --release --locked --target <target>`. Strict notice
generation is a prerequisite, so the known evidence gaps stop binary packaging
and draft creation. No successful five-platform workflow run is claimed here.

Successful future runs must show Windows WinFsp delay loading; Linux dynamic
libfuse3; and macOS legacy libfuse without MFMount. Packages contain only the
executable, build metadata and allowlisted documentation/notices, with no bundled platform
driver or shared-library installation. Each archive records the source commit,
binary and lockfile hashes, Rust compiler and build command in BUILD-INFO.json.
The packager has focused tests for ZIP/tar contents, checksum sidecars,
executable permissions, unresolved-notice rejection and stale lockfile rejection.

Local validation also rebuilt the Windows product with
`cargo build -p studiofs --release --locked`; the command succeeded and
`target/release/studiofs.exe --version` reported `studiofs 0.2.0`. This checks
the version bump and host build. Local `dumpbin /headers /dependents` also
confirmed x64 machine type and `winfsp-x64.dll` under delay-load dependencies.
Neither check clears a tagged package or the other four targets.

The workflow attaches all successful tagged packages to a draft and includes
an exact tracked-project source archive. That archive plus GitHub's tag source
downloads is not by itself a reviewed complete corresponding-source method
for every dependency. Before GO, establish the chosen delivery/access method
for all covered source, embedded native components and necessary build material,
retain required notices, and verify it from the download location. The
[build/install guide](../releases.md) explains current reproduction limits.

SHA-256 `d29144deff3a68aa93ced33dddf84b7fdc26070add4aa0f4513094c8332afc4e`.
The non-shallow checkout contained 5,170 commits reachable from the starting

| generic-api-key | `crates/studiofs-data/src/crypto.rs:1033`, commit `6be949a12f756f7b5a99413cfd5ba482cdc51177` | Same synthetic test identifier |

Raw scanner exit status is **1**, because these two matches are not suppressed.
The redacted HEAD/all-refs JSON reports are identical, SHA-256
`ea8616091659dca30ace038c486f88200ed0f129abe105f23a2775ade65de13d`,
under `target/sfs-854/refresh/`. This covers fetched reachable Git history;
unfetched remote refs, dangling objects and arbitrary binary/private-data formats
are outside the scan's guarantees. Current-tree heuristic checks found synthetic
configuration/redaction examples, no suspected live credentials or private

response is not an empty-alert result.

The maintainer's prior decision accepts historical developer paths, hostname,
removed symlink/header and earlier template copies without rewriting history.
That decision is retained in the provenance register. No new history rewrite,
secret suppression, platform driver bundling or native licensing exception is
introduced here.

## Recheck and final decision

From the repository root, run:

```powershell
cargo metadata --locked --offline --no-deps --format-version 1
cargo deny --locked check licenses
python docs/legal/check-license-policy.py
python docs/legal/generate-third-party-notices.py --self-test
python docs/legal/generate-third-party-notices.py --release --output-dir target/license-compliance
python tools/release/test_package.py
git diff --check
```

Use the pinned cargo-deny version and Python 3.11+. On this Windows sandbox,
point TEMP/TMP at a writable directory under `target/` for the notice self-test.
Run actionlint on `.github/workflows/release.yml`. After notice gaps are resolved,
run the five native builds and inspect their real artifacts before publishing
the draft. Preserve linkage, archive hashes and source mapping in the final GO
record. Do not equate passing packaging unit tests with native or mounted QA.

**The current decision remains NO-GO.** Version/provenance preparation and a
draft-release mechanism are delivered; unresolved notices and uninspected
platform/source artifacts still prevent public binary distribution.
