## Publication hygiene

A bounded inspection considered 714 tracked paths, scanning readable text up
to 5 MB for common private-key and AWS/GitHub/Slack/Stripe token patterns and
credential-bearing URLs. It did not load ignored local `.env` values. No
suspected live credential was identified by those patterns. This is a limited
heuristic result, not proof that the repository is secret-free.

The credential-bearing URL matches were local test/example values in
`.agent/execplans/SFS-650.md`, `crates/studiofs-meta/src/pg_dsn.rs`,
`crates/studiofs-meta/src/pg_engine/tests/snapshot_control.rs`, and the English
and Ukrainian `13-create-your-first-volume-studiofs-init.md` user guides.
`.env.example` intentionally includes local RustFS fixture credentials and
PostgreSQL placeholders. These values must remain local examples and must not
be treated as production credentials; no credential values are reproduced
here.

A pattern-limited `git log --all -G` inspection found an explicitly marked AWS
sample-key example in historical README commit `7c6a2bb2`. It did not scan every
historical blob or establish complete history coverage. No dedicated secret
scanner was available. The `cargo-audit` job in `.rwx/ci.yml` checks dependency
advisories, not repository credentials. The authenticated GitHub secret-scanning
API returned HTTP 404 with the explicit message that secret scanning is
disabled on this repository; this is not an empty-alerts result.
The sanitized endpoint/status/message receipt is retained locally as
`target/sfs-854/github-secret-scanning.json`.

Existing related security work was located in Linear:
[SFS-647](https://linear.app/valandreev/issue/SFS-647) (redaction/contracts),
[SFS-366](https://linear.app/valandreev/issue/SFS-366) (E2E artifact redaction),
and [SFS-859](https://linear.app/valandreev/issue/SFS-859) (init-output
credentials) are Done. Those runtime-output fixes do not establish source or
history clearance. Their tests were not duplicated or rerun for this
documentation-only gate; this is not an exhaustive security-issue audit.

Four tracked redb compatibility fixtures have documented test purposes; common
credential/path markers did not match their bytes. Their internal database
contents were not decoded or cleared for publication. The tracked opaque file
`.antigravitycli/9d7276d9-1579-4c0b-8fa1-49bdc747c598.json` fails JSON parsing.
Common token/email/home-path markers did not match, but its provenance and
contents remain unresolved. Its directory being ignored does not remove the
already tracked file. Review or exclude it through SFS-851 before publishing,
including any history that will become public.

Codebase Memory was used for discovery and its coverage was checked. Its
snapshot predates the legal report/README changes and does not index the
binary fixtures or parse the opaque artifact, so conclusions about those
paths use direct inspection. No clean-history, asset-rights, or publication
clearance is granted.
