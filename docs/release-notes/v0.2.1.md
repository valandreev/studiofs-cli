# StudioFS 0.2.1

This release focuses on Linux performance work, including VFS optimizations,
alongside POSIX compliance testing and fixes. It also includes reliability
improvements and dependency updates accumulated since 0.2.0.

## Highlights

- Accelerate Linux filesystem operations through VFS optimization.
- POSIX compliance testing and fixes for issues found during testing.
- Improve Linux mount responsiveness and tray-helper isolation.

## Dependency updates

- Update `aws-smithy-json` to 0.62.7.
- Update `rand` 0.8 to 0.8.6 and `rand` 0.9 to 0.9.3.
- Update `tray-icon` to 0.26.1 and select its GTK-free KSNI backend on Linux,
  removing the tray's GTK3/GLib/AppIndicator dependency path affected by
  RUSTSEC-2024-0429.

## Bug fixes

- Improve mounted write and metadata correctness across deferred creates,
  truncation, rename/unlink, hard links, extended attributes, and concurrent
  publication. Preserve newer local file data when uploads or peer updates
  arrive out of order.
- Improve random-write packing and cleanup of obsolete local payloads, while
  bounding cleanup work during mount startup and shutdown.
- Keep mounts responsive during local cache stalls and bound waits during
  shutdown and tray-helper teardown.
- Fix macFUSE directory refresh, file mapping, executable-file, and
  cross-user access behavior.
- Isolate the Linux tray in an owned helper so an unresponsive session D-Bus or
  tray watcher cannot hold mount startup or completion. A helper that cannot
  shut down normally is terminated and reaped after a two-second grace period.
- Preserve Linux tray synchronization status through StatusNotifierItem over
  session D-Bus. KDE and other compatible hosts can display the indicator;
  GNOME needs an AppIndicator/KStatusNotifierItem extension. Missing desktop
  support remains non-fatal for mounts. Windows/macOS use their native backends.
