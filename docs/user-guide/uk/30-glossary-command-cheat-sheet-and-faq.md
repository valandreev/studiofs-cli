# 30. Глосарій, шпаргалка команд і поширені запитання
> **Сторінка в процесі доповнення**

Ця глава допоможе швидко згадати термін, знайти команду й повернутися до роботи. Якщо ви налаштовуєте StudioFS уперше, почніть із [вибору конфігурації](05-choose-your-setup.md), а не з копіювання всіх команд поспіль.

## Короткий словник

| Термін | Що це означає на практиці |
| --- | --- |
| **Том (volume)** | Спільний файловий простір StudioFS зі своєю структурою папок і налаштуваннями. У прикладах його назва — `projectfs`. |
| **Монтування (mount)** | Підключення тому як диска або каталогу, з яким працюють звичайні програми. |
| **Точка монтування** | Місце, де видно файли: наприклад, `Z:` у Windows або каталог у macOS чи Linux. Це не адреса S3. |
| **Клієнт** | Комп’ютер із запущеним StudioFS, який працює з томом. |
| **S3-сумісне сховище** | Сервіс, де StudioFS зберігає вміст файлів у власному форматі. Це може бути хмарний сервіс або ваше власне сховище. |
| **Bucket** | Контейнер для об’єктів у S3. Його вміст не можна редагувати як звичайну папку проєкту. |
| **Endpoint** | Адреса сервісу S3, через яку клієнт звертається до сховища. |
| **Метадані** | Відомості про назви, папки, розміри й версії файлів. Саме відео чи вміст сцени — це дані, а не метадані. |
| **PostgreSQL** | База спільних метаданих, через яку клієнти дізнаються про опубліковані зміни. |
| **Локальна база метаданих** | Робоча копія метаданих на комп’ютері. Підключений том використовує її, щоб не звертатися до PostgreSQL під час кожної файлової операції. |
| **Кеш** | Локальні дані на SSD: уже завантажені частини файлів і нові зміни, які ще можуть чекати на передавання. Це не просто папка з тимчасовим сміттям. |
| **Синхронізація** | Фонове передавання даних і поширення метаданих між клієнтами. Збереження в програмі й поява результату в колеги відбуваються не одночасно. |
| **Знімок (snapshot)** | Зафіксований стан усього тому, який можна відкрити лише для читання й скопіювати звідти потрібні файли. |
| **TTL / retention** | Строк зберігання знімка. У командах Snapshot v2 його відраховують від моменту переходу в стан `Ready`. |
| **Резервна копія** | Незалежна копія потрібних даних, метаданих і ключів із перевіреним способом відновлення. Самого знімка для цього недостатньо. |

Докладніше про зв’язок цих частин — у главі [«Як це все працює?»](02-how-does-this-thing-work.md).

## Шпаргалка команд

У прикладах `projectfs` — назва вашого тому, `Z:` — вільна літера диска у Windows. У macOS і Linux замість неї вкажіть підготовлений каталог (`/Volumes/Studiofs` або `/mnt/StudioFS`). Підтримку платформ перевірте в [главі про вимоги](03-capabilities-limits-and-requirements.md) та [інструкції для Linux](12-install-studiofs-on-linux.md).

| Що потрібно | Команда | Де прочитати подробиці |
| --- | --- | --- |
| Дізнатися версію | `studiofs --version` | [Встановлення у Windows](10-install-studiofs-on-windows.md) |
| Відкрити довідку | `studiofs --help` або `studiofs mount --help` | Довідка саме вашої встановленої версії |
| Підключити том | `studiofs mount projectfs Z:` | [Монтування](14-mount-your-volume-studiofs-mount.md) |
| Задати ліміт кешу під час підключення | `studiofs mount projectfs Z: --cache-size 500GB` | [Кеш](20-cache-why-is-the-cloud-using-my-ssd.md) |
| Переглянути стан | `studiofs status projectfs` | [Налаштування, стан та активність](22-settings-status-and-activity.md) |
| Отримати докладніший стан | `studiofs status projectfs --verbose` | Та сама глава |
| Переглянути збережені налаштування | `studiofs settings` | Та сама глава |
| Зберегти типовий ліміт кешу | `studiofs settings --cache-size 500GB` | Та сама глава |
| Переглянути активність підключеного тому | `studiofs perf Z: --count 5` | Та сама глава |
| Відключити диск | `studiofs umount Z:` | [Безпечне відключення](17-unplug-safely-studiofs-umount.md) |
| Створити знімок на сім діб | `studiofs snapshot projectfs create --ttl 7d` | [Знімки](24-snapshots-a-time-machine-for-your-volume.md) |
| Переглянути знімки | `studiofs snapshot projectfs list` | Та сама глава |
| Перевірити розклад знімків | `studiofs snapshot projectfs policy show` | Та сама глава |
| Попередньо оцінити очищення | `studiofs janitor projectfs --dry-run` | [Обслуговування](27-maintenance-and-removing-a-volume.md) |
| Очищувати невеликими порціями | `studiofs janitor projectfs --max-deletes 100` | Та сама глава |
| Показати локальні scratch-записи або осиротілі піддерева | `studiofs scratch list --volume projectfs [--orphaned]` | [Scratch-шар та `.studiofsignore`](31-scratch-layer-and-studiofsignore.md) |
| Очистити старі scratch-записи | `studiofs scratch clean --volume projectfs --older-than 7d` | Та сама глава |
| Перевести scratch-шлях у відстежувані | `studiofs scratch promote --volume projectfs -- renders/tmp` | Та сама глава |
| Відновити осиротілий scratch-запис | `studiofs scratch restore --volume projectfs <orphan>` | Та сама глава |

Для роботи зі знімком скопіюйте справжній ідентифікатор зі списку. Наприклад, якщо це `projectfs.2026-08-12T14-07-09.482Z`:

```powershell
studiofs snapshot projectfs inspect projectfs.2026-08-12T14-07-09.482Z
studiofs smount projectfs projectfs.2026-08-12T14-07-09.482Z Y:
```

`Y:` має бути окремою вільною літерою. `smount` відкриває знімок лише для читання; завершивши роботу, виконайте `studiofs umount Y:`. У кожній команді `snapshot` потрібно явно вказувати назву тому — поточний том автоматично не визначається. Якщо назва невідома чи некоректна, команда пояснить проблему й підкаже, що виправити. У `smount` назва тому також обов’язкова.

### Команди, перед якими варто відкрити відповідну главу

`studiofs init` створює новий том і потребує параметрів сховища та PostgreSQL. Готовий приклад із поясненням параметрів наведено в [главі про перший том](13-create-your-first-volume-studiofs-init.md). Щоб підключити наявний том на іншому комп’ютері, потрібна команда `studiofs discover`, а не повторний `init` (див. [підключення другого комп’ютера)](16-connect-a-second-computer-studiofs-discover.md).

`studiofs fsck projectfs` перевіряє метадані й **може запропонувати виправлення**, тож це не просто звіт, який нічого не змінює. З прапорцем `--repair` знайдені проблеми виправляються без запиту на підтвердження. Підготовку й обмеження описано в [главі про обслуговування](27-maintenance-and-removing-a-volume.md).

`studiofs destroy projectfs` — **це безповоротне видалення тому**, а не відключення. Варіант `--local` залишає віддалені дані, але видаляє локальний стан і може знищити ще не передані зміни. Не використовуйте його, щоб «освіжити кеш».

`studiofs dump projectfs --path-to-dump ./projectfs-metadata.json` експортує частину метаданих із PostgreSQL. Цей JSON не містить самих файлів і не є повною резервною копією бази чи тому. Команда `load` змінює цільову базу; порядок дій і обмеження обох команд описано в [главі про перенесення метаданих](25-migrating-studiofs-metadata-to-new-postgresql-server.md).

## Поширені запитання

### Чи потрібен постійний інтернет?

Щоб отримувати дані, яких немає локально, потрібен доступ до S3, а щоб обмінюватися змінами — до PostgreSQL. Уже закешовані дані за певних умов можна читати й без зв’язку, а локальні зміни чекатимуть, доки мережа відновиться. Але повноцінної автономної роботи це не гарантує. Докладніше — у [главі про поганий Wi-Fi](19-sync-bad-wi-fi-and-other-surprises.md).

### Де кнопка «Синхронізувати зараз»?

Передавання відбувається у фоновому режимі, окремої команди `studiofs sync` немає. Перевіряйте `status`, активність і помилки. На Windows, macOS і Linux `mount` автоматично намагається показати значок у треї чи рядку меню, якщо доступне графічне середовище; параметр `--tray` для цього не потрібен. Якщо значок не з’явився, том однаково працює, а керувати ним можна з командного рядка.

### Файл збережено. Можна вимикати комп’ютер?

Спершу збережіть роботу, дайте програмі завершити запис і дочекайтеся передавання змін. Червона пульсація значка означає, що синхронізація триває, — у цей момент краще зачекати. Але й спокійний значок не доводить, що всі колеги вже отримали потрібну версію. Закрийте програми, що використовують том, і виконайте `umount`; якщо команда завершилася з помилкою, з’ясуйте причину, перш ніж вимикати комп’ютер. Див. [безпечне відключення](17-unplug-safely-studiofs-umount.md).

### Чому файли у хмарі, а SSD зайнятий?

StudioFS тримає потрібні дані поруч із програмами й накопичує нові зміни перед передаванням. Не видаляйте кеш вручну: там можуть бути єдині копії ще не опублікованих даних. Як оцінити використання місця, описано в [главі про кеш](20-cache-why-is-the-cloud-using-my-ssd.md).

### Змінив `settings`, а поведінка та сама. Чому?

`settings` зберігає типові параметри для наступних підключень, а не змінює налаштувань уже запущеного процесу. Крім того, параметри, явно вказані в `mount`, мають пріоритет. Ця команда називається саме `settings`, команди `studiofs prefs` немає. Див. [главу 22](22-settings-status-and-activity.md).

### Знімок замінює резервну копію?

Ні. Знімок залежить від доступності метаданих, об’єктів і ключів того самого тому. Крім того, він не захоплює автоматично того, що ще лежить неопублікованим у локальному кеші. На випадок аварії потрібні незалежні резервні копії з перевіреною процедурою відновлення.

### Після розриву зв’язку треба знову виконати `init` чи `discover`?

Ні, після звичайного відновлення мережі новий том не потрібен. Перевірте VPN, доступність S3 і PostgreSQL, стан клієнта й вільне місце. Якщо підключення зупинилося, з’ясуйте причину й підключіть наявний том командою `mount`. `discover` призначений для підготовки нового клієнта до роботи з наявним томом, а повторний `init` синхронізації не відремонтує. Якщо проблема не зникла, перейдіть до [діагностики](29-logs-diagnostics-and-asking-for-help.md).
