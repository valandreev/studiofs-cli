# 12. Встановлюємо StudioFS на Linux
> **Сторінка в процесі доповнення**

На Linux StudioFS підключає сховище через **FUSE3**. Цей компонент дає програмі змогу показати файли із S3 як звичайну папку: монтажна програма бачить шлях до матеріалів, а StudioFS дбає про їх отримання та збереження.

У цій главі підготуємо систему, завантажимо StudioFS і перевіримо, чи він запускається. Створення тому й справжнє підключення сховища залишимо для наступних глав. Папка для майбутнього диска поки що буде порожньою, і це нормально: матеріали ще не надійшли.

## Який Linux підійде?

StudioFS протестовано на **Ubuntu 24.04** і **Rocky Linux 9.4**. На інших дистрибутивах Linux він теж має працювати, але ми їх не перевіряли; набір і назви системних пакетів там можуть відрізнятися.

Для встановлення системних пакетів потрібні права адміністратора. Сам StudioFS працюватиме від імені звичайного користувача.

## Встановлюємо системні залежності

### Ubuntu 24.04

Відкрийте термінал і виконайте:

```bash
sudo apt-get update
sudo apt-get install -y fuse3 libfuse3-3
```

Це системні бібліотеки та утиліти, потрібні для запуску програми й підключення FUSE3.

### Rocky Linux 9.4

Потрібні пакети є в стандартних репозиторіях Rocky Linux, тож підключати EPEL і CRB не потрібно.

```bash
sudo dnf install -y fuse3 fuse3-libs
```

Якщо пакет не знаходиться, спершу перевірте доступність репозиторіїв і версію системи. Не замінюйте FUSE3 старим FUSE2: StudioFS використовує саме третю версію.

## Значок у системному треї (версія 0.2.1)

Починаючи з версії 0.2.1, значок StudioFS у треї Linux працює через стандарт KSNI/StatusNotifierItem і сеансову шину D-Bus. Бібліотеки GTK3, GLib, libxdo та AppIndicator для цього більше не потрібні.

* **Де значок відображається.** У сумісних середовищах, наприклад KDE Plasma. У GNOME потрібно ввімкнути розширення AppIndicator/KStatusNotifierItem; спливні підказки там можуть не відображатися.
* Якщо служба трею запуститься пізніше або перезапуститься, StudioFS зареєструє значок повторно.
* Якщо сумісного середовища чи сеансової шини немає, том підключиться й працюватиме без значка в треї.
* Якщо процес трею зависне в D-Bus, через дві секунди його буде примусово зупинено; підключений том при цьому продовжить працювати.
* Відсутність значка не означає, що синхронізацію завершено. У старіших збірках 0.2.0 як і раніше потрібні GTK та AppIndicator.

## Перевіряємо FUSE3

Для обох систем перевірка однакова:

```bash
fusermount3 --version
ls -l /dev/fuse
```

Перша команда перевіряє, чи доступна утиліта `fusermount3`. Друга показує пристрій ядра, через який відбувається підключення.

Якщо у звичайній Linux-системі немає `/dev/fuse`, адміністратор може спробувати завантажити модуль:

```bash
sudo modprobe fuse
```

Після цього ще раз перевірте пристрій. У контейнері чи іншому обмеженому середовищі самого лише встановлення пакетів недостатньо: хост має надати доступ до `/dev/fuse` і дозволити підключення FUSE. Якщо це керований сервер, таку зміну має внести його адміністратор.

## Завантажуємо StudioFS

Відкрийте [сторінку випусків StudioFS](https://github.com/valandreev/studiofs-cli/releases) і завантажте збірку для своєї системи та архітектури. Якщо файл запаковано в архів, розпакуйте його. У команді `install` замініть `/path/to/studiofs` на шлях до завантаженого виконуваного файлу:

```bash
mkdir -p "$HOME/.local/bin"
install -m 755 "/path/to/studiofs" "$HOME/.local/bin/studiofs"
export PATH="$HOME/.local/bin:$PATH"
studiofs --version
studiofs --help
```

Команда `export` діє лише в поточному терміналі. Щоб шлях зберігся після закриття термінала, додайте цей рядок до файлу налаштувань своєї оболонки, якщо його там ще немає. Для Bash це зазвичай `~/.bashrc`. Потім відкрийте новий термінал і ще раз виконайте `studiofs --version`.

Якщо ви вже встановлювали StudioFS раніше, перевірте, який файл запускається:

```bash
command -v studiofs
```

У цьому прикладі команда має показати шлях до `studiofs` у вашій папці `.local/bin`. Якщо шлях інший, імовірно, термінал знаходить попередню копію раніше за нову.

## Готуємо папку для підключення

Створіть каталог `/mnt/StudioFS` і зробіть його власником свого користувача, щоб StudioFS міг створювати в ньому точки монтування:

```bash
sudo mkdir -p /mnt/StudioFS
sudo chown "$(id -un):$(id -gn)" /mnt/StudioFS
ls -ld /mnt/StudioFS
```

Для тому `studio` фактичною точкою монтування буде `/mnt/StudioFS/studio`: StudioFS додає назву тому до вказаного каталогу. Не кладіть у цю папку матеріали до підключення: звичайні локальні файли не стануть файлами тому автоматично, а після підключення вміст папки сховається за змонтованою файловою системою.

Запускайте StudioFS від імені того самого користувача, який працюватиме з матеріалами. Не відкривайте папку для всіх командою `chmod 777` і не запускайте програму через `sudo`, щоб обійти незрозумілу помилку доступу. Спершу перевірте власника папки та доступ до `/dev/fuse`. Ці приклади готують підключення для вашого користувача; права інших облікових записів потрібно перевіряти окремо.

## Якщо щось не запускається

* **Повідомлення про відсутню системну бібліотеку.** Переконайтеся, що встановлено системні пакети, описані вище.
* **`studiofs: command not found`.** Запустіть файл за повним шляхом `"$HOME/.local/bin/studiofs" --version` і перевірте налаштування `PATH`.
* **Помилка доступу до FUSE.** Перевірте, чи є `/dev/fuse`, які права на нього встановлено та чи немає обмежень середовища. У контейнері причина часто в налаштуваннях хоста.

Якщо `--version` і `--help` спрацювали, консольна програма запускається. Але підключення файлової системи, PostgreSQL чи S3 вони ще не перевіряють. Це ми зробимо під час створення й підключення першого тому.

## Що далі?

Тепер у вас є програма, FUSE3 і місце для майбутнього диска. У наступній главі створимо перший том командою `studiofs init` і об’єднаємо підготовлені раніше PostgreSQL та S3 в одне робоче сховище.
