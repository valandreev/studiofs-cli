# 14. Підключаємо том — studiofs mount
> **Сторінка в процесі доповнення**

Том уже створено, але монтажна програма ще не знає, де шукати матеріали. Підключімо його до файлової системи комп’ютера: у Windows він з’явиться як диск із літерою, а в macOS чи Linux — як папка. Саме для цього призначена команда `studiofs mount`.

## Windows: обираємо вільну літеру

Відкрийте PowerShell і виконайте:

```powershell
studiofs mount myvolume Z:
```

`myvolume` — ім’я тому, а `Z:` — місце, де його побачать програми. Виберіть літеру, яку ще не використовує інший диск чи мережеве підключення. Якщо `Z:` зайнято, можна взяти, наприклад, `S:`.

**У Windows літеру диска потрібно вказувати явно.** Шлях на кшталт `C:\Projects` у цій команді не замінює літери диска. Ім’я тому до `Z:` не додається: коренем підключеного тому буде `Z:\`.

Відкрийте Провідник і перейдіть до `Z:\`. Новий том може бути порожнім — це нормально. Він не мусить одразу містити відео з котиками, хоча іноді дуже хочеться почати саме з них.

## macOS і Linux: обираємо папку

На macOS використайте каталог `/Volumes/Studiofs`, підготовлений у попередній главі:

```bash
studiofs mount myvolume /Volumes/Studiofs
```

StudioFS додає ім’я тому до вказаного шляху, якщо останній елемент шляху ще не збігається з цим ім’ям. Тож фактичною точкою монтування буде **`/Volumes/Studiofs/myvolume`**. У Linux використайте каталог `/mnt/StudioFS`, підготовлений у [главі 12](12-install-studiofs-on-linux.md):

```bash
studiofs mount myvolume /mnt/StudioFS
```

Обидві команди створюють точку монтування з назвою тому. Виконайте ту, що відповідає вашій системі.

StudioFS намагається створити потрібні каталоги самостійно. Оберіть для підключення окрему папку, у якій немає ваших робочих файлів. На macOS переконайтеся, що маєте право запису в `/Volumes/Studiofs` (як підготувати права, описано в главі 11). У Linux використовуйте папку, до якої ваш користувач має доступ.

У Linux підключений том типово може відкрити лише той користувач, який запустив монтування; навіть `root` і служби, що працюють під іншим обліковим записом, отримають відмову. Якщо файли потрібні іншому локальному обліковому запису (наприклад, демону рендер-вузла чи спільній папці Samba), додайте параметр `--allow-other`. Звичайні права доступу до файлів для таких користувачів і далі діятимуть. Якщо ви монтуєте том не від імені `root`, у файлі `/etc/fuse.conf` має бути рядок `user_allow_other`; інакше StudioFS зупиниться з помилкою, у якій буде згадано цей рядок. Щоб увімкнути цей режим типово, виконайте `studiofs settings --allow-other`, а щоб вимкнути — studiofs settings `--allow-other=false`.

На macOS відкрийте Finder, натисніть **⌘⇧G** і введіть `/Volumes/Studiofs/myvolume`. На Linux відкрийте `/mnt/StudioFS/myvolume` у файловому менеджері. Системні компоненти тут різні: macOS використовує macFUSE, а Linux — libfuse3.

## Чому термінал не дає вводити нові команди?

Бо він зараз утримує підключення. Типово `mount` працює **в активному режимі (foreground)**: процес залишається запущеним, а вікно термінала зайняте. Щоб перевірити диск, відкрийте інше вікно термінала або файловий менеджер.

Той самий режим можна вказати явно:

```powershell
studiofs mount myvolume Z: --foreground
```

На macOS чи Linux замість `Z:` вкажіть свій шлях. Для першого запуску цей режим зручний: повідомлення про проблеми видно відразу. Але не закривайте вікно: разом із ним відключиться й диск.

Для щоденної роботи є **фоновий режим**:

```powershell
studiofs mount myvolume Z: -d
```

На macOS:

```bash
studiofs mount myvolume /Volumes/Studiofs -d
```

На Linux:

```bash
studiofs mount myvolume /mnt/StudioFS -d
```

`-d` — скорочення від `--detach`. StudioFS запускає окремий процес, і терміналом знову можна користуватися. Параметри `--foreground` і `--detach` не можна вказувати одночасно.

Команда повертає керування, щойно том готовий приймати запис, — зазвичай за одну-дві секунди. Якщо синхронізація із сервером триває довше ніж 10 секунд, команда все одно завершується й повідомляє, що доступ на запис ще очікується. Доти файли можна читати, але спроба створити чи змінити файл завершиться помилкою «Permission denied».

Фоновий режим не встановлює системної служби й не налаштовує автоматичного підключення після перезавантаження. Журнали фонового процесу зберігаються в каталозі `logs` кореня клієнта, типово — `~/.studiofs/logs/`.

## Перевіряємо, що бачимо саме том

Після запуску відкрийте диск або папку й перегляньте вміст. У другому терміналі можна виконати:

```powershell
Get-ChildItem Z:\
```

На macOS:

```bash
ls -la /Volumes/Studiofs/myvolume
```

На Linux:

```bash
ls -la /mnt/StudioFS/myvolume
```

Щоб перевірити запис, створіть через Провідник чи файловий менеджер папку `mount-check`, переконайтеся, що вона з’явилася, і видаліть її. Після цього порожній том знову стане порожнім. Якщо ви свідомо підключили том із параметром `--read-only`, створити папку не вдасться — так і має бути.

На macOS і Linux **сама наявність каталогу ще не означає, що том підключено**: каталог може залишитися й після відключення. Переконайтеся, що запуск завершився без помилок, а процес підключення працює. Якщо термінал повідомив про невдалий запуск, не копіюйте матеріали в цю папку: вони можуть потрапити у звичайний локальний каталог.

## Зберегти файл і передати його команді — це різні події

Коли програма зберігає файл на підключений том, StudioFS спершу приймає зміни локально. На цьому комп’ютері вони доступні одразу. Вміст передається в S3, а спільні метадані публікуються у фоновому режимі; інші комп’ютери побачать результат після синхронізації.

Тому закритий файл, успішне збереження чи поява папки `mount-check` ще **не означають, що зміни вже доступні колегам**. Не вимикайте комп’ютер одразу після великого експорту лише тому, що монтажна програма закрила вікно прогресу.

Якщо є графічне середовище, StudioFS автоматично намагається показати значок у системному треї чи рядку меню. Зараз це передбачено для Windows, macOS і Linux, але чи буде значок видно, залежить від графічного середовища. Окремий параметр `--tray` для `mount` не потрібен. Якщо графічний значок недоступний, том однаково працює, а керувати ним можна з командного рядка.

Червона пульсація означає, що локальні зміни ще чекають на синхронізацію. Анімований синьо-жовтий прапор з’являється, коли передавання прийнятих змін і метаданих підтверджено. Якщо значка немає або його стан застарів, це нічого не підтверджує. І навіть після підтвердження програма може знову щось записати.

Параметр `--detach` сам по собі не гарантує появи значка, а фонове підключення працює й без нього.

## Як завершити першу спробу

Закрийте програми, які працюють із томом. Якщо підключення працює в активному режимі, натисніть **Ctrl+C** у його терміналі й дочекайтеся завершення процесу.

Фонове підключення відключають окремою командою. У Windows:

```powershell
studiofs umount Z:
```

На macOS передайте **фактичний шлях із назвою тому**:

```bash
studiofs umount /Volumes/Studiofs/myvolume
```

На Linux:

```bash
studiofs umount /mnt/StudioFS/myvolume
```

Дочекайтеся завершення команди. Докладніше про відключення поговоримо в окремій главі. Примусово завершувати процес, щоб відключити диск, — погана звичка.

У наступній главі збережемо на новий том перші файли й простежимо їхній шлях від локального збереження до хмари.
