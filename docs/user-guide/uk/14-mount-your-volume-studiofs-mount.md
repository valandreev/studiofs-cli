# 14. Підключаємо том — studiofs mount
> **Work in progress**

Том уже створено, але монтажна програма ще не знає, де шукати матеріали. Підключимо його до файлової системи комп’ютера: у Windows він з’явиться як диск із літерою, а в macOS чи Linux — як папка. Саме це робить команда `studiofs mount`.

## Windows: обираємо вільну літеру

Відкрийте PowerShell і виконайте:

```powershell
studiofs mount myvolume Z:
```

`myvolume` — ім’я тому, а `Z:` — місце, де його побачать програми. Виберіть літеру, яку ще не використовує інший диск або мережеве підключення. Якщо `Z:` зайнято, можна взяти, наприклад, `S:`.

**У Windows літеру потрібно передавати явно.** Для цієї команди шлях на кшталт `C:\Projects` не замінює літеру диска. Ім’я тому не додається до `Z:`: коренем підключеного простору буде `Z:\`.

Відкрийте Провідник і перейдіть до `Z:\`. Новий том може бути порожнім — це нормально. Він не повинен одразу містити відео про котів, хоча іноді дуже хочеться почати саме з нього.

## macOS і Linux: обираємо папку

На macOS використайте каталог `/Volumes/Studiofs`, підготовлений у попередній главі:

```bash
studiofs mount myvolume /Volumes/Studiofs
```

StudioFS додає ім’я тому до переданого шляху, якщо його остання частина ще не збігається з цим ім’ям. Фактична точка буде **`/Volumes/Studiofs/myvolume`**. У Linux використайте папку у своєму домашньому каталозі:

```bash
studiofs mount myvolume /mnt/StudioFS
```

Обидві команди створюють точку монтування з назвою тому. Виконайте команду для своєї системи.

StudioFS намагається створити потрібні каталоги самостійно. Оберіть окрему папку для підключення, без ваших робочих файлів. На macOS перевірте, що маєте права запису в `/Volumes/Studiofs`; інструкцію з підготовки прав наведено в главі 11. У Linux використовуйте папку, до якої ваш користувач має доступ.

На macOS відкрийте Finder, натисніть **⌘⇧G** і введіть `/Volumes/Studiofs/myvolume`. На Linux відкрийте `/mnt/StudioFS/myvolume` у файловому менеджері. Системні засоби різні: macOS використовує macFUSE, Linux — libfuse3.

## Чому термінал не повернув запрошення?

Бо він зараз тримає підключення. За замовчуванням `mount` працює **у передньому плані**: процес залишається активним, а вікно термінала зайняте. Поки він працює, відкрийте інше вікно термінала або файловий менеджер для перевірки диска.

Той самий режим можна вказати явно:

```powershell
studiofs mount myvolume Z: --foreground
```

На macOS чи Linux замість `Z:` передайте свій шлях. Для першого запуску цей режим зручний: повідомлення про проблеми видно відразу. Не закривайте вікно, сподіваючись, що диск залишиться підключеним.

Для щоденної роботи є **фоновий режим**:

```powershell
studiofs mount myvolume Z: -d
```

На macOS:

```bash
studiofs mount myvolume /Volumes/Studiofs -d
```

На Linux:

```bash
studiofs mount myvolume /mnt/StudioFS -d
```

`-d` — скорочення для `--detach`. StudioFS запускає окремий процес, і терміналом знову можна користуватися. `--foreground` і `--detach` разом передавати не можна.

Команда повертає керування, коли том уже приймає запис, зазвичай за секунду-дві. Якщо синхронізація із сервером триває довше за 10 секунд, команда однаково завершується й повідомляє, що доступ на запис ще очікується. До того файли можна читати, але створення чи зміна файлів завершується помилкою «Permission denied».

Фоновий режим не встановлює системну службу й не налаштовує автоматичне підключення після перезавантаження. Журнали фонового процесу зберігаються в каталозі `logs` кореня клієнта, за замовчуванням — `~/.studiofs/logs/`.

## Перевіряємо, що бачимо саме том

Після запуску відкрийте диск або папку й перегляньте їхній вміст. У другому терміналі можна виконати:

```powershell
Get-ChildItem Z:\
```

На macOS:

```bash
ls -la /Volumes/Studiofs/myvolume
```

На Linux:

```bash
ls -la /mnt/StudioFS/myvolume
```

Для перевірки запису створіть через Провідник чи файловий менеджер папку `mount-check`, переконайтеся, що вона з’явилася, і видаліть її. Порожній том після цього знову буде порожнім. Якщо ви свідомо підключили його з `--read-only`, створення папки має бути заборонене — це очікувана поведінка.

На macOS і Linux **сама наявність каталогу ще не доводить, що том підключено**: каталог може залишитися після відключення. Переконайтеся, що запуск завершився без помилки й процес підключення продовжує працювати. Якщо термінал повідомив про невдалий запуск, не починайте копіювати матеріали в цю папку: вони можуть потрапити у звичайний локальний каталог.

## Зберегти файл і передати його команді — різні події

Коли програма зберігає файл на підключений том, StudioFS спочатку приймає зміни локально. На цьому ж підключенні вони доступні одразу. Вміст передається в S3, а спільні метадані публікуються у фоні; інші комп’ютери побачать результат після синхронізації.

Тому закритий файл, успішне збереження або поява папки `mount-check` **не підтверджують завершення публікації для колег**. Не вимикайте комп’ютер одразу після великого експорту лише тому, що монтажна програма вже закрила вікно прогресу.

За наявності графічного середовища StudioFS автоматично намагається показати індикатор у системному треї або рядку меню. У поточній реалізації це передбачено для Windows, macOS і Linux; фактична видимість залежить від графічного середовища. Окремий параметр `--tray` для `mount` не потрібен. Якщо графічний індикатор недоступний, підключення може працювати через командний рядок.

Червона пульсація означає, що локальні зміни ще потребують синхронізації. Анімований синьо-жовтий прапор з’являється після підтвердження завершення передавання прийнятих змін і метаданих. Відсутність індикатора або застарілий стан нічого такого не підтверджують. Навіть після підтвердження програма може знову щось записати.

`--detach` сам по собі не гарантує появи індикатора. Його наявність не є умовою роботи фонового підключення.

## Як завершити першу спробу

Закрийте програми, які працюють із томом. Для підключення у передньому плані натисніть **Ctrl+C** у його терміналі й дочекайтеся завершення процесу.

Фонове підключення відключають окремою командою. У Windows:

```powershell
studiofs umount Z:
```

На macOS передайте **фактичний шлях із назвою тому**:

```bash
studiofs umount /Volumes/Studiofs/myvolume
```

На Linux:

```bash
studiofs umount /mnt/StudioFS/myvolume
```

Дочекайтеся завершення команди. Детальніше про відключення та завершення роботи поговоримо в окремій главі; примусове завершення процесу не варто робити звичним способом прибрати диск.

У наступній главі покладемо на новий том перші файли й перевіримо, як вони проходять шлях від локального збереження до хмари.
