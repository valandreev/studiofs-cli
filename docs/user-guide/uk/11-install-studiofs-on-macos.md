# 11. Встановлюємо StudioFS на macOS

> **Український оригінал для редакційного й технічного погодження.** Ще не затверджено.

На Mac StudioFS теж починається з термінала. Після підключення ви працюватимете з папкою у Finder, монтажній програмі чи композері, але спочатку потрібно встановити дві окремі речі: **macFUSE**, який допомагає macOS підключити файлову систему, і сам **StudioFS**.

У цій главі підготуємо комп’ютер і перевіримо запуск програми. Створення тому та повне налаштування підключення залишимо для [глави 13](13-create-your-first-volume-studiofs-init.md) і [глави 14](14-mount-your-volume-studiofs-mount.md). Встановлена програма ще не означає, що S3 і PostgreSQL уже налаштовані. Вони, на жаль, самі себе не адмініструють.

## Спочатку macFUSE

Основний шлях StudioFS на macOS зараз — **звичайний macFUSE, або legacy backend**. Саме його використовуємо далі. FSKit — окрема експериментальна реалізація; про неї поговоримо наприкінці.

Завантажте інсталятор з [офіційного сайту macFUSE](https://macfuse.github.io/) і пройдіть його кроки. Якщо вже користуєтеся Homebrew, можна встановити той самий компонент командою:

```bash
brew install --cask macfuse
```

Це встановлює macFUSE, **не StudioFS**. Збережіть відкриті проєкти перед перезапуском, якщо його попросить інсталятор.

### Дозволи macOS

Встановлення пакета й дозвіл на роботу його системного компонента — різні кроки. macOS може попросити підтвердити завантаження розширення в **System Settings → Privacy & Security** («Системні параметри → Приватність і безпека»), а потім перезапустити Mac. Назви й розташування пунктів залежать від версії macOS; орієнтуйтеся на повідомлення інсталятора та [інструкцію macFUSE](https://github.com/macfuse/macfuse/wiki/Getting-Started).

На Mac з Apple silicon для звичайного macFUSE може знадобитися дозвіл на сторонні розширення ядра через середовище відновлення: **Startup Security Utility → Reduced Security → Allow user management of kernel extensions from identified developers**. Це зміна політики безпеки комп’ютера. Дотримуйтеся актуальної інструкції macFUSE саме для вашої системи, а на студійному Mac узгодьте її із системним адміністратором. Якщо корпоративна політика забороняє цей крок, не намагайтеся обійти її командами з випадкового форуму.

Звичайне встановлення StudioFS не потребує вимкнення SIP. Також не надавайте всім програмам Full Disk Access «про всяк випадок». Якщо macOS окремо запитує доступ термінала до захищеної папки, дозвольте лише потрібний доступ або оберіть для першого тесту папку у своєму домашньому каталозі.

## Звідки взяти StudioFS?

У поточному репозиторії описано складання з вихідного коду. Нижче — саме цей шлях: без вигаданого інсталятора StudioFS чи команди Homebrew, якої тут немає. Якщо адміністратор студії вже надав вам перевірений виконуваний файл для вашого Mac, використовуйте його шлях і перейдіть до перевірки запуску.

Для складання потрібні Git, інструменти командного рядка Xcode та Rust із Cargo. Інструменти Apple встановлюються так:

```bash
xcode-select --install
```

Якщо система відповідає, що вони вже встановлені, повторювати встановлення не потрібно. Rust можна отримати за [офіційною інструкцією](https://www.rust-lang.org/tools/install). Поточний `Cargo.toml` StudioFS вимагає Rust **1.95 або новішої версії**. Перевірте інструменти:

```bash
rustc --version
cargo --version
```

Складайте програму на тому Mac, де плануєте її запускати: так не доведеться вгадувати між Apple silicon та Intel. У терміналі перейдіть у робочий каталог і виконайте:

```bash
git clone https://github.com/valandreev/studiofs-cli.git
cd studiofs-cli
cargo build --release -p studiofs
```

Для команди студії варто заздалегідь погодити одну версію коду: поточна гілка репозиторію змінюється, а сумісність між довільними збірками не гарантована.

**Результат цієї команди — `target/release/studiofs` усередині репозиторію.** Це консольна програма, а не застосунок у папці Applications. Для початку запускайте її безпосередньо:

```bash
./target/release/studiofs --version
./target/release/studiofs --help
```

Якщо ви задали власний `CARGO_TARGET_DIR`, шукайте результат у його підкаталозі `release`.

Складання потребує справжніх заголовків macFUSE, зокрема `fuse_lowlevel.h`. Збірка шукає їх через `pkg-config fuse`, а також у стандартних каталогах Homebrew. Якщо бачите помилку про відсутній заголовок, перевірте встановлення macFUSE; сам Rust його не містить. Для діагностики через `pkg-config` потрібен цей інструмент, наприклад `brew install pkg-config`, якщо ви користуєтеся Homebrew. Відсутність `MFMount.framework` — інша ситуація: вона вимикає експериментальний FSKit, але не замінює й не скасовує вимог звичайної збірки macFUSE.

## Щоб не набирати довгий шлях

Можна залишити програму в каталозі збірки й завжди вказувати повний шлях. Або скопіюйте її у власний каталог команд:

```bash
mkdir -p "$HOME/.local/bin"
cp ./target/release/studiofs "$HOME/.local/bin/studiofs"
export PATH="$HOME/.local/bin:$PATH"
studiofs --help
```

`export` діє для поточного термінала. Для постійного налаштування додайте цей рядок до `~/.zshrc`, якщо використовуєте стандартний інтерактивний zsh, і відкрийте нове вікно термінала. Перевірте, яку копію програми знайшла система:

```bash
command -v studiofs
studiofs --version
```

Після нового складання копію в `~/.local/bin` потрібно оновлювати окремо. Інакше дуже легко цілий вечір перевіряти нову версію старим виконуваним файлом.

## Готуємо місце для підключення

Точка монтування — це локальна папка, через яку ви бачитимете файли тому. Для першого підключення звичайним macFUSE зручно використати порожню папку у своєму домашньому каталозі:

```bash
mkdir -p "$HOME/StudioFS/myvolume"
ls -A "$HOME/StudioFS/myvolume"
```

Друга команда не повинна показувати файлів. Якщо щось є, оберіть іншу порожню папку. Не підключайте том поверх каталогу з матеріалами поточного проєкту: після монтування його звичайний вміст буде прихований до відключення.

У прикладі том називається `myvolume`, і кінцева папка має ту саму назву. Це навмисно: якщо вказаний шлях не закінчується назвою тому, StudioFS додає її автоматично. Кеш зберігайте окремо на локальному SSD, не всередині підключеного тому.

## Перший запуск: що вже можна перевірити

Якщо `studiofs --help` працює, виконуваний файл запускається. Це ще **не перевірка монтування чи дозволів macFUSE**.

Після створення тому через `init` або підключення наявного тому через `discover` команда виглядатиме так:

```bash
studiofs mount myvolume "$HOME/StudioFS/myvolume" --foreground
```

Цей приклад розрахований на вже підготовлений локальний клієнт тому `myvolume`. Без нього спочатку пройдіть главу 13 або [главу 16 про другий комп’ютер](16-connect-a-second-computer-studiofs-discover.md). Не створюйте новий том замість того, до якого вас запросила команда.

Залиште термінал із монтуванням відкритим. В іншому вікні можна відкрити папку у Finder:

```bash
open "$HOME/StudioFS/myvolume"
```

Першу перевірку читання й запису робіть на тестових матеріалах за главами 14–15. Перед відключенням закрийте файли й програми, які використовують том, а потім виконайте:

```bash
studiofs umount "$HOME/StudioFS/myvolume"
```

Якщо macFUSE відхиляє монтування, поверніться до системних дозволів і перезапуску. Якщо StudioFS повідомляє про відсутній том, доступ до PostgreSQL чи S3, перевіряйте відповідні налаштування: перевстановлення драйвера не виправить пароль до бази.

## А що з FSKit?

FSKit у StudioFS залишається **експериментальним і вмикається окремо**. Це не автоматична заміна основного macFUSE й не обіцянка однакової готовності для робочого проєкту. Реалізація використовує macFUSE `MFMount.framework`; вона потребує macOS **15.4+**, macFUSE **5.3.3+**, доступного framework і точки монтування під `/Volumes`. Якщо framework не був доступний під час складання, вибір FSKit завершиться помилкою непідтримуваного backend.

Для звичайного встановлення залиште `STUDIOFS_MOUNT_BACKEND` незаданою. Якщо раніше експериментували в цьому терміналі, поверніться до стандартного шляху командою:

```bash
unset STUDIOFS_MOUNT_BACKEND
```

Експеримент із FSKit краще проводити окремо, на тестовому томі, за [технічною документацією](../../platform-bridges.md#macos-backend-selection). Для першого підключення за цим посібником він не потрібен.

## Що далі?

Mac підготовлено, коли StudioFS запускається, macFUSE встановлено з потрібними системними дозволами, а для тому обрано порожню папку. Саме підключення перевіримо після налаштування тому. Якщо Linux вам не потрібен, можна одразу перейти до [створення першого тому](13-create-your-first-volume-studiofs-init.md).
