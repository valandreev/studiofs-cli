# 10. Встановлюємо StudioFS на Windows

На монтажній станції StudioFS складається з двох частин: програми `studiofs.exe` і WinFSP — компонента Windows, який дає їй змогу показати том як диск. Спочатку встановимо обидві частини й перевіримо запуск. Підключати S3 та створювати том будемо далі: порожній диск не з’явиться лише від того, що ми завантажили програму.

Нижче працюємо у **PowerShell на самій Windows**, не всередині WSL. Приклади орієнтовані на Windows x64. Наявність у коді підтримки інших архітектур сама собою не підтверджує готовність конкретної збірки для вашого комп’ютера.

## Спочатку WinFSP

Завантажте й установіть **WinFSP 2026 або новішу версію** зі [сторінки випусків офіційного репозиторію WinFSP](https://github.com/winfsp/winfsp/releases). StudioFS використовує кілька новіших можливостей WinFSP, тому попередні версії не підтримуються. Windows може попросити права адміністратора, оскільки встановлюється драйвер файлової системи. Якщо інсталятор просить перезавантаження, виконайте його перед перевіркою StudioFS. На робочій станції з обмеженими правами цей крок краще доручити адміністратору.

## Завантажуємо StudioFS

Відкрийте [сторінку випусків StudioFS](https://github.com/valandreev/studiofs-cli/releases) і завантажте збірку для **Windows x64**. Якщо файл упаковано в архів, розпакуйте його в окрему папку. Скопіюйте всі файли релізу до папки StudioFS у своєму профілі:

```powershell
$studiofsBin = Join-Path $env:LOCALAPPDATA 'Programs\StudioFS'
New-Item -ItemType Directory -Force -Path $studiofsBin | Out-Null
Copy-Item 'C:\path\to\extracted\release\*' -Destination $studiofsBin -Recurse
& (Join-Path $studiofsBin 'studiofs.exe') --version
& (Join-Path $studiofsBin 'studiofs.exe') --help
```

У команді `Copy-Item` замініть `C:\path\to\extracted\release` на шлях до розпакованої папки релізу. Якщо реліз містить окремі вказівки, дотримуйтеся їх.

## Щоб не набирати повний шлях щоразу

У параметрах Windows знайдіть **«Змінення змінних середовища для облікового запису»**, відкрийте користувацьку змінну **Path** і додайте папку, отриману командою `$studiofsBin`. Додавайте саме папку, без `studiofs.exe`, зберігаючи попередні записи. Зміна користувацького Path не потребує встановлення програми для всіх користувачів.

Закрийте PowerShell і відкрийте нове вікно. Якщо працюєте у Windows Terminal і нова вкладка зберігає старе оточення, перезапустіть увесь Terminal. Тепер перевірте:

```powershell
Get-Command studiofs
studiofs --version
studiofs --help
```

`Get-Command` показує, який саме файл буде запущено. Це допомагає, коли на станції залишилася стара копія. PowerShell також вимагає `.\` перед назвою програми з поточної папки: використовуйте `.\studiofs.exe --help` або повний шлях. Для шляху в лапках потрібен оператор `&`, як у прикладі вище.

## Права й перший запуск

Після встановлення драйвера починайте роботу зі звичайного PowerShell під тим обліковим записом, у якому працює монтажна програма. Не перемикайтеся автоматично на «Запуск від імені адміністратора» при кожній помилці: підвищений сеанс і звичайний сеанс можуть по-різному бачити підключені диски.

Обліковому запису потрібен запис до локальних папок стану й кешу StudioFS. Кешу також потрібне вільне місце на локальному диску. Захищена системна папка або мережевий ресурс — невдалий вибір для першої перевірки. Доступ до S3 і PostgreSQL визначається окремими обліковими даними: права адміністратора Windows їх не замінюють.

Якщо запуск повідомляє про відсутню DLL WinFSP, перевірте його встановлення, стандартний шлях і відповідність архітектури. Якщо Windows блокує завантажений файл, перевірте джерело та зверніться до адміністратора згідно з правилами студії. Для запуску `studiofs.exe` не потрібно змінювати PowerShell Execution Policy — це налаштування сценаріїв, а не спосіб встановити драйвер.

**Довідка відкривається — клієнт готовий до налаштування.**
