# 17. Безпечне відключення — studiofs umount
> **Сторінка в процесі доповнення**

Роботу завершено, проєкт збережено, ноутбук уже проситься в рюкзак. Залишився один крок: дати StudioFS завершити передавання змін і відключити том.

## Збережено тут — ще не означає доступно всюди

StudioFS приймає зміни локально, а вміст файлів передає до S3 у фоновому режимі. Спільні метадані теж публікуються асинхронно через PostgreSQL. Тому файл уже може відкриватися на вашому комп’ютері, тоді як на іншому комп’ютері ще немає його останньої версії.

Навіть закриття файлу чи запит програми на `fsync` самі по собі не підтверджують, що зміни опубліковано. І завершене завантаження в S3 — ще не все: StudioFS також має опублікувати версію файлу й отримати підтвердження збереження метаданих.

Найкраще перевіряти це, **поки том ще підключено**. Після відключення значок уже не допоможе дочекатися завершення передавання.

## Спочатку закрийте робочі програми

Збережіть проєкт і дочекайтеся завершення експорту, копіювання та інших операцій запису. Потім закрийте редактор, програвачі й інші програми, які працюють із томом. Автозбереження теж уміє записувати файли — навіть коли ви подумки вже пішли додому.

Закрийте вікна файлового менеджера з цим диском. Якщо в терміналі відкрито папку на томі, перейдіть до домашньої папки чи іншого локального каталогу. Так том не буде зайнятий відкритим файлом чи поточною папкою.

## Дочекайтеся підтвердження синхронізації

Якщо є графічне середовище, StudioFS автоматично намагається показати значок у системному треї чи рядку меню на Windows, macOS і Linux. Чи буде його видно, залежить від середовища; том може працювати й без значка. Якщо значок є, перевірте його стан:

- **Червона пульсація** означає, що локальні зміни ще чекають на синхронізацію. Не вимикайте комп’ютер; за потреби відновіть доступ до S3, PostgreSQL і приватної мережі.
- **Анімований синьо-жовтий прапор** з’являється, коли StudioFS підтвердив, що всі зміни даних і метаданих, прийняті на цьому комп’ютері, успішно передано. Підказка до значка може показувати `safe to shut down`.

Перевіряйте значок уже після закриття програм: якщо після перевірки щось записалося, синхронізації знову є над чим працювати. Потім відключіть том звичайною командою, наведеною нижче.

Якщо значка немає, можна стежити за роботою підключеного тому з командного рядка. Наприклад, у Windows:

```powershell
studiofs perf Z: --section upload --section metadata --count 5
```

На macOS:

```bash
studiofs perf /Volumes/Studiofs/myvolume --section upload --section metadata --count 5
```

На Linux:

```bash
studiofs perf /mnt/StudioFS/myvolume --section upload --section metadata --count 5
```

Ця **команда лише показує стан, а не запускає синхронізацію**.

## Відключаємо том

Команді потрібна **точка монтування**, а не назва тому. Для диска `Z:` у Windows:

```powershell
studiofs umount Z:
```

Для папки на macOS:

```bash
studiofs umount /Volumes/Studiofs/myvolume
```

Для папки на Linux:

```bash
studiofs umount /mnt/StudioFS/myvolume
```

Замініть шлях на той, який використали під час підключення. Якщо шлях містить пробіли, візьміть його в лапки. Зверніть увагу на написання: `umount`, без літери `n` після `u`.

Дочекайтеся завершення команди. Після успішного відключення том більше не доступний через цей диск чи папку. Але сам том, його файли в S3 і локальний кеш при цьому не видаляються.

## Якщо щось пішло не так

Якщо команда повідомляє, що том зайнятий, ще раз перевірте відкриті програми, вікна й термінали. Якщо бракує прав, згадайте, чи не запускали ви монтування з підвищеними правами: тоді й для відключення може знадобитися термінал із такими самими правами.

Не завершуйте процес StudioFS примусово лише заради швидшого відключення. Сама команда чекає обмежений час і в деяких ситуаціях теж може примусово завершити процес. Якщо ви побачили відповідне попередження чи помилку, не вважайте синхронізацію завершеною та збережіть повідомлення для діагностики.

Якщо інтернет зник, а вам потрібно завершити роботу, відключення не передасть локальних змін у недоступну хмару. **Не видаляйте локального кешу й налаштувань клієнта.** Коли зв’язок відновиться, підключіть том на тому самому комп’ютері з тим самим кешем і дочекайтеся завершення синхронізації.

## Підключаємося знову

Після звичайного відключення не потрібно ні створювати том повторно, ні ще раз виконувати `discover`. Скористайтеся знайомою командою `mount` з назвою тому й потрібною точкою монтування. Наприклад, у Windows:

```powershell
studiofs mount myvolume Z:
```

На macOS:

```bash
studiofs mount myvolume /Volumes/Studiofs
```

На Linux:

```bash
studiofs mount myvolume /mnt/StudioFS
```

Підставте свою назву тому та шлях із [глави про підключення](14-mount-your-volume-studiofs-mount.md). Після запуску дайте StudioFS завершити незавершену роботу, якщо така залишилася. Далі можна знову відкривати проєкт — або спершу переконатися, що вчорашні зміни вже доступні колезі.
