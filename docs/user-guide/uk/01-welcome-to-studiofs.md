# StudioFS за 20 секунд

**StudioFS — open-source, self-hosted альтернатива LucidLink для спільної роботи над медіапроєктами. Один офіс чи різні континенти — неважливо.** На Windows, macOS і Linux зі спільними файлами можна працювати як зі звичайного диска. Не потрібно попередньо завантажувати терабайти матеріалів: StudioFS читає потрібні частини файлів із S3, кешує їх локально й синхронізує зміни між комп’ютерами у фоновому режимі.

*“We'll build our own LucidLink — with blackjack and hookers!”*

# 01. Ласкаво просимо до StudioFS!
> **Work in progress**

Уявіть: ваша команда працює над одним фільмом, але всі в різних місцях. Монтажер удома, колорист у студії, VFX-художник — п’яний на пляжі Балі. А матеріалів — кілька терабайтів: оригінали, проксі, EXR-ки, 3D-сцени, рендери.

Зазвичай доводиться качати файли, копіювати папки, пересилати нові версії й з’ясовувати, у кого актуальний проєкт. Особливо весело, коли хтось уже працює зі старою копією.

**Ідея StudioFS — дати всій команді один спільний файловий простір**, незалежно від того, де хто сидить.

## Як це працює для вас?

Підключаєте StudioFS — і бачите звичайний диск у Windows або папку на macOS чи Linux. Відкриваєте матеріали в DaVinci Resolve, Flame чи іншій програмі. Усе як ви звикли.

Великі файли не обов’язково завантажувати цілком. StudioFS підтягує потрібні частини зі сховища й тримає їх у локальному кеші. Зміни спочатку зберігаються на вашому комп’ютері, потім передаються в хмару й стають доступними колегам після синхронізації.

Тобто **спільний диск — так, миттєва синхронізація — ні**. І якщо двоє одночасно змінять один файл, StudioFS не зможе автоматично об’єднати їхні правки. Добра новина в тому, що грамотно побудований медіапайплайн допомагає уникати таких ситуацій.

## Чому не просто LucidLink?

Саме LucidLink і надихнув на цю ідею: віддалені файли як локальний диск, зручний для медіавиробництва. Але хотілося отримати **відкриту систему, яку можна повністю розгорнути на власній інфраструктурі**.

Тому StudioFS використовує S3-сумісне сховище для вмісту файлів, PostgreSQL для спільних метаданих і локальний SSD для кешу. Сховище й сервер обираєте та контролюєте ви.

Це ще не повна заміна LucidLink за можливостями й зрілістю. StudioFS активно розробляється, тому важливі проєкти поки краще не довіряти йому без незалежних резервних копій. Але на момент відкриття репозиторію для всіх ми вже встигли зробити на StudioFS пару реальних проєктів. Тобто воно працює.

## Що далі?

У наступній главі коротко розберемо, як S3, PostgreSQL і кеш перетворюються на один диск. Далі — налаштуємо все на практиці.
